# OpenDesk：实现 Flow 分发、安装、信任、授权与运行闭环

## 目标需求

让普通用户拿到一个自动化文件后，不需要操作 OpenDesk 内部目录或任何密钥，即可安装并运行 Flow。

最终用户链路必须成立：

```text
开发者完成自动化
→ 交付单个 .js / .odpkg / .odflow
→ 用户双击 .odflow，或拖入 OpenDesk / Script Runner
→ OpenDesk 校验内容与签名
→ 按需要确认发布者、登录或激活
→ 自动安装并注册
→ Script Runner 显示正确的 Flow 名称与可运行状态
→ 用户明确点击运行
→ Flow 正确读取自身资源并完成业务
```

同时，一个 OpenDesk 必须可以同时使用多个发布者、多个受保护包；用户不需要选择 Key。同一产品可以一次激活后自动取得多个 Flow 所需的独立包授权。安装不自动执行业务，非法包或授权失败时 JavaScript 零执行，受保护源码不因快照、日志、预览或临时文件落盘。

## 完成标准

- `.js` 免项目导入、已具备可信材料的 `.odpkg` 导入、已签名 `.odflow` 安装均真实可用；不需要用户手动复制目录、公钥或 Content Key，安装后重启仍可发现。
- 正式安装统一为 `flows/<installId>/`，没有版本目录；包内容、业务数据与宿主状态分离；安装不会覆盖官方 UI 或其他 Flow。
- 未知发布者可以取消或明确批准；单 Flow 批准不扩散成全发布者信任；官方/市场证明、同名冒充、密钥用途、轮换与已知撤销处理有测试，不把测试根作为生产官方根。
- 多发布者、多受保护包不串密钥或授权；一次产品激活后各包独立取得授权；未包含的包、错误设备、过期、撤销与重放仍被拒绝，凭据不发往任意包声明网址。
- 带资源 Flow 在不同 cwd、安装位置以及接入的 Runner/CLI/AI/Scheduler 入口下得到一致资源结果；旧 Execution 路径语义不被伪造，旧入口不被删除或降级明文执行。
- 验签、内容校验或授权失败时业务零执行；成功、失败、异常、语法错误、取消等路径不自动写出解密源码、私钥或 Content Key。
- Zip Slip、链接/别名逃逸、重复条目、超限、Manifest 不一致、并发安装、崩溃恢复、运行中更新/卸载和版本冲突均有可重复的断言；失败不留下 ready 的半安装状态。
- Runner 的选择、上一个/下一个、名称、列表、刷新、运行与停止不回归；旧 recipes、资源、顺序和既有调用关系不因改根丢失。
- 已生成真实测试文件、注册到对应测试入口并实际执行；逐项报告 FLOW-01～FLOW-25 的 PASS / FAIL / BLOCKED / NOT_RUN / SKIP、命令与证据。源码/构建/Runtime/native-live 分层说明，不把跨编译或 mock 成功写成真机通过。

最终交付应包含：实际修改的功能与测试文件、已通过与未通过的行为、可从仓库根目录复制的一行测试/体验命令、当前平台关键证据，以及剩余阻塞与对应 owner。把真实验收结果记录到 `docs/quality/flow-distribution-qualification.md`；没有证据的项目不能写已完成。
