# UI 定位失败诊断与修复｜生成、预检、验证、固化

## 0. 定位与当前事实

本方法用于 AI / 开发者生成或修改桌面自动化代码时，解决“API 调用合法，但真实目标定位失败或动作结果未被证明”的问题。它补充[自动化任务求解方法](automation-problem-solving-framework.md)的分层观察、结果验证和有界恢复，不增加一套 Workflow、Runtime、公共 API 或强制 Skill。

2026-09-14 核对基线：`master` 的 `ba33655cd059521e9beadd551143124f9a02f298`。以下区分仓库合同、用户提供的故障描述和待执行验证；接续时仍须重新读取当前源码、API 文档、实际构建物与执行入口。

- 用户报告：`await UI.tapTexts(['2', '5', '×', '4', '=']);` 返回 `TIMEOUT / UI.tapTexts`，OCR 将 `×` 读为 `†`，并漏掉 `4`、`=`。本轮未连接目标 Mac，未取得这次失败的原截图、完整错误或实际显示值，不能把该归因写成重新复现的事实。
- 当前 [Desktop UI API](../api/desktop-ui.md) 已公开 `UI.findTextMatches()`：一次截图和 OCR 批量计算字符串／正则查询，只读。`UI.tapTexts()` 仍接收字符串动作序列，逐步重新观察，默认绑定首次活动窗口；不是一次观察的批量点击，也不是别名接口。
- 当前 [Accessibility API](../api/accessibility.md) 为 Experimental。可信本地 `-script`、`-script-text`、stdin、`opendesk ai run` 可启用；HTTP、MCP、Scheduler 当前关闭。必须核对当前 execution 的实际能力，不得为兜底绕过入口限制。
- 实际读取的[计算器黄金样本](../../workflows/human-to-recipe/golden-samples/calculator.js)使用录制来源的窗口相对点、固定布局校验、PID 范围点击及 Accessibility 结果读取。其业务最终期望是 `115`，不是本次单式的 `100`；源码存在不等于当前环境实测通过，也不等于按钮全部通过原生 invoke 定位。

## 1. 核心决定

**允许在开发／维修阶段，根据真实证据建立应用内 OCR 别名；不允许把错读字符全局改义，也不要求所有定位失败都切换 Accessibility。**

业务始终表达“点击乘号”；`†` 只是某个应用、布局、区域和 OCR 配置下的候选观察值。原始 OCR 不修改。注释说明原因，运行前置和测试负责约束，二者不能互相替代。

生成代码的最小闭环：

```text
固定任务与当前 API／执行环境
→ 生成或复用候选代码
→ 无输入预检所需目标和结果读取方式
→ 获准后执行最小真实任务
→ 独立读取并核验业务结果
→ 不通过：保留现场、分类、修复最小定位规则
→ 从已确认的安全状态重新验证新候选
→ 保存规则、限制和证据，交给原工作流的资格／发布环节
```

静态检查、模拟测试、预检、真实动作、业务成功和独立资格分别记录。没有桌面连接或权限时继续可完成的离线工作，但把真机项保留为未运行／阻塞，不声称“已点击”“已读取 100”。

## 2. 先分类，不把所有错误都当等待问题

| 故障类型 | 应取得的证据 | 最小修复方向 |
| --- | --- | --- |
| 错窗口、错区域、遮挡或旧布局 | 当前应用／进程／窗口身份、活动状态、原图、region 和布局 | 先修 scope、准备状态或重新认识；不要扩大到全桌面 |
| 错读：乘号区域确有候选但原文是 `†` | 原图与同帧 OCR bbox、原文、provider；目标语义复核 | 应用内显式别名、区域约束，或更合适的原生／图像定位 |
| 漏检：`4`、`=` 没有 bbox | 保留完整观察中的缺失，不只记录查询超时 | 局部补采／OCR 配置实验、模板、经核验布局规则、原生控件或人工补证 |
| 歧义：同一目标命中多项 | 全部候选及所属区域，例如显示区与按钮区都有 `5` | 约束到 keypad／目标容器；仍歧义就停止，不取第一个或最高分 |
| 尚未出现、动画或切换未完成 | 前后观察能证明状态确在变化 | 有界等待适用；固定 sleep 不证明就绪 |
| 观察或坐标过期 | 窗口／布局／DPI／滚动／遮挡与观察来源变化 | 失效旧位置，按当前上下文重新观察；不能只增加 timeout |
| 动作已提交但返回异常或业务未证实 | `failedPhase`、完成前缀、原始 cause、可用的 actionState、当前结果 | 停止输入，先只读核对；不切换 backend 后重复点击 |

`TIMEOUT` 本身不能证明 OCR 错读。反过来，若同一稳定画面反复漏检或错读，没有新信息的重试也不能可靠修复。`match: 'contains'` 不会让 `†` 自动等于 `×`，别名不会凭空产生缺失的 bbox。

## 3. 应用内 OCR 别名：可用，但必须有边界

- 建立规则。
  - 保留语义 token `×`，将经证实的 OCR 观察值记录为 `['×', '†']`；不要把业务步骤改写成“点击匕首号”。
  - 限定应用身份、Basic 布局／版本范围、keypad／按钮区域、实际 OCR provider／配置与证据来源；无法核对的字段保留未知，不能伪造版本或人审记录。
  - 原图与候选位置必须支持“这是乘法按钮”。“计算器通常没有 †”只是假设，不能单独证明目标身份。
  - 原文、bbox、provider、语义归属和采用原因分别留存；不改写截图或全局 OCR 输出。
- 运行约束。
  - exact 和已批准 aliases 的候选合并后必须唯一；原文 `×` 与 `†` 同时命中两个位置时停止，不静默优先其中一个。
  - 别名只适用于该规则，不用于别的应用、其他区域、显示结果解析或任意业务文字。
  - 没有候选、出现矛盾、布局／provider 超出已验证范围时使规则失效。AI 不在无人值守运行中临时发明新别名。
- 保存方式。
  - 一次实验：工作包记录假设和未测项，不能发布为稳定规则。
  - 已验证局部修复：放入既有 AppProfile／定位规则或普通 JS 的具名常量与注释，关联实际证据和失效条件。
  - 出现跨应用重复需求后再评估公共能力；本轮不新增 `UI.tapTargets()`，不向 `UI.tapTexts()` 塞入未发布的 `aliases`／`accessibility`／`fallback` 参数。

注释建议明确表达：`乘法按钮在已核验 Calculator Basic keypad 和指定 OCR 配置下可能被读为 †；只在此范围接受，仍须唯一候选与真实结果核验；规则依据见当前工作包。` 只有注释而没有 scope、拒绝条件和测试，不算修复完成。

## 4. 一次 OCR：区分批量预检与坐标复用

### 4.1 优先使用现有只读批量查询

[API 文档](../api/desktop-ui.md)和[类型](../../types/UI.d.ts)中的 `UI.findTextMatches()` 支持 `1..32` 个字符串／RegExp 查询，返回与输入一一对应的 `{ queryIndex, matches }`。正则不能带 `g`／`y`；混用正则时不要额外传字符串专用 `match` 等选项。调用不接受点击参数，不产生输入。

下面是开发诊断函数，不是可直接跑完整任务的 Recipe。`win` 必须是已唯一确认的当前 WindowInfo；`keypadRegion` 必须来自实际审阅过的 Geometry 区域／规则，不能猜一个比例。启用 `†` 查询表示检验别名假设，不表示已批准它用于点击。

```js
async function inspectCalculatorKeypad(win, keypadRegion) {
  if (typeof UI.findTextMatches !== 'function') {
    throw new Error('当前 Runtime 没有 UI.findTextMatches；先核对构建与 API');
  }
  if (!win || !keypadRegion) {
    throw new Error('需要已确认的窗口与按钮区域');
  }
  const tokens = ['2', '5', '×', '4', '='];
  const groups = await UI.findTextMatches(
    ['2', '5', /^(?:×|†)$/u, '4', '='],
    { within: win, region: keypadRegion },
  );
  if (groups.length !== tokens.length
      || groups.some((group, index) => group.queryIndex !== index)) {
    throw new Error('批量查询结果与输入不对应');
  }
  return groups.map((group, index) => ({
    token: tokens[index],
    status: group.matches.length === 1 ? 'unique'
      : group.matches.length === 0 ? 'missing' : 'ambiguous',
    candidates: group.matches.map(target => ({
      rawText: target.text,
      provider: target.provider,
      confidence: target.confidence,
      bounds: target.bounds,
    })),
  }));
}
```

`unique` 只说明 OCR 候选数，不证明语义、enabled、当前可点击或业务成功。诊断函数的 status 是普通 JS 数据，不是新增 Runtime 错误码或正式合同。

对于静态 keypad，在任何表达式输入前预检全部 distinct targets，并预检结果组件可读取，能够提前发现“输入 25 后才遇到缺失 ×／4／=”的已知缺口。对分步出现的动态页面，只预检当前可操作阶段，不能要求未来页面的目标现在就出现。

### 4.2 批量预检不等于一次 OCR 后永久复用点

- 一次预检后调用 `UI.tapTexts()`，后者仍按合同逐步重新 OCR；前次结果并未注入该接口。
- 一次 OCR 的候选位置只属于该次观察。可作为受控静态批次的候选，但动作前还须检查同一窗口身份、当前 bounds、布局、遮挡和状态；失效即停止并重新定位。
- 窗口移动且布局规则仍被独立证明适用时，可按当前窗口重算窗口相对规则；不能把旧 screen point 直接平移并宣称目标仍有效。窗口没移动也不能证明内容／遮挡没变。
- 多步复用仅用于已证明不重排的按钮区；显示区文本仍需新观察。发生 resize、模式切换、跨 DPI、窗口重建或未知变化时，不继续使用缓存。
- OCR 的文字 bbox 不是完整按钮边界。安全点击点需经按钮范围核验；裁剪／放大后的 image pixels 必须通过实际来源映射成 tagged screen logical 坐标。现有 Geometry 结果不能被当作裸比例或与原始 imageBounds 混用。
- 预检不是事务锁，不能保证检查与点击之间绝无竞态；因此仍需逐动作防护和独立后置验证。无法建立复用前提时，保持逐步观察更简单。

## 5. 可选定位方法：按证据和任务约束选择，不是失败后盲试链

| 方法 | 合适条件 | 必须保留的限制 |
| --- | --- | --- |
| 原生 Accessibility / UIA | 当前 execution 已启用，目标提供唯一语义及实际 action | 从真实 snapshot 取得 name／identifier；不能假定可见 `×` 就是原生 name；完整查找、状态检查、ref 释放；unknown 动作停止 |
| 区域 OCR + 局部别名 | 有可靠文字候选，只是稳定错读 | 原文保留、范围限定、候选唯一、provider／布局资格明确；不能补回漏检 |
| 局部模板匹配 | 图标／符号有可用、获准的真实素材 | 使用当前 `UI.findImage()`／`UI.tapImage()` 支持的选项；验证主题／scale、唯一性及误匹配，不假定一种模板覆盖所有版本 |
| 锚点、关系与已测量布局 | 有当前可验证锚点、明确按钮区／控件结构 | 复用 region、relativeTo、Geometry 或普通 JS 规则；不能凭常见计算器布局均分窗口、猜缺失按钮 |
| Recorder／测量辅助 | 自动识别不足，但人工能确认目标与操作 | 录制提供发生过什么，测量提供范围和几何；结合窗口、来源、坐标空间及动作／结果证据，形成有失效条件的相对规则，不固化无上下文绝对点 |
| 开发期视觉模型补证 | 文字检测失败，需要理解真实截图里的符号／控件关系 | 模型只提出候选；保留实际看图来源、bbox 和未知，经过规则校验、叠加审阅及真实测试再固化；不伪称原生属性，不默认每次运行调用模型 |

没有“一律 AX → OCR → 坐标”的全局优先序。对当前可用的原生 Calculator，先检查原生语义通常值得尝试；对自绘软件或受限入口，已验证的视觉／录制规则可能更适合。选择发生在开发和预检阶段；某次动作可能已发生后，禁止用另一方法再点一次。

快捷键、键盘输入或应用自动化接口也是其他任务可考虑的操作方式，但本案例明确验收按钮点击，不能静默替换成输入整式、JS 算术或返回预写答案。更改操作方式必须先改变任务合同。

### OCR 输入质量实验

先保存原图与原始观察，再对必要小区域比较裁剪、放大、对比度／二值化、分割模式和实际可用 provider。每个实验记录新信息、耗时、误检、漏检及配置，不能用更高置信度冒充语义正确。

Tesseract 官方 [ImproveQuality](https://tesseract-ocr.github.io/tessdoc/ImproveQuality.html) 讨论缩放、二值化、裁剪边界、分割模式和受限字符集。这是可实验方向，不是对当前 Calculator 的效果保证，也不代表这些底层参数已被 OpenDesk 暴露；实现只能使用当前 API 支持的参数，缺口另走现有 Runtime 扩展流程。

## 6. 接入现有开发工作流

- 生成／复用候选时。
  - 明确任务目标、输入序列、结果来源及允许副作用；先读当前 API，选当前 execution 实际支持的入口。
  - 先复用已有脚本、AppProfile、录制、测量和验证证据；不为了采用新方法重做完整示范。
  - 生成者必须自检 scope、全部必要目标、读取方法、数据流和失败停止；“代码能解析”不是完成标准。
- 预检／最小实测时。
  - 没有输入的定位预检先行；唯一候选、身份和允许状态都通过后，才进入获准真实动作。
  - 对 `25 × 4 =` 从已确认的干净状态开始，逐键完成后独立读取显示区实际值，再与期望 `100` 比较。清空本身也属于动作，须确认本次允许及实际 C／AC 语义。
  - 不把已有显示值或 expected 注入 actual；按钮动作成功、结果读取成功、结果正确分别记录。
- 失败／维修时。
  - 保存实际 `code / operation / failedIndex / failedText / failedPhase / completed / cause` 及可用原生 actionState；缺失字段写未知，不推导“肯定没点”。
  - 先按第 2 节分类，再提出能增加证据的最小修复；默认先做只读比较。固定本轮时间／调用／候选预算，预算耗尽、没有新信息或授权不足就停止。
  - 修改一项定位规则形成新候选，重验受影响步骤和必要后置；不从头自动重放已经可能生效的前缀。原生 `actionState: 'unknown'` 或视觉输入状态不明时终止当前执行，不自动续跑。
- 固化／交接时。
  - 把修复写回既有 AppProfile／定位规则、普通 JS 与相关测试，保留来源版本、适用范围、误识别原文和失效条件。
  - 新候选不能继承旧候选的资格结论；生成者自测不冒充独立验收，局部通过不冒充所有平台／布局通过。

路由使用既有 [application-engineer](../../workflows/agent-to-recipe/skills/application-engineer/SKILL.md) 的 `harden / repair`，不增加 mode 或第十三个阶段。Agent-to-Recipe 在 S10 定位工程、S11 生成者自检、S12 验证与维修回流中消费本方法。Human-to-Recipe 复用同一方法；涉及真实桌面、定位策略替换、业务意图或结果 Oracle 时按根 `AGENTS.md` 进入 Human-to-Recipe 的完整方法，不能借本方法扩大 recorder-script-refiner 的静态行为保持权限。纯格式精炼不因此被强制执行桌面测试。

## 7. 验证清单与证据

| 场景 | 必须证明什么 |
| --- | --- |
| 原始 `×` 能识别 | 正常路径不依赖错读别名，语义保持乘法 |
| 仅错读为 `†` | 在批准范围内命中同一乘法按钮，保存 rawText；其他区域不接受 |
| `×` 与 `†` 分别命中不同位置 | 歧义停止，不挑其中一个 |
| 缺 `4` 或 `=` | 表达式输入前预检发现缺口；别名不能把 missing 改成通过 |
| 显示区也有相同数字／另一个应用有 `†` | scope／区域限制有效，不跨区域或应用误命中 |
| 动态页面目标尚未出现 | 按阶段预检，不强制未来目标当前可见 |
| 窗口平移与旧缓存 | 用当前有效规则重定位或明确失效，不用旧 screen point |
| resize／模式／主题／DPI 超出资格 | 重新认识并验证，或安全停止，不假定兼容 |
| 动作已发出后超时／取消／unknown | 不自动重试该动作，不改 backend 后续点，不从完成前缀推导安全重入 |
| 真机单式 | 操作真实 `2 → 5 → × → 4 → =`；从显示组件读取 actual，独立断言 `100` |

验证分层：纯规则／模拟测试 → 已保存图片的识别与审阅 → 当前窗口的只读预检 → 授权后的真实动作与业务后置 → 所声明支持范围内的变化测试。静态／模拟通过不能替代后面几层；只在声明支持的环境内要求正向通过，超出范围可以用明确拒绝作为正确行为。

工作包沿用当前目录和共享合同。运行原图、OCR 原文、诊断和日志保存到既有 `.runtime/automation-authoring/` 工作包或相应 `.runtime/tests/` 运行目录，不提交到源码。最小修复记录包括：来源候选与规则版本、故障及原始证据、分类与仍未知项、采用／拒绝的方法、范围和失效条件、动作状态、实际结果来源、已运行／未运行项、下一消费者。它是现有工作包的说明，不新建竞争性的 AppProfile schema。

本方法的完成标准是：生成者能在真实失败后找到对应修复分支并正确留证、停止或重验，而不是每次都增加 timeout、重新生成整段脚本，或把碰巧成功的一次点击称为稳定自动化。
