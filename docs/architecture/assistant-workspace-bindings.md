# AI 助手：任务、资产、授权与 Codex 接续合同

修订 v0.5，2026-09-18。状态：任务/资产与安全另存核心已实现，作者源码工具仍 BLOCKED，真实桌面/模型资格待证据。源码、测试命令和未运行项统一见 [主方案](assistant-script-invocation.md) 第 0 节；本合同继续拥有最小绑定和授权语义。

本文拥有最小绑定、文件授权、任务目录、候选保存和接续规则。沿用现有 [对话工作台](conversational-task-workspace.md) 的会话列表、消息、草稿、窗口和编辑体验，不因增加制作入口重做 UI。旧“一个主工作区／轻量项目记录必需”前提由本合同替代；已有开发项目仅保留为可选来源。

## 1. 用户对象与四类起点

**用户看见本次任务、可选关联自动化和当前阶段，不需要创建项目、Git 仓库或开发目录。**

| 状态 | 默认绑定 | 工作资源 |
| --- | --- | --- |
| 普通问答／只读解释 | 当前会话；解释资产时带明确资产引用 | 不建制作目录；按权限提供必要文本或只读视图，传输缓存不算制作工作区 |
| 使用已有自动化 | 明确脚本／Flow 或允许的 Flow 范围，随后冻结选中身份 | 仅需要既有调用草稿与 Run Record；不要求源码或作者目录 |
| 制作／改进 | 当前任务＋零个或多个必要资产引用 | 首次产生候选、进度或必要证据时自动准备任务资料 |

四种起点的完整入口表在主方案第 2 节。这里固定其绑定结果：无资产为真正的空引用，不生成虚拟项目；单脚本为精确文件引用；目录自动化为明确根、入口与必要依赖边界；已安装 Flow 为 installId、来源和内容摘要，sourceRef 可以为空。

上下文栏最多显示：模式、本次任务、关联自动化、阶段；保存位置和技术身份放详情。第一次需要持久材料时系统自动选择应用数据位置并告知，用户可以明确另存，但不需要先挑文件夹。未授权执行的普通对话不能因措辞“运行／自动化”就获得工具权限。

本地 Codex、AI 助手、Recorder 交接和从 Flow Runner 进入均引用相同任务／资产合同。已有选择来自入口事件，之后 Runner 切换条目不改变当前任务。市场链接仅产生安装意图，不附带作者态、助手启用或运行许可。

## 2. 最小记录：不是新项目管理系统

以下是逻辑语义组，不是已发布的 JSON Schema 或公共 API。优先扩展已有会话/request、TaskContract、progress/handoff、Candidate、Qualification 和 Run Record；字段能引用就不复制。现有 Calculator envelope 的 task 是 operation 名，不冒充制作任务 taskId。

| 记录 | 最小语义 | 可为空／兼容规则 |
| --- | --- | --- |
| 会话上下文 | conversationId、mode、contextRevision、当前 taskRef、允许调用范围 | taskRef 可空；保留可选 projectRef 作为来源或过滤项 |
| 制作任务 | taskId、goalRevision、目标／标准、mode、assetRefs、工作流版本、阶段、产物／证据引用、下一缺口、已知／未知副作用 | assetRefs 可空；workdirRef 按需；不要求 projectId，不强制每阶段另建任务 |
| 关联资产 | kind、来源身份、精确文件／目录／installId 引用、内容修订／摘要、已知入口、依赖／资源边界 | 源码引用可空；入口未知可用于澄清／有限解释，但不能放行执行 |
| 文件与动作授权 | 授予者、用途、资源集合、允许动作、外发范围、相关修订、有效期／撤销状态 | 不从 assetRef、projectRef、Skill、profile 或模型文本派生授权 |
| 调用草稿与确认 | 已选 Flow／资产、固定行为或参数及来源、目标对象、previewRevision、内容／输入摘要、授权引用 | 无参数固定任务显式空输入；确认需绑定最终版本和效果 |
| 执行绑定 | 既有 runId／Execution.id、task/request、精确运行内容、实际 cwd／资源／输出位置、确认、状态和证据 | 已安装 Flow 可无源码；直接源文件运行也必须有内容身份，不为此强制安装 |
| Codex 调用绑定 | callId、任务／请求修订、适配器与实际 CLI 版本、Skill／配置来源摘要、可用时的 thread/turn/item、最后持久事件 | 不以 Codex thread 作为任务或 Execution 身份；无持久线程也可凭任务资料接续 |

示意关系：

```text
Conversation ──当前视图──→ Task（可空）
Task ──来源──→ AssetRef[0..n] ──可选──→ Developer projectRef
Task ──按需──→ Task materials / Candidate / progress / evidence
Grant ──约束──→ 某任务的某资源、动作、用途和修订
Codex call ──关联──→ task + request + revision
Run ──固定──→ 内容 + 输入 + 目标 + 授权 ──实际执行──→ Execution
```

单次确定运行可以复用现有 invocation/task 记录，不强制先有 authoring task。多个会话可引用同一资产，但参数、候选写入、授权和迟到事件按身份隔离；禁止全局“当前工作目录／当前脚本”承担这些关系。

可选项目迁移采用版本化读取：保留旧 projectId/projectRef，映射为可选来源信息，不生成新空项目，不将旧 project root 直接转为递归授权。旧记录缺资产或授权范围时标为待补，不自动选择其第一个 JS。任务 ID、源资产、证据链接和进行中状态保留；迁移不能自动运行或清理原资料。

## 3. 文件授权与第三方内容边界

| 动作 | 需要的独立依据 | 明确不包含 |
| --- | --- | --- |
| 关联文件／目录／Flow | 用户选择或受信入口携带的资产引用 | 读取整个父目录、模型外发、安装、运行 |
| 解释 | 必要内容的只读及模型外发依据；产品可提供清晰的范围确认 | 执行源码、解密受保护源码、读取无关文件 |
| 改进 | 当前任务候选写入许可、允许源材料、变更目标 | 回写原文件、修改安装树、运行候选 |
| 实际操作／测试 | 应用、账号／对象、文件与外部效果、预算／期限和停止规则 | 任意 Shell、整个桌面或其他任务的权限 |
| 回写／另存 | 精确目标、已审阅 diff／候选、基线摘要、覆盖策略 | 保存即安装、启用或运行 |
| 安装／启用 | 既有安装、信任、权益与助手范围管理的批准 | 自动执行旧需求或取得源码修改权 |
| 日常运行 | 最终内容、固定行为／参数、实际目标与本次确认，或既有明确调度授权 | 继承制作许可、遇失败自动进入作者态 |

### 3.1 单文件与目录

单文件选择只允许该文件；解析到相邻 helper、配置、图片或外部路径时先列出必要依赖，再按授权读取，不隐式读取父目录 AGENTS、环境文件或其他脚本。单文件解释可明确“未读取依赖”；缺依赖不是扩大读取范围的理由。

目录选择先界定可列举／可读范围和排除项。入口来自受支持且通过静态结构校验的 Manifest，或用户明确选择；Manifest 的入口声明仍是数据，不是发布者信任。存在多个合理入口、动态加载或资源边界未知时澄清，不选择“第一个／最大的 JS”。未知 npm scripts、install hooks、配置代码不在发现阶段执行。

授权作用于规范化真实对象，不只字符串前缀。服务端检查真实路径、符号链接／Windows reparse point、目录逃逸、大小写／Unicode 冲突、替换文件及半写入；必要时使用已打开句柄或受控副本防止检查后替换。候选不以硬链接／符号链接写穿原文件或安装树。解析不确定则拒绝，不以正则路径白名单声称安全。

资源授权区分可读源码、可变业务输入、可写结果和可外发数据；它们不是一个 root 的全权限。哈希固定代码与必要依赖身份，可变业务数据另按调用合同管理。摘要不证明可信、无秘密或正确性。

### 3.2 不可信指导与受保护 Flow

关联第三方目录不是信任该目录的 AGENTS、Skills、hooks、`.codex` 或插件配置。它们不得进入受管 Codex 的自动发现命名空间；需要分析时只以明确标记的数据视图提供。源文件、控件、邮件、截图 OCR 和模型建议不能修改宿主授权。

受管启动固定工作位置、有效配置和 Skill 来源，不在第三方根启动。官方发现层及 ignore-user-config 的限制见主方案第 5 节；不能宣称 CODEX_HOME 已隔离 HOME 的全部 Skills/hooks。实际加载源无法限定时停止作者入口，不关闭管理员保护来“修复”。

已安装 Flow 默认只通过宿主白名单元信息解释。对受保护载荷不解密给模型，不创建明文快照／临时源码／日志；拥有运行权益不等于取得源码。助手运行还要求 `.odflow` 根级可选 `assistant-use.json`：它必须位于现有 signed file inventory 中，并在 `AcquireRun` 的包目录复验通过后才由宿主投影 effectSummary、参数类型和 fixedInputs。缺少该签名资源的旧 Flow 仍可由 Runner／CLI／计划中心运行，但助手 fail closed，不猜固定行为或参数。改进需合法可编辑来源，或用户明确另建新的实现；不能热改安装树或假称已改进无法读取的内部实现。

### 3.3 文件工具与脚本权限不能混淆

作者材料读写优先走宿主资源引用与有界文件工具；原始文件路径可保留作显示／来源，但不由模型自由解析为权限。禁止通过通用 Shell、未知插件或 raw JS 接口绕开文件工具授权。工具名称筛选只是减少可见工具，服务端仍须校验任务、调用者、授权、参数、资源与有效期。

现有 App-owned Runtime 不等于细粒度 OS 沙箱。直接运行自有已选脚本可保留现有入口，但必须如实展示该入口实际权限和未验证限制；若用户要求的窄范围不能强制保证，或脚本来源不可信而要求隔离，则阻塞相应运行。不把候选文件读写限制冒充业务 JS 的文件／网络／native 隔离。

## 4. 工作目录与业务运行目录必须分开

| 位置 | owner 与目的 | 规则 |
| --- | --- | --- |
| 用户源文件／目录 | 用户拥有的原资产 | 默认只读引用；不因开始任务移动或复制整个父目录 |
| 任务资料根 | 现有助手／作者任务持久化 owner | 存必要候选、进度、交接及证据；可选采用应用数据根下 assistant/tasks/taskId 的内部布局，不是新项目系统 |
| Agent cwd | 本次 Codex 的受管操作位置 | 通常指任务工作材料区；普通解释可仅用传输目录；不指向用户整个源码或 Flow 安装树 |
| 候选源码／资源树 | 当前任务生成的可审阅资产 | 只包含获准必要依赖；保留相对布局，不拷贝凭据与自动发现配置 |
| 业务 execution cwd | 现有执行服务按脚本合同选定 | 与 Agent cwd 分开；当前助手默认复用正式 Runner 的 `appDataRoot` cwd，只有用户明确填写时才覆盖；不从源码父目录猜测 cwd |
| Flow 资源根／数据／状态 | 既有 Flow owner | 安装内容在 flows/installId；flow-data 与 flow-state 各依原 owner，不借作者任务改布局 |
| 传输缓存／日志 | 现有 invocation/artifact owner | 限范围、限尺寸、脱敏；不能是唯一脚本、未完成任务必要资料或有效资格证据 |

当前实现已在现有 assistant app-data 下建立 immutable task revision 与 candidate revision 文件；它不是 project root，也不改变 Flow 安装根或凭据位置。Task revision 使用 expectedRevision＋`File.writeNew`，旧 revision 冲突不会静默覆盖；sessionId 只是最近会话元数据，不再拥有 taskId。历史 projectId/projectRef 仍为可选来源字段，不会转成递归文件授权。

相对路径需要分别判定：Runtime module/helper 以何处解析，`Execution.scriptDir` 指向什么，File 相对路径按何 cwd，输出路径由何合同决定。只改变 Agent cwd 不得改变这些业务含义。已知旧脚本 cwd 依赖不得默默替成任务目录或“总是脚本父目录”。未知时只阻塞依赖该信息的运行，不强迫用户为解释配置工程。

候选冻结包含精确入口、代码依赖及资源映射；测试从正常执行入口加载同一候选，不伪造 scriptPath/scriptDir。有绝对路径、运行时下载或无法固定的动态代码依赖时先暴露缺口。复制成候选并不天然保持业务语义；路径变更必须被审阅和验证，不能以旧代码 PASS 覆盖新执行布局。

## 5. 候选、保存与并行修改

修改默认写本次任务的候选，留来源摘要、必要依赖版本、diff、变更目的与未验证项。普通改进不强制参数化，不复制整个开发工程，也不按业务文件生成 Skill。只读解释不自动生成可运行候选。

回写流程：用户审阅候选与明确目标 → 宿主重读当前源文件及相关依赖 → 比较制作基线与实际身份／摘要 → 重查权限与目标 → 由唯一写入者提交 → 保存结果及新摘要。原文件已变化、被替换、目标越界或相关依赖变化时，保留两侧内容并返回冲突；不覆盖、不自动以模型 merge 解决业务差异。

当前生产实现对候选采用**安全另存而非原地覆盖**：`File.writeNew` 通过已打开父目录＋独占创建提交新文件，拒绝已存在目标、最终 symlink、父目录 symlink/reparse-point 别名及授权期间父目录身份替换；源文件原地覆盖暂不支持。目录型多文件回写仍没有事务 owner，因此不宣称目录原子回写。未来若增加原地更新，必须另做 compare-and-swap/事务 owner；更新安装版本仍只能走原 Flow 事务安装服务。

同一任务只有一个进度写入者；候选并行编辑需独立候选修订或写入租约。只读分析可并行，桌面输入不并行。同一资产被其他会话修改后，相关资格、预览或未执行确认失效；正在执行的精确内容由原 owner 持有，不混用新 helper。

保存不代表安装；安装不代表助手启用；启用不代表立即运行；测试通过不代表批准上述动作。UI 可以提供明确组合选项，但必须展示每一项效果并逐项满足原 owner 的门，不能由一次模糊“完成”批准全部。

## 6. 精准使用与确认绑定

使用范围为用户允许的 Local Flow Catalog 投影，或当前明确绑定的直接脚本。不因搜索无结果自动扩到全磁盘、其他项目、其他会话或远程市场。名称不承担身份，模型 confidence 不承担正确性或授权。

固定任务的门店、收件人、输出与副作用是硬约束，无业务参数也需完整匹配。当前窗口、账号、剪贴板、选中对象和日期时区等必要隐式输入应解析／核验；关键未知先澄清。参数化只能开放实际代码消费且验证过的字段，不能通过只改描述符假装参数生效。

后续“把刚才的乘数改成 7”绑定本会话 draft/revision，不重新猜其他脚本。关键业务值保存真实来源消息或 Observation 引用，模型自述不是已核对来源。同名歧义返回 clarify，不可用、未激活、权限不足或固定行为冲突返回明确阻塞，不偷偷换一个近似任务。

可信预览由宿主的确定描述与校验输入生成，列出真正目标、文件、效果和关键权限；不是直接展示模型自报执行计划。确认固定 context/goal/preview 修订、内容及依赖摘要、参数／固定约束、相关配置、目标、策略与有效期。相关变化使确认失效；双击确认只消费一次。无关条目新增只有在可证不影响绑定时才不使确认失效。

保存、启用和历史恢复不重放最初需求。Flow Runner、CLI、计划中心对已确定任务直接进入现有执行合同，不需要 Codex 再决定一次；若脚本本身明确声明模型节点，那是其独立业务依赖，不是助手强制依赖。

## 7. Codex 接续、来源固定与一次性设置

两条通用 Skill 只负责方法选择，不按每份脚本部署新实例。主方案维护官方版本与发现规则；本合同固定每次任务的实际 Skill 路径、产品来源、版本／摘要及必要方法资料。活动任务不静默升级 Skill。与现有 Agent/Human 方法共享成果结构，内部专业方法并非必须部署为更多独立模型。

一次性设置负责官方 CLI、认证、受管配置和 Skill 部署，采用产品可见引导；普通用户不复制内部文件、不修改 TOML。优先复用合法官方凭据存储，不把凭据复制到任务或安装包。版本变化触发有界兼容检查，不在每次任务都重装；getCapabilities 的静态 configured 结果不能冒充已验证版本／登录。

近期非交互 exec 的每段工作必须在已授范围内；权限不足不自动批准，保存待确认原因和接续点。未来 App Server 的 thread/turn/item、审批与中断只改变传输接缝，不改任务和执行 owner。当前 analysis-only Agent.run 不被扩大为作者模式；新作者接入需可测试的独立策略，不提前发布不存在的 API。

接续顺序：读取 task／progress／handoff／候选与最后可信事件 → 校验内容、依赖、授权、Skill 与工具版本 → 核对现场及未知外部效果 → 确定第一个实际缺口 → 用户批准必要动作后继续。使用明确关联的 session ID；禁止 `resume --last` 意外接入其他任务。

Codex 线程丢失可以用原任务资料开新线程，不强迫从零演示；线程恢复成功也不能跳过现场核对。原任务授权不自动续期，原 read grant 不因改进要求变成 write grant；模型总结不能替代实际工具和 Runtime 证据。

## 8. 联合停止与事件归属

停止必须同时处理模型与实际执行：先阻止新的工具授权／动作提交 → 请求 Codex 调用停止 → 请求 OpenDesk 活动工具／Execution 取消 → 等待 owner 收口和最后状态 → 对已提交效果做核对。只有实际可确认静止才显示 stopped；两者任一未知保留 stopping 或 interrupted/unknown，不把进程退出当业务成功。

事件至少关联原 task/request/revision、call/thread/turn/item（存在时）、tool call、Execution 和 step。真实动作、结果、失败与不确定状态在发生时持久化；后写模型摘要不补造动作顺序。事件丢失要有可见缺口，不能把断流前“已请求”改成“已完成”。

切换会话只切视图，不转移授权；旧活动任务可按原绑定继续或由用户停止。改变活动任务的资产／模式／工作根之前必须实际停止并生成新修订。迟到事件仅追加到原任务证据，不覆盖当前会话，不复活已取消确认。

Codex sandbox 不约束另一个服务进程的所有副作用；MCP 和现有执行 owner 必须独立实施授权、资源仲裁、时限和取消。无法核验的外部 CLI／其他 App 排他范围如实说明，不能拿本窗口 single-flight 证明全系统互斥。取消不承诺撤销外部发送或 exactly-once。

## 9. 持久资料、缓存与安全删除

任务资料按生命周期分类而不是按目录名字删除：用户唯一源码、未另存候选、未完成任务的接续资料、未知效果对账材料、仍被有效资格或运行引用的证据属于保护集；可再生成的索引、已确认无引用的传输缓存才可自动清理。

实施在现有任务／artifact owner 增加引用与保留判断，不建立新证据平台。活动租约、未解决效果、有效 Qualification 引用及用户保留要求会阻止清理。容量不足时提示另存、导出或明确删除，不用 TTL 删除唯一脚本。需要保留的证据可按政策脱敏归档；原证据不足则标记资格失效，不能删除后仍宣称有效。

历史 `.runtime/automation-authoring/<task-id>/` 可能含唯一候选或未完成工作；不得因 `.runtime` 通常可清理而直接递归删除。先识别和保护必要资料，在后续明确迁移／导出获得耐久副本并验证引用后才能清理旧缓存。本轮不搬迁这些资产。

删除会话、删除任务、清理缓存、卸载 Flow、撤销助手启用、删除用户源码和业务输出是不同操作。删除会话不级联删除后几类；明确删除任务须说明哪些未另存成果和证据会消失。Flow 卸载／更新与运行中内容保护沿原安装 owner，不由任务清理器删除。

## 10. 验收与兼容

主方案是唯一总入口，本合同不是新的项目服务或第二份排期。生命周期继续拥有候选／资格／发布，既有对话工作台继续拥有 UI。生产版本、官方版本、隔离和停止的未验证项及行为覆盖统一见 [验收合同](../quality/assistant-authoring-reuse-acceptance.md)。

必须分别记录静态文档检查、确定性 fixture、真实 Codex、真实 Runtime、业务与视觉证据。缺源码、缺真实平台或无权限时明确未验证／阻塞；不得把本轮设计通过写成实现通过。
