# AI 助手：入口、会话绑定与 Codex 接续合同

日期：2026-09-18。状态：设计合同，未表示 UI、Codex 集成或新 Runtime API 已实现。

主阅读入口：[制作与复用总方案](assistant-script-invocation.md)。本文拥有入口、上下文绑定和权限转换规则；现有 [对话工作台](conversational-task-workspace.md) 继续拥有会话列表、消息、草稿、窗口及编辑体验。其 2026-09-13 的“下一轮只实施 P0.1”是历史排期，不是当前实施指令；涉及项目绑定和作者态的旧泛化描述以本合同为准，不要求重做已实现会话功能。

## 1. 用户看见的三个状态

| 状态 | 默认上下文 | 可做什么 |
| --- | --- | --- |
| 普通问答 | 当前对话，可未绑定项目 | 回答、解释；不因消息提到文件/应用就得到读写或运行权限 |
| 使用自动化 | 用户明确可用的 Flow 范围；项目是可选过滤项 | 查询已接入任务、澄清、预览、经确认执行确定版本 |
| 制作／改进自动化 | 一个主工作区、一个制作任务、必要来源资产 | 在声明权限和预算内操作、留证、生成候选、验证；不自动启用或发布 |

不要求每次提问先选项目。第一次制作时可由宿主采用已设置的个人工作区，展示任务名称和实际保存位置；更换位置仍须经用户明确选择。单个 JS 可使用轻量项目记录，不强制建 Git 仓库、复制源码或手写 Manifest。

上下文栏只需展示：当前模式、项目或可调用范围、当前任务、关联程序及阶段。技术身份、真实路径、代码摘要与证据放入详情。不建设必需的任务商城、脚本选择器或参数表单；对话内消歧和已存在 Runner 的明确选择继续支持。

## 2. 六个正式入口场景

| 入口 | 携带的绑定 | 行为与边界 |
| --- | --- | --- |
| 本地 Codex 制作 | 工作区＋制作任务＋初始目标 | 操作 OpenDesk 时同步记录真实观察；生成普通 JS 后独立验证 |
| 助手中“制作自动化” | 工作区＋新制作任务 | 后期接入官方 Codex 适配器，复用同一任务包与工作流 |
| 对已有 Flow 解释／改进 | 精确 Flow/候选引用及来源项目 | 解释只读；改进另建候选，禁止编辑安装区或正在运行的内容 |
| 从 Recorder 整理 | recording 引用＋来源任务＋输出工作区 | 保留 Human 来源；优先复用已有动作和证据，不重新演示同一已确认事实 |
| 对话运行已有 Flow | 已授权目录范围，随后固定 Flow 版本及输入 | 不需要源码目录；已选定目标不再对全库重新模糊选择 |
| 继续未完成制作 | 原任务包＋产物＋进度＋失败/未知效果 | 核验当前状态，从首个实际缺口接续；未知副作用先核对，不重放整个前缀 |

从 Flow Runner 进入助手时，目标必须是入口事件中明确携带的 Flow 身份；播放器随后切换条目，不得改变已建立的任务绑定。市场链接只产生安装意图，安装、启用给助手、运行互不自动推出。

## 3. 六类身份，不能只用一个“当前目录”

以下是逻辑信息组，不是已经发布的 JSON Schema 或公共 API；优先映射现有字段，不机械新增同义 ID。

| 记录 | 最少保存的语义 |
| --- | --- |
| Conversation Context | conversationId、mode、contextRevision、可选 projectRef、允许 Flow 范围、当前任务引用 |
| Workspace Binding | projectId、规范化 root、显式允许读/写范围、来源、权限版本；路径不是身份 |
| Authoring Task | taskId、目标修订、工作流版本、来源资产、阶段、产物引用、已完成证据、下一缺口与副作用状态 |
| Invocation Draft | 所选 Flow/operation、固定行为或参数及来源、业务对象、previewRevision、支持范围 |
| Run Binding | runId、Execution.id、精确安装内容摘要/版本、input 摘要、相关配置和目标、授权引用 |
| Codex Binding | 工作区/制作任务＋适配器版本＋thread/turn/item 身份及最后可核对事件；不充当项目或业务运行身份 |

会话 A 和 B 可属于不同项目；草稿、参数、确认、Agent 上下文和返回事件都按各自身份隔离。一个任务内部可以有多个阶段及候选，不要求一个阶段另开 Agent 或另建项目。

切换会话只是切换视图，不把旧任务授权转给新会话。取消旧任务后才迁移其工作区/模式；取消未完成时保持 stopping，不能重绑定正在操作的执行者。只要版本/范围/目标发生影响授权的改变，旧预览及确认失效。

运行视图可以附带来源项目用于解释，但源码缺失不阻止一个已合法安装且当前可用的 Flow 运行；安装内容和授权独立校验。反过来，看到一个源码目录不证明其中程序能被助手使用。

## 4. 权限不随绑定隐式扩大

| 动作 | 需要的独立依据 |
| --- | --- |
| 绑定项目 | 允许把该项目作为上下文，不等于递归读取/上传全部文件 |
| 解释代码 | 明确只读范围与必要模型外发范围；受保护载荷不解密给模型 |
| 编辑候选 | 当前任务写入范围、单写入者或冲突检测；修改留 diff 与来源 |
| 真实操作/测试 | 指定应用、账号/对象、可接受副作用、停止与预算；必要高风险动作单独确认 |
| 验证候选 | 固定候选和标准，测试数据/恢复方式获准；不得再次发送/扣款以“验证”为由造成重复业务 |
| 发布/安装/启用 | 沿既有发布及安装链；验证成功不代表获准安装或自动纳入助手可调用范围 |
| 日常运行 | 确定 Flow、输入/固定约束、当前环境和本次确认；不继承制作或安装授权 |

缺能力时只能生成 Gap 或建议制作，不能自动启用作者工具。用户明确要求的模式上限由宿主执行，不能由模型文本改变。

第一阶段对没有可强制限制的任意第三方脚本不提供安全沙箱承诺。同进程独立 Runtime 只解决上下文和生命周期的一部分；文件/网络/桌面权限及 native 崩溃隔离需依真实实现说明。

## 5. 精准匹配与多轮修订

用户指定的 Flow、参数、禁止项、项目和业务对象先成为硬约束。查找仅消费 Local Flow Catalog 的授权投影及可信调用说明，不执行源码来探测用途，不自动扩大到其他项目或远程市场。

固定任务没有业务参数时只接受空输入，但仍比较其固定效果与完整请求。请求“门店乙”不能丢掉该限定后运行“门店甲”。当前窗口、账号、剪贴板、选中对象和系统日期属于隐式环境输入，必要时显式解析并确认。

已明确选中任务后的“乘数改成 7”绑定当前 draft/revision，而不是全库重新猜目标。关键值保留来源消息或已验证 Observation 引用；模型生成的来源说明不算已核验事实，宿主应能找到真实来源。

相关但未获权限/未激活/不支持当前平台的 Flow 返回 blocked；不能悄悄换成另一个不符合要求的程序。候选接近则在对话内消歧；没有候选则 Gap。相似度和模型自报 confidence 不是授权或准确率。

## 6. 本地 Codex → 助手内 Codex

两种入口共用工作区、任务包、工作流与 OpenDesk 工具服务；不复制第二套桌面执行器、录制器、生产流程或资格体系。

近期先完成本地 Codex 的真实制作与交接；后期在适配层评估官方 App Server 的 thread/turn/item、审批、流式事件与中断。上游协议能力不证明 OpenDesk 已接线；固定实际 CLI/协议版本并验证取消、认证、权限和兼容性后再启用。不得直接扩大当前只读 Planner profile 的权限以冒充作者态隔离。

Codex 线程可被替换，任务包必须可独立读取。接续流程：检查原任务/产物/最后证据 → 核对当前文件和环境 → 识别未完成/未知效果 → 从实际缺口继续。线程恢复和打开历史都不自动执行。

需要保存的信息可以引用既有 progress/handoff/procedure/AppProfile/Candidate/Qualification，而不是再生成一套同义记录。临时运行材料继续归 `.runtime/`；用户源脚本和启用版本所需证据不能只有可清理临时副本。

Agent 工具结果和 OpenDesk 步骤事件分别记录来源，关联到 task/run/step。模型说“已经点击”不等于 Runtime 有动作证据。停止制作要向适配器和 OpenDesk 活动动作传递，拒绝迟到事件；外部已提交效果不能保证撤销。

## 7. 计划与实际可视化

不新增可执行 DSL。业务步骤说明、实际代码位置、当次动作/Observation 和证据之间建立可核对映射；计划图与实际轨迹分开。

页面可以显示：计划包含五步，本次执行到第三步失败；未执行步骤不能渲染成完成。查看代码只显示运行时固定内容；受保护 Flow 展示获准元信息和行为说明，不展示解密源码。日志/trace 默认本地脱敏，不自动复用为 PostHog 产品统计或模型上下文。
