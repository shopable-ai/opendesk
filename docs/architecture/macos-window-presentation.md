# macOS 窗口与 Dock 行为

需求来源：2026-11-02 用户反馈，Flow Runner 的三个标题栏按钮只有关闭可用，且最小化与 Dock 入口不清楚；同类 Recorder 窗口应共享规则。

## 设计

- 普通页面保留关闭、最小化、缩放和普通窗口层级；显示或最小化期间提供 Dock 入口。
- 横向原生工具条保留关闭与可用的最小化，隐藏不适用的缩放；布局固定，不因启用最小化变成可调整大小的窗口。
- 60pt 竖向及过窄工具条保留紧凑的关闭按钮，不强塞第二个按钮；保持原有内容尺寸与非激活行为。
- 工具条显示时保持菜单栏工具的轻量行为；有工具条最小化时保留 Dock，以免窗口失去恢复入口。
- Dock 点击恢复最近使用的可恢复窗口；Dock 菜单可分别恢复多个普通页面和工具条。恢复不改变窗口原有置顶策略。
- 隐藏不等于最小化：普通页面隐藏后不单独保留 Dock；另一个窗口仍显示或最小化时不能提前撤销 Dock。通知、Measurement、reference-selection 不单独创建 Dock 入口。
- Dock 使用所属桌面应用的名称和图标，不把内部二进制名当作产品名称。主进程继续负责菜单栏和产品退出，UI Host 不提供仅退出子进程的命令。

采用共享原生 Host 的窗口状态规则，避免在 Flow Runner、Recorder 中各写一套。保留主进程与 UI Host 的既有隔离；不把全部工具条永久改为普通应用，也不更改用户的系统 Dock 偏好。

## 实施与验收计划

1. 先运行 JavaScript 原生回归，证明旧 Host 的横向工具条最小化不可用。
2. 修改共享标题栏、最小化恢复和可见窗口/Dock 生命周期；保持现有未提交修改。
3. 验证普通页面、横向/竖向工具条、两个窗口同时最小化、hide/show/close、Dock 恢复与非激活/置顶行为。
4. 按固定开发签名构建完整 App，核对运行路径与产物签名后验收实际窗口并保存截图；运行产物写入 `.runtime/tests/window-presentation/`。
5. 独立专家按功能 35、Dock/多窗口 25、原生体验/视觉 20、回归与维护 20 评分。95 分仅在证据支持时成立；分开报告源码、加载、视觉和功能状态。

约束：不创建或切换分支，不提交其他任务改动，不重置权限，不强杀未知进程，不更改产品按钮 URL，不为本次窗口修复扩大到业务流程回归。
