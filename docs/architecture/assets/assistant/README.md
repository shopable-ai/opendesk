## 必须与原图一起阅读的旁注

这些是对图中简化表达的明确限定，不修改原图，也不把图中未画出的机制说成已经实现。

1. 总体流程中画出的 Codex 节点不表示每个请求都必须经过 Codex。普通问答／只读解释不执行业务；已确定 Flow 的日常执行走现有执行服务，不强制启动 Codex。
2. 图尾“用户确认与后续”对应保存、安装、启用等后续选择，不表示先执行真实业务再征得同意。真实操作和独立测试必须事先取得对应授权；确认不能只依赖模型文案。
3. 制作链的压缩方框不能改变独立验证顺序：获准真实操作及第一次业务核验（需要时）→ 提炼普通 JS 候选 → 冻结候选与标准 → 在获准测试状态独立运行。Agent 临时补做不能算候选通过；第一次已有副作用不能盲目重复。
4. 图中的“工作目录／隔离安全”是职责和目标，不是只改变 cwd 就获得隔离。关联资产不等于权限；任务材料、用户源码、Flow 安装区和业务执行目录必须区分。
5. Codex harness／Profile／Skill 方框不表示 OpenDesk 已接通作者模式、恢复、事件或权限。只复用官方能力，不另造记忆、Agent 编排、业务脚本副本库或 Runtime；两个通用 Skill 名称仍须按实际部署核验。
6. 图中安全结论是验收要求，不是实测结果。受保护 Flow 不因解释／改进泄露源码；停止以实际执行收口为准；未知结果不伪装成功；清理不能删除唯一资产、未完成资料或有效证据。
