## 1. 用户需求与最新架构决定

用户希望 Go 开发 macOS / Windows 桌面时钟、时差与 Codex 公告提醒，呈现在系统桌面背景中。价格目标为每人 0.99/月，首次免费；先在现有 Go 仓库做 demo，确认方案后才写代码。2026-10-11 最新补充：**数据采集可能已有外部程序或服务提供，当前程序不应默认自行爬取 X、维护 Cookie、数据库或采集调度。**最好先尝试直接以 HTTP/HTTPS 获取已有内容；请求不成功时清楚报告原因，只在明确缺口出现时追加适配。

### 1.1 默认最小架构

**外部数据提供方（自由选择实现） → 一个受控 HTTPS JSON Feed → Go 桌面端 HTTP 获取、缓存、时间换算和提醒。**

“提供方”可以是已有正式 API、用户运营的独立定时任务、可信第三方、授权发布平台或经人工维护的 JSON 文件。桌面端不关心谁负责采集，不向 X 发起批量请求，不共享或托管用户的 X 网页 Cookie。当前 demo **无需 Go 采集服务、SQLite、LLM、对象存储部署或商业授权服务器**。

仅当外部数据源不能直接提供可校验的事件 JSON 时，才考虑在**外部生产侧**增加非常小的格式转换或审核步骤；只有客观证明需要历史、并发、撤销队列或商业鉴权后才建设更复杂的后端。未经用户单独批准，不恢复原先自动构建的中心采集系统。

| 决策 | 当前默认 | 可选升级触发条件 |
|---|---|---|
| 采集 | 完全由外部来源负责 | 没有合法可用源时暂停真源功能，不暗中启用爬虫 |
| 数据协议 | HTTPS GET 的版本化 JSON | 仅有 HTML/RSS/原始帖时由外部适配器统一转换 |
| 访问认证 | 公共 feed 无 Cookie；私有 feed 可用供应商支持的 Bearer/API Key | 外部合法会话要求 Cookie 时，独立评估范围、安全和协议 |
| 存储 | 桌面只保存当前有效快照、ETag、必要设置及去重状态 | 真正需要长期事件库时才增加服务端 DB |
| 发布 | 外部发布者提供经过审核的事件 | 自动语义提取与多来源合并作为后续单独工作项 |
| 实时性 | 轻量轮询与来源健康显示 | 有明确时效和用户规模证据再考虑推送 |
| 个人额度 | 可选独立本地读取功能 | 不混淆公共公告与账户实时额度 |
| 商业 | 暂按美元展示成本假设，首次免费及收款周期待确认 | 至少 30 天成本、可靠性、持续使用价值调查后定价 |

准确 tibo X 账号仍待确认；此前候选为 [@thsottiaux](https://x.com/thsottiaux)，不能当作已核实的唯一来源。0.99 币种仍未确认；如暂按美元，US$11.88/年等效月均 US$0.99、首次 30 天无绑卡试用仍是建议，不是已批准商品。只有文档评审，**没有代码、HTTP 联调、真机测试或真实支付验收**。

## 2. 产品定位与最小范围

建议工作名为 **Reset Clock**。收费价值是可靠消费经过来源方核实的公告、时间换算、异常可见、提醒与双平台维护；采集和公告审核可以由外部数据提供方完成。

### 2.1 公告与个人额度必须分别表达

公共来源的发言不能直接证明某个人的账户余额、正常滚动额度窗口或兑换状态。应用应保持三种来源：

| 来源 | 能表达的内容 | UI 必须标注 |
|---|---|---|
| 公共公告 | 某来源宣布一次重置、发放可使用的重置机会、调整规则或倍率 | 来源、公告状态、适用范围、原帖时间、核查状态 |
| 手动提醒 | 用户自己输入的目标时刻 | 手动设置 |
| 可选个人额度适配 | 本地官方客户端实际返回的个人窗口与时间 | 当前账户、读取时间、实际返回值 |

公共公告不得覆盖手动提醒或个人额度。没有确定下一次事件时，显示“暂无确定的下一次重置”；不能根据以往间隔编造一个循环倒计时。

到达预计时刻，只能说明“预计时间已到”。作者说已经完成时，显示“来源已宣布完成”。只有个人账户适配取得相应实测结果时，才能显示该账户当前额度；不能把前两者当作账户已恢复。

### 2.2 首版功能

| 功能 | 首版行为 |
|---|---|
| 当前时间 | 本地 12/24 小时，默认显示到分钟，秒显示可选 |
| 公告卡片 | 事件类型、范围、预告 / 完成 / 更正 / 待确认、来源链接 |
| 时间换算 | 有明确时刻才精确换算；不明确时展示窗口或原文时间说明 |
| 提醒 | 已批准且符合范围的事件才触发；支持提前提醒、到时、免打扰 |
| 手动时间 | 日期、时间、来源时区或持续时长；与自动公告分别保存 |
| 桌面显示 | 可被普通应用遮挡、不抢焦点、锁定后点击穿透 |
| 托盘 / 菜单栏 | 查看公告、刷新、设置、编辑位置、隐藏、退出 |
| 本地持久化 | 配置、可信事件缓存、通知去重、权益缓存 |
| 运行状态 | 显示来源检查时间；区分无新公告、来源停更和离线 |
| 商业 Beta 后 | 试用、购买 / 恢复授权、两设备、到期与退款 |

先支持一个经过确认的公共来源频道。任意账号自助监控、多账户、团队、多产品、云同步和个性化模型任务不进入首版。

### 2.3 桌面信息结构

紧凑组件优先三行：当前时间；最相关公告状态；明确的本地生效时间或“时间待确认”。详细证据、时区和历史在托盘展开页或设置中查看。

用户可选择自己的套餐以筛选公告。这个选择只用于匹配已知适用范围，不证明账户符合资格。来源范围未知时不能默认全体用户；精确提醒要等范围与时间满足发布规则。

设置只保留“公告与提醒”“桌面显示”“授权与关于”。工程诊断如协议版本、模型、缓存哈希留在主动打开的诊断页。

## 3. 外部数据接入策略：先用现成 HTTP，不为采集重建系统

### 3.1 最简方案的优先顺序

| 优先级 | 数据路径 | 要做的事情 | 何时升级 |
|---|---|---|---|
| A：首选 | 外部提供商直接暴露符合本协议的 HTTPS JSON | 桌面端 GET、校验和显示；成功后无需自建采集、转换或数据库 | 仅当数据没有版本 / 来源 / 时间时 |
| B | 外部提供商有 JSON/RSS/正式 API，但字段不同 | 在**数据生产侧**放一个极薄转换任务，输出本产品 JSON；可定时生成静态文件 | 只有事件语义不清才增加审核 |
| C | 仅有网页或 X 公开内容 | 先验证合法访问与供应方许可，再由独立来源系统处理成结构化事件 | 401/403/验证码不采用 Cookie 池或绕过策略 |
| D：兜底 demo | 没有可靠可用实时源 | 使用明确标注的人工发布 / fixture JSON 测试端到端 | 不以模拟或过期公告声称提供实时服务 |

用户提及“HTTP + Cookie 尝试”：Go 的 net/http 可以在取得授权的情况下发起标准 HTTP 请求，且原生程序不会受浏览器 CORS 限制；这**不等于拥有访问权限，也不意味着需要 Cookie 才能读取公开数据**。对允许会话认证的外部服务，Cookie 可选由其文档明确支持并在**独立、受控的数据提供侧**处理，不能把个人 X 登录 Cookie、浏览器 Cookie 导出或登录绕过作为桌面客户端默认功能。认证材料仅存在密钥存储，不进源码、日志、截图、事件包和多用户客户端。Token / Cookie 过期时提示更新授权，严禁自发绕过 403。

如果既有来源 HTTP 成功、返回的数据真实且符合下述契约，**停止建设额外采集流程**，直接推进桌面功能。若返回的是原始帖子或未判断范围的内容，即使 HTTP 200，也不能直接生成“全体用户已重置”提醒。

X 官方开发者政策约束 API 访问、认证信息、内容再分发、数据使用范围。任何外部提供商也需要核实其是否允许本产品商业消费与必要字段分发。格式转换不自动赋予内容再分发权利。[X Developer Policy](https://docs.x.com/developer-terms/policy)。

### 3.2 最小 HTTP 协议与返回状态

客户端只配置**经过信任审核的 HTTPS 来源**，限制跳转目标、响应大小、超时、JSON 层级和字段长度。不要把服务器端“任意 URL 代理”开放给用户以免 SSRF，付费入口不传递原站 Cookie。

| 返回结果 | 客户端处理 | 记录 |
|---|---|---|
| 200 + 合法 JSON、Schema / 版本 / 时间验证通过 | 原子替换有效快照；如果事件版本没变，不重复提醒 | 本次请求成功、快照验证成功、必要的新版本时间 |
| 304 + 本地已有对应有效快照 | 复用快照并记录条件请求完成，不重新处理事件 | 请求成功；**不能据此推断上游采集器刚刚检查 X** |
| 304 + 没有可用缓存 | 无法直接恢复；允许一次无条件重新获取 | 缓存缺失 / 协议异常 |
| 200 + HTML 登录页、验证码、非预期内容或字段不全 | 判为协议或内容错误，不作为成功数据发布 | 本次 HTTP 200，内容验证失败 |
| 204 / 合法空事件列表 | 仅在上游契约明确定义时视为“没有事件”；未知 204 为协议错误 | 源状态和事件数量 |
| 401 / 403 | 标记未授权 / 拒绝访问，暂停该来源自动重试并通知配置维护者 | 状态码、失败时刻、来源名称 |
| 404 / 410 | 来源失效或已移除；需人工核查 | 最后一次故障 |
| 429 | 遵守 Retry-After 与预算，按上游规则有界重试 | 下次允许请求时间 |
| 5xx、超时、断网 | 有界指数退避；保留标注“旧缓存”的快照 | 最后失败、重试时间 |
| 签名错误、版本回退、异常未来时间 | 拒绝新快照并报警；保留仍有效的先前版本 | 安全 / 格式错误 |

若有 ETag，下一次 GET 携带 If-None-Match；也可以使用 Last-Modified 与 If-Modified-Since，优先正确处理 ETag。304 是**条件缓存验证**而非“采集到新帖子”。若服务端只提供 200，也可计算内容摘要进行本地去重；不要强行增加另一套存储系统。[MDN Conditional Requests](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Conditional_requests)、[304](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Status/304)。

### 3.3 发布契约：一个文件先跑通，后续可拆健康清单

**最小可交付：一个 events.json。**下例仅为设计 fixture，日期与事件均为虚构测试数据：

~~~json
{
  "schema_version": 1,
  "channel_id": "codex-announcements",
  "feed_version": 12,
  "generated_at": "2026-10-11T09:00:00Z",
  "source_health": {
    "status": "ok",
    "last_checked_at": "2026-10-11T08:59:00Z"
  },
  "events": [
    {
      "id": "example-event-01",
      "revision": 1,
      "type": "reset_announcement",
      "state": "active",
      "audience": "known-eligible-plan",
      "effective_at": "2026-10-12T08:00:00Z",
      "verified_at": "2026-10-11T08:58:00Z",
      "source_url": "https://example.org/source-post"
    }
  ]
}
~~~

字段要求：版本可比较，时间含时区（ISO 8601 UTC），事件有稳定 ID、修订、类别、适用范围、是否已撤回、确定时刻或时间窗口、来源与证据核查时间。含混时间和未知范围保留 null / unknown，不凭猜测通知。事件更正须有同 ID 新 revision 或撤销记录，不能删除旧事件后让离线客户端继续按旧计划提醒。外部提供商若不支持这些最小字段，应在生产侧加一次受控转换；不让桌面端尝试解析任意网页。

**可选的静态双文件优化（非 MVP 强制）：**若发布者能主动更新健康心跳，使用 status.json（来源最近检查时间、源状态、事件版本）与 events.json（只有事件变化才重新下载）。客户端按版本决定是否再 GET 事件内容。这样无新公告时仍能证明外部生产者在检查来源，而不需要每次重新下载事件。没有可信上游心跳时，客户端只能报告自己的 HTTP 请求健康，不能假装知道源站已更新。

### 3.4 来源选择与停止规则

第一步先拿到实际可访问 URL，记录内容类型、示例、许可、认证方式、刷新频率与责任方。不得将 X 搜索摘要或不明来源转发当作已核实真源。HTTP 200 及有效 JSON 成立后，进入时间与桌面开发；没有数据时使用 fixture 并把“实时来源”标为 BLOCKED，而不是启动自动爬取设计。网页 403 是访问边界信号，不是必须寻找其他 Cookie 的理由。

## 4. 事件语义与数据契约

### 4.1 先分类，再解释时间

下表是自拟规格示例，不是经本系统核实的当前公告。

| 语义 | 事件类别 | 正确行为 |
|---|---|---|
| 指定某日某时统一重置 | 公共重置预告 | 时间与范围有证据后可设置预计提醒 |
| 今天结束前重置 | 模糊时间预告 | 保留时间窗口；时区未知则待确认，不编造午夜 |
| 发布者称重置已全部生效 | 公共重置完成声明 | 展示作者声明；不证明每个账户余额 |
| 给付费用户一次可自行使用的重置机会 | banked grant | 提醒查看可用机会；是否需领取及如何使用以官方说明为准，不当作当前额度已重置 |
| 恢复某套餐的五小时限制 | 规则变化 | 说明规则，不生成统一重置时刻 |
| 重置一次，同时短期提高倍率 | 多效果公告 | 分开重置与倍率有效期，关联同一公告组 |
| 某人说自己的额度刚恢复 | 个人经历 | 不触发公共重置提醒 |
| 引用旧公告并否认 / 开玩笑 | 非事件或待复核 | 补上下文，不只按关键词发布 |

一个帖子可以产生多个效果，多个帖子也可以更新同一事件。例如预告和完成回复应关联到同一事件组。词语相似不意味着效果相同。

### 4.2 内部字段

下列是拟定内部契约，不是已经发布的 OpenDesk API：

| 字段组 | 规则 |
|---|---|
| source_account_id / post_id / post_url | 稳定来源与原文定位；ID 为字符串 |
| source_version / evidence_post_ids | 编辑链、原帖和相关上下文证据 |
| source_published_at / fetched_at | 分开发帖时间与本次采集时间 |
| event_id / event_group_id / revision | 稳定语义事件、公告组、递增修订 |
| event_type / effects | 重置、赠送、规则、倍率等；一帖多效果可表达 |
| workflow_state | candidate / review_required / approved / rejected，表示内部审核 |
| announcement_state | announced / propagating / author_confirmed，表示来源所述进展 |
| lifecycle_state | active / superseded / withdrawn / expired / unverifiable |
| audience / product_scope | 套餐、区域、条件等；未知保持 unknown |
| effective_at / effective_window | UTC 明确时刻或时间窗口；不能确定时为空 |
| time_expression / time_basis | 原始时间表达、解释依据、时区和歧义 |
| evidence_status / evidence_spans | 关键字段的依据与缺失；不使用模型自评分冒充事实概率 |
| last_poll_success_at | 频道时间线最后成功检查；空结果也可成功，但不能替代旧帖复查 |
| evidence_checked_at | 该事件关键证据最后成功复查；与频道抓取及 feed 重签分别计算 |
| notify_until / revalidate_before | 允许首次通知的截止点、自动行动前需再次核查的截止点 |
| supersedes / tombstone | 更正、替换和撤销关联；使客户端取消旧计划 |
| extractor_version / reviewer / reviewed_at | 可追踪提取器与审核记录；不在公开 feed 暴露个人审核信息 |
| approved_evidence_hash / approved_revision | 批准绑定确切证据与事件版本；关键证据变化使旧批准失效 |

严格区分事件事实、来源声明和系统审核。“审核通过”表示证据满足本产品的发布规则，不表示代替 OpenAI 对每个账户作保证。

### 4.3 时间解释

- 绝对时刻统一存 UTC，额外保留 IANA 时区与解释依据。
- 明确相对时长以原帖发布时间为基准，不以采集时间或用户打开时间为基准。
- “稍后”“今晚”“EOD”“下一小时内”通常只支持范围或未知状态。
- 账号所在地、用户所在地和服务器时区都不能自动补成作者的精确时区。
- 时间缩写如 PST 与相应日期的夏令时用法存在冲突时保留原文并要求确认。
- 预告到期不自动变成已完成；没有后续证据时显示“预计时间已过，等待更新”。
- 不从不定期的活动公告推断正常五小时 / 每周额度重置周期。

## 5. 极简运行架构：取消默认自建采集后端

~~~mermaid
flowchart TD
    A["已有 API / 外部采集任务 / 人工审核发布"] --> F["受信任的 HTTPS JSON Feed"]
    F --> H["Go HTTP 获取与格式校验"]
    H --> C["本地版本缓存与健康状态"]
    C --> R["事件去重、时区换算与提醒"]
    R --> U["macOS / Windows 桌面卡片"]
    P["可选：个人权益服务"] -.-> H
    N["可选：外部轻量格式转换"] -.-> F
~~~

### 5.1 现在不开发哪些东西

**不开发** X 专用采集器、浏览器 Cookie 提取、登录自动化、SQLite 事件仓库、常驻 Go 云后端、消息队列、LLM 采集流水线、后台审核系统或微服务。已有合规数据源能够提供有效事件，只有桌面 HTTP 消费器、少量 JSON 本地缓存、系统提醒需要实现。

外部系统可以采用任何语言、部署方式或已有工作流，按照协议生成 JSON。生产侧必须负责原始信息真实性、来源核验、编辑撤销和真实内容授权；桌面客户端不承担这类无法从远程数据推断的保证。

### 5.2 升级决策树

1. **能直接取得合规的事件 JSON？** 是：直接用它，跳过转换与数据库。
2. **仅字段命名 / 包装不同？** 用外部几十行级别适配逻辑或静态文件构建任务；仍不建采集框架。
3. **有原始文本，但没有事件类别、范围与时间？** 在生产侧加有限的解析 / 人工核实；先样本评估后决定是否需要模型。
4. **外部只返回拒绝访问或不稳定 HTML？** 停止该来源，查许可或换授权的数据提供方；不绕过封锁。
5. **只有在需要付费服务访问控制、可靠服务监控或多来源聚合时**，才引入小型权益 API、CDN 鉴权或最小事件持久化；独立于桌面时钟功能验收。

首版不需要把源 URL、Cookie 或付费密钥嵌进每台客户端；公开 feed 可直接 GET，私有 feed 使用其自身发行的合法短期凭据。凭据认证影响的是数据访问，不应阻塞本地时钟与手动提醒。

### 5.3 轮询策略与成本

默认客户端每 5 分钟检查一次，休眠或无新事件时可放宽到 15 分钟；启动、网络恢复、手动刷新可以触发一次，但合并并发请求。实际间隔由外部提供方的上限、缓存和用户期望确定，不盲目高频请求。

1000 台全天运行的设备，5 分钟一次在 30 天约有 864 万次 HTTP 检查；15 分钟一次约 288 万次。条件请求可能减少字节数，但请求和鉴权仍可能计费。如果上游提供可信 status.json 心跳与事件版本，优先拉取很小的状态清单，版本改变时才获取完整事件。

不为“实时”二字默认上 WebSocket / SSE，也不要求服务器持续连接。端到端时延约为外部提供方更新时间 + HTTP 检查间隔 + 事件审核 / 处理延迟；没有实际来源 SLA 时，不承诺秒级通知。

### 5.4 数据与可信度边界

HTTP 传输与签名 / 校验只能证明响应可用、来源身份与版本一致，不能单独证明 X 公告事实。可信提供方已有审核与版本控制时可以复用其事实责任，不在本产品再做一套重复审核流程；若没有可靠证据、范围或核查时间，自动通知需保持关闭或由用户手工设定。

商业接入时如使用共享静态 feed，只有公共数据可共享缓存；付费 / 个人令牌数据不能混入公共 CDN 缓存。未来需要付费 feed 权益时由适当的鉴权边界实施，不能靠客户端隐藏 URL 或本地布尔值保护。

## 6. 桌面客户端与 Go 边界

### 6.1 业务逻辑

Go 管理 feed 校验、事件筛选、时间换算、调度、去重、配置和权益。UI 只消费显示模型。

Go 的 time / tzdata 提供时区转换所需能力。入口包含时区数据兜底；当地时间的重复或不存在要显式处理，不能只相信一次日期构造就已经消除歧义。[来源：Go time](https://pkg.go.dev/time)、[Go time/tzdata](https://pkg.go.dev/time/tzdata)

- 时差按事件日期算，不固定写死两个城市相差几小时。
- 每次刷新按绝对目标减当前时间重算，避免计数器累计漂移。
- 休眠、改时、时区切换、网络恢复时重算并刷新适用状态。
- 自动通知共同要求 workflow_state=approved、lifecycle_state=active、范围符合、feed 与关键证据未失效。unverifiable / withdrawn / superseded / expired 的旧计划取消。
- 精确到时 / 提前提醒还必须有确定的 effective_at。仅有完成声明或赠送机会时，可按经核实的公告时间发消息通知，不虚构到账时刻或未来倒计时。
- 通知按语义事件及提醒种类去重；只修改描述的 revision 不再次弹窗。
- 改期 / 撤回时原子替换本地计划，任务执行时再次检查当前有效版本。
- 休眠补偿受 notify_until 限制，只补仍有意义的一条，不回放一天的消息。
- 通知提交成功不代表用户实际看见；权限、免打扰与无可靠回执分别表达。
- 应用常驻是首版提醒前提；退出或关机不承诺后台继续提醒。

### 6.2 桌面背景验收定义

“显示在系统桌面背景中”以行为定义：普通应用在上；显示桌面时可见；不抢焦点；锁定时图标可点击；从托盘进入编辑后可拖动；断开屏幕后位置可恢复。

macOS 优先用公开原生窗口接口验证层级、点击穿透、Spaces / Stage Manager 与全屏行为。Windows 单独验证 Win+D、Explorer 重启、虚拟桌面、缩放与多屏。

Windows IDesktopWallpaper 提供壁纸相关能力；它不是任意实时组件的通用嵌入接口。将自有窗口挂到 WorkerW / Progman 的实现依赖 Shell 结构，SetParent 的公开性不等于该组合有稳定承诺，并有 DPI 兼容风险。[来源：IDesktopWallpaper](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nn-shobjidl_core-idesktopwallpaper)、[SetParent](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setparent)

透明卡片优先原生绘制；设置页可用 Wails。Wails 关于 macOS 透明 WebView 的文档提示涉及 private_mac_apis，因此不能仅凭 CSS 透明就认定原生桌面效果可行。GUI 框架与版本经过技术验证后再固定。[来源：Wails Private macOS APIs](https://v3.wails.io/guides/build/private-macos-apis/)

Wails 设置页与自建原生窗口必须归属同一个明确的主线程 / 原生事件循环，由统一生命周期管理。不能并行启动两套 AppKit 主循环，或从任意 goroutine 更新原生窗口；技术验证时确定与所选框架的集成方式。

某平台无法达到上述行为时记录 BLOCKED 并调整产品范围，不能以置顶浮窗替代“桌面模式已通过”。

### 6.3 资源与能耗预算

以下是待测目标，不是已有成绩：

- 默认到分钟显示，按内容变化重绘，不持续运行 60 FPS 动画。
- 常驻 Go 核心、托盘、原生卡片空闲平均 CPU 目标低于单核 0.5%，至少观察 5 分钟。
- 常驻内存先按 100 MB 评估；设置 WebView 等所有子进程单列并报告总占用。
- 唤醒 / 屏幕变化后目标 2 秒内恢复本地正确显示，网络新内容另计。
- 连续 24 小时无明显内存增长、重复通知或持续失败重试。
- 记录进程唤醒、请求量、缓存命中和模型调用，检查集中处理是否真实降低总资源消耗。

CPU / 请求量可以验证效率；没有相应测量不能宣称通过正式能耗或环保认证。

### 6.4 个人额度作为后续独立适配

官方 Codex App Server 提供额度读取及相关更新能力，可用于未来的可选个人功能；实际支持取决于客户端版本、账户模式和返回字段。[来源：Codex App Server](https://learn.chatgpt.com/docs/app-server)

该功能在本机读取，OpenAI 凭证、会话和代码不上传到本产品服务器。不得把公共公告替代成个人账户数据，也不硬编码所有账户都有相同窗口。它不进入集中公告 MVP 的关键路径，当前不扩大 OpenDesk Browser RPC 白名单。

## 7. 请求健康与数据新鲜度：必须可观察、可诊断

用户要求显示“上一次请求查看时间”，并在间隔过长时帮助发现问题。为避免误报，严格分开**请求健康**、**上游检查健康**、**事件内容变化**三个概念。

### 7.1 最少保留的时间字段

| 字段 | 含义 | 从哪里得到 |
|---|---|---|
| last_attempt_at | 最近一次客户端 HTTP 尝试 | 本机开始请求时 |
| last_http_success_at | 最近一次 HTTP 200 / 合法 304 响应 | 本机接收到响应时；与内容验证成功分别记录 |
| last_valid_feed_at | 最近一次接受合法 JSON / 对已有合法缓存完成条件验证 | 客户端协议验证结果 |
| last_source_checked_at | **外部提供方最后成功检查目标来源的时间** | 只有生产者明确提供可信心跳才显示 |
| last_event_changed_at | 事件内容 / 版本最后变化时刻 | 发布方明确版本 / 事件信息；不可用则未知 |
| last_evidence_verified_at | 驱动自动提醒的关键证据最近核实时间 | 可选，生产者给出的事件级字段 |
| last_client_sync_at | 客户端最近一次接受有效版本的时间 | 本机确认快照 / 304 时 |
| last_failure_at / last_error | 最近失败时间、类别与必要错误码 | HTTP / Schema / 信任校验 |
| next_retry_at | 下一次预定请求时间 | 本地退避、预算和配置计算 |

**请求返回 200 ≠ 数据有效；返回 304 ≠ 目标账号最近被检查；事件三天没更新 ≠ 采集失败。**日期全存带时区的绝对时间，界面转换为本地时间，并可显示“几分钟前”。

若外部方不暴露 last_source_checked_at，显示“上游检查状态未知”，不使用客户端 last_http_success_at 代替。若 feed_version 不变且其状态没有变化，不能重新写出更近的事件更新时间。

### 7.2 UI 展示（例子为演示数据）

~~~text
公告频道：正常
上次请求：今天 19:45（7 分钟前）
上游最近检查：今天 19:44（8 分钟前）
上次发现新公告：10 月 7 日 11:30
下次计划检查：19:55
~~~

如果用户点击详情，可显示最近请求状态、HTTP 响应码、上次验证、证据核查时刻、缓存版本与最近错误；默认桌面卡片只显示“正常 / 连接异常 / 数据可能过时 / 上游状态未知”等短状态，保持简洁。

### 7.3 建议阈值（对应默认 5 分钟刷新）

| 状态 | 判断（初始可配置） | 展示 / 行为 |
|---|---|---|
| 正常 | 最近有效客户端请求在预期范围，且上游心跳在约定范围 | “已检查，无新公告”也属于正常 |
| 延迟 | 超过 15 分钟没有有效检查，或上游心跳落后约定周期 | “更新延迟，显示上次数据” |
| 过期 | 超过 30 分钟未证实有效上游检查 / 关键证据失效 | 旧公告可查看，但**停止由过期公告触发新的自动通知** |
| 严重异常 | 超过 60 分钟，或显式认证失败、签名错误 | 托盘状态提示和有限一次系统异常通知；不持续弹窗 |
| 状态未知 | 来源没有可信心跳，或只有客户端能验证的数据 | 只报告“本机获取成功”，不能保证外部生产者仍在采集 |

15 / 30 / 60 分钟是默认刷新五分钟情景的设计建议，正式版应跟随来源 SLA、轮询间隔及事件有效期校准；不因没有新内容而触发健康告警。每个自动提醒还应检查事件级有效期和证据状态，健康的频道也可能包含失效事件。

### 7.4 失败时最小处理

- 认证拒绝：停止来源请求、显示问题与最近成功时间，不自动改换 Cookie 或重试绕过。
- 短期失败：保留上一个有效快照并标注缓存年龄，采用有限退避；旧数据不得显示成刚更新。
- 部分 / 错误数据：不覆盖有效缓存，不发布事件，不把解析失败当作“没有新公告”。
- 休眠恢复 / 网络恢复：立即重算本地倒计时，最多合并一次数据刷新；不补发过期的通知。
- Feed 新版本撤销事件：取消旧提醒，不依赖本地仅凭时刻过期清理。
- 纯客户端仅持久保存最小缓存、时间戳、错误摘要和去重 ID；不创建请求日志数据库。可选保留最近 10 条简短诊断，循环覆盖，避免无限增长。
- 错误告警按“进入异常状态”去重；恢复时清除，反复断网期间不重复弹窗。

如未来由外部提供方承担采集，数据源自身的停更 / 许可到期 / 账号变更须由该方监测或提供心跳。当前客户端能检测的只是其所公开的状态，不能替代提供方的运行运维。

## 8. 商业与复杂度：价格应按实际数据提供方式重算

### 8.1 先验证数据源成本，不先建收费后台

原文中按 X Post 数、自己运行 Go 采集器、人工审批所有帖子计算的固定开销**是“自建来源”条件预算，不再是当前默认方案**。更换为外部提供方后，成本主体变为：

~~~text
每月总成本 =
  外部数据提供费 / 使用许可
  + 必要的外部格式转换 / 人工抽检
  + HTTPS / CDN / 域名及实际请求
  + 桌面签名与更新月摊
  + 维护与客服工时
  + 支付手续费、退款及试用支持
~~~

重要区分：外部数据免费提供 ≠ 数据长期免费或许可支持商业再分发。Cookie 成功登录 ≠ 数据可以被商业使用。**首次验证应先确认合法稳定的提供方、数据结构、更新 SLA、授权费用和中断后的维护责任**，再决定需不需要自己的服务器。

### 8.2 价格建议维持“假设”，而不是先涨价

用户的 0.99 币种尚未确认。以下假设 USD：

| 选项 | 优点 | 缺点 / 条件 |
|---|---|---|
| US$0.99 / 实际月扣 | 用户感知门槛低 | 小额固定支付费、自动续费和客服占比高 |
| **US$11.88 / 年，一次支付** | 月均 US$0.99，降低交易次数；适合长期公告服务 | 必须明确一次扣一年，不可只写 0.99/月 |
| 免费公开静态 feed + 付费桌面增强体验 | 容易先验证价值，数据源成本可观测 | 付费点必须是确实有用的提醒、桌面体验或持续维护 |

推荐：技术 demo 免费，首次可用 feed 后 30 天免绑卡完整试用；实际支付规则等币种和供应方确定。首个版本优先考虑年度一次性服务授权，不默认自动续费；到期保留时钟、手动提醒和本地配置。

如果没有持续有用的公告、数据许可无法确认或数据源不稳定，不能凭“服务器每月很便宜”直接上线付费。

### 8.3 变动费用与粗略保本

仅用于对比的美元假设：年度 US$11.88 一次性支付，Stripe 美国境内标准卡基础支付费 2.9% + US$0.30 / 笔；每付费用户每月另预留 US$0.15 分发、客服和退款。年付月均贡献约 **US$0.78629**。若实际月度订阅采用基本支付费外再计 0.7% Billing，月均贡献约 **US$0.50436**。此处未逐笔分币舍入，且费率只为举例，真实地区、渠道和产品应重新验证。[Stripe Pricing](https://stripe.com/pricing)、[Billing Pricing](https://stripe.com/billing/pricing)。

| 月固定成本预算（含外部源与既定人工） | 年付保本用户数（估算） | 月扣保本用户数（估算） |
|---|---:|---:|
| US$40 | 51 | 80 |
| US$130 | 166 | 258 |
| US$370 | 471 | 734 |

公式：向上取整（月固定费用 / 人均月贡献）。这些只是用假设参数计算的运行保本下界，不含首发研发、获客、税、商业利润，也未保证 US$0.15 的客服预算足够。外部数据方的实际报价、全部试用 / 活跃设备负载和真实人工工作量决定经营是否成立。

### 8.4 在什么条件下停止扩展

在稳定 HTTPS feed 和两平台客户端跑通之前，不建设许可证服务器、CDN 边缘鉴权、团队计费或 X 专用采集器。付费服务需要权限验证时，优先选择现成支付与可用的权益 / 边缘能力。不要把“本地试用到期”与“外部数据源失效”混在一起；本地授权宽限不延长远端数据源访问凭证。

Beta 至少记录 30 天：上游中断次数、信息有用事件数、自动提醒纠错、外部数据费、实际请求账单、用户支持工时、付费意愿和无新公告期的持续使用。之后才能确定 0.99 价格是否可持续。

## 9. 仓库结构和文档驱动约束

唯一方案保存在 docs/plans/desktop-reset-clock.md；现有 demo 文档入口为 examples/desktop-reset-clock/README.md；评审与质量门槛保存在 docs/quality/desktop-reset-clock/design-review.md。本轮只修订文档，**不创建源码、第三方采集程序或 Go module**。

| internal/entitlement/ | 未来授权；demo 使用模拟状态 |

| frontend/、build/ | 如确需 Wails 设置窗口、可维护的构建资源 |

**不预建** cmd/reset-clock-server、internal/source、internal/extraction、internal/review 等采集后端目录。只有外部提供方不能给出符合要求的事件数据、且需求审批确认时，才在独立生产侧做必要的 adapter；不与桌面时钟打包发布。

遵守已有 OpenDesk AGENTS.md：新增稳定源码与正式文档进入版本库，日志 / 测试结果放仓库根 .runtime/tests/desktop-reset-clock/；Go 内部逻辑用同包 _test.go，嵌套 module 设独立 CI 入口；正式桌面验收真实截图、加载来源、行为测试分开记录。已存在的 App Shell 原生生命周期可参考，不把整套 RobotGo / Goja 运行时带入此 demo。Browser RPC 白名单不因为一个时钟被扩张。

每个实施 Goal 按 **需求 ID → 示例 JSON / HTTP fixture → 明确接受标准 → 实现 → 单测 → 真 HTTP / 真机证据 → 修正文档** 顺序推进。未经用户确认，不把可选采集升级变成默认里程碑。

## 10. 逐阶段推进：直连成功便停止采集扩展

| 阶段 | 工作 | 成功门槛与结束条件 |
|---|---|---|
| 0：来源明确 | 确认实际 feed URL / 提供方、准入许可、格式、预期更新周期、Cookie 是否合法必要 | 有来源契约或明确进入 fixture-only demo |
| 1：**HTTP 技术验证** | 用受控配置测试 GET 的 200 JSON / 304 / 401 / 403 / 429 / 错误正文；记录真实响应和更新时间字段 | **200+内容验证通过或有合法 304 缓存，即停止采集研究，直接做客户端**；失败只报告缺口 |
| 2：数据契约与时间健康 | 建立最小 events.json fixture、ETag、本地快照、三种新鲜度时钟、异常阈值和更正规则 | 测试无新内容 ≠ 故障，stale 时禁止误通知 |
| 3：双平台最小 demo | Go HTTP 客户端、时区 / 提醒与桌面卡片、托盘、设置 | Mac / Windows 真实运行，按约定显示检查时间 |
| 4：**按需**外部适配 | 仅当来源不能给出事件 JSON，使用现有合法服务转成标准 feed | 转换在生产侧，客户端不依赖来源平台细节 |
| 5：观察 Beta | 真实来源、间隔超时、断网、编辑、费用及用户反馈，至少 30 天账单与运维记录 | 来源稳定和用户价值有证据 |
| 6：商业 / 发行 | 试用、实际价格、现成支付与权益、签名安装包 | 法规与数据许可、支付退款、两平台安装验收通过 |

第 1 阶段应先于完整采集系统；阶段 2 / 3 可在只用 fixture 时推进，但不能把模拟数据称为真实服务验收。第 4 阶段完全可跳过。对明确拒绝访问的目标，不采用循环换 Cookie / 账号的方式绕过。

最小实践验证包括：合法 JSON 200；连续 304；200 但登录 HTML；初次 304 无缓存；401/403 授权失败；5xx/超时；来源心跳不变；事件久未更新但源仍正常；新修订取消旧通知；恢复网络后不重复弹窗。

时间与来源健康的真实性是阶段验收的 P0 条件。若来源方不能确认真实检查时间，产品只承诺自己的请求状态，不承诺“目标平台最新”；价格与时效承诺随之收敛。

## 11. 95 分质量目标、必要场景与硬门槛

评分不是凭文档长度。设计审查和运行验收各自满分 100；目标不低于 95，且任何 P0 硬门槛不能被其他项目分数抵消。详细见 [交叉评审](../quality/desktop-reset-clock/design-review.md)。

| ID | 必须验证 |
|---|---|
| HTTP-001 | 成功 HTTPS + 200 合法 JSON 后不触发另建采集器 |
| HTTP-002 | ETag / 304 用对应缓存；无缓存的 304 被正确识别 |
| HTTP-003 | 200 HTML 登录页、401 / 403、429、5xx、超时不当作有效内容 |
| HTTP-004 | 不自动读取浏览器 Cookie；凭据不进入客户端包、日志和公开 feed |
| FEED-001 | 事件稳定 ID、版本、来源、范围、撤回和时间字段正确处理 |
| FRESH-001 | last_attempt、last_http_success、last_source_checked、last_event_changed 分开记录与显示 |
| FRESH-002 | 源检查成功但内容不变不会误报陈旧；304 不伪造上游心跳 |
| FRESH-003 | 长时间失败显示最后有效时间、错误和下次重试；过期自动提醒暂停 |
| EVT-001 | reset、可自行使用的重置机会、规则变化、倍率分开解释 |
| EVT-002 | 模糊时间 / 未知范围不触发精确自动通知 |
| EVT-003 | 修改 / 撤回取消旧提醒，重启 / 休眠恢复去重 |
| TIM-001 | UTC、跨日、夏令时缺失与重复正确处理 |
| GUI-001 | Mac / Windows 真桌面、不抢焦点、不遮挡图标、断屏恢复 |
| PERF-001 | 24 小时进程、流量、资源实际记录 |
| PAY-001 | 免费期、实际付费金额与周期、退款和恢复真实一致 |
| REL-001 | 签名安装、更新卸载与用户可复制启动方式实测 |

**硬门槛**：可信及获准的数据源；数据内容验证与事件语义；来源状态不过时或明确告知未知；无旧公告误通知；两平台真机桌面验收；商业前完成数据使用与付费生命周期审核。

本轮所有代码 / HTTP 联调 / 真机与支付运行验收为 NOT_TESTED，不能写成已通过 95 分；只将本方案视作待确认的设计候选。

## 12. 当前交付与下一步

本轮仅把“默认自己采集 X → Go 服务 + SQLite + 审核 + CDN”调整为**外部生产者提供合法结构化数据；Go 桌面应用优先用标准 HTTPS/JSON 消费；状态和检查时间独立观察**。X 专用采集、自动登录、Cookie 池、云端数据库与支付服务均不再是 Demo 必需功能。

现有仓库的 Go App Shell 可提供设计参考，Mac / Windows 原生背景行为仍需真实验证。数据接入的正确性取决于真实 URL / 合规许可及数据格式，不取决于仅 HTTP 返回 200。

下一次源码阶段应优先获取一个可验证的 feed 地址或测试 fixture；单独确认 0.99 币种、试用规则与付费路径。设计文档审核不代表运行测试、外部真人专家签字或正式能源 / 环保认证。本轮没有写入 Go 代码或启动抓取。
