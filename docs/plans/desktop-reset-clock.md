## 1. 一句话方案

**外部可信数据提供方 → HTTPS JSON → Go 桌面应用 → 本地时间换算与提醒。**

- **解决的需求**
  - 桌面显示本地时间、Codex 公告、下一次有证据的事件时间和剩余倒计时。
  - 根据用户时区换算公告日期；到时或提前发送系统提醒。
  - 告诉用户**上一次成功请求、上游最近检查、公告最近变化**分别是什么时候。
- **做法**
  - 优先读取其他系统已经提供的 HTTP/HTTPS 数据，不在本项目默认采集 X。
  - 只处理**有效、来源明确、范围与时间可信**的事件；不从任意帖子编造下一次重置。
  - 网络异常时保持桌面时钟、手动提醒可用，自动公告显示缓存年龄与故障。
- **第一版明确不做**
  - 不搭建 X 专用爬虫、Cookie 池、云端 Go 采集服务、SQLite 事件库、模型抽取流水线或云任务平台。
  - 不把 X 公开公告当作用户**个人额度已经恢复**的证明。
  - 不先开发订阅、许可证服务器和多账号团队系统。
- **仅在有证据时升级**
  - 外部源已有有效 JSON → **直接消费，停止扩展采集方向**。
  - 外部源只有其他数据格式 → 在**数据提供侧**做最薄的转换，不让桌面端解析任意 X HTML。
  - 外部源拒绝访问或没有商业使用许可 → 说明问题，使用模拟事件进行客户端验证；不绕过访问控制。

## 2. 完整功能树

以下按产品功能组织。**MVP** 是首版必须完成的范围；**可选** 只有出现实际缺口才启动；**商用阶段** 不进入最初 Demo。

- **A. 外部数据输入（MVP）**
  - **F01｜数据源**：选择一个可信的 HTTPS 事件源；采集工作完全外置。
  - **F02｜HTTP 请求**：GET、条件缓存、访问拒绝、重试与网络失败处理。
  - **F03｜事件协议**：统一公告类别、来源、时间、范围、版本和撤回。
- **B. 时间与提醒（MVP）**
  - **F04｜当前时间**：本地时钟、12/24 小时、日期及可选秒显示。
  - **F05｜时区换算**：UTC、跨日、夏令时、模糊时间解释。
  - **F06｜提醒引擎**：提前通知、到时通知、去重、休眠恢复、撤销。
- **C. 运行状态与本地缓存（MVP）**
  - **F07｜检查时间**：分别展示请求、有效数据、上游检查和事件变化时间。
  - **F08｜异常诊断**：区分无新公告、断网、来源停更、无权限和未知。
  - **F09｜本地缓存**：保留有效快照、条件请求标识、配置和提醒去重状态。
- **D. macOS / Windows 桌面（MVP）**
  - **F10｜桌面卡片**：显示时间与重要事件；不抢焦点，锁定后点击穿透。
  - **F11｜托盘与设置**：刷新、显示/隐藏、编辑位置、免打扰、数据详情。
- **E. 按需功能（不阻塞 MVP）**
  - **F12｜外部适配器（可选）**：已有源不能输出事件 JSON 时才在生产侧转换。
  - **F13｜个人 Codex 额度（可选）**：在本机读取官方支持的数据，独立于公共公告。
  - **F14｜试用与付费（商用阶段）**：免费试用、年付或月付、权益与设备管理。
- **F. 工程质量（分阶段执行）**
  - **F15｜测试与证据**：HTTP 反例、时间逻辑、桌面真机、运行成本。
  - **F16｜安装与更新（发行阶段）**：macOS 签名公证、Windows 签名、更新卸载。

## 3. 每个功能的解决方案

所有功能采用同一写法：**用户效果 → 技术实现 → 异常处理 → 验收方式**。这样开发者或 Codex 可以按功能 ID 实现，不必全文寻找隐含要求。

### A. 外部数据输入

- **F01｜选择数据源（MVP）**
  - **效果**：用户获得一条可解释来源的公告频道，而不是自动登录 X。
  - **实现**：优先使用已经合法提供 `events.json` 的 HTTPS 地址；真实提供方须明确负责人、字段、刷新周期、使用许可和撤回机制。
  - **异常**：没有真实数据源时保留手动提醒与合成 JSON 测试，不声称实时同步。此前提及的 tibo 候选账号尚未获确认。
  - **验收**：记录 URL、授权方式、样本响应、最近更新字段与内容使用范围。成功后**不新增采集器**。

- **F02｜HTTP 获取（MVP）**
  - **效果**：无新内容时低成本检查；请求失败仍能看到最近有效快照。
  - **实现**：Go `net/http` + HTTPS GET；在支持时保存 `ETag`，后续使用 `If-None-Match`；启动和网络恢复合并一次请求；默认约 5 分钟检查，空闲可延长至 15 分钟，最终服从数据源约束。
  - **异常**：
    - `200` 且 JSON、版本、时间、大小与字段通过验证 → 接受；`200` 但返回 HTML 登录页或无效 JSON → **失败**。
    - `304` 且存在与同一 URL/身份对应的有效缓存 → 沿用；**没有缓存** → 允许一次无条件重取。
    - `401/403` → 标记权限问题并暂停该源自动重试；`429` → 遵守 `Retry-After`；超时/`5xx` → 有界退避，不无限循环。
  - **安全**：限制最大响应体、跳转目标和请求时间；不记录凭据。合法 API Key / Token 优先；Cookie 仅限提供方明确允许的认证用途，不导出浏览器 X 登录 Cookie，也不用于绕过 403。
  - **验收**：测试 200 有效/无效、304 有/无缓存、401、403、429、超时和签名/版本异常。

- **F03｜统一事件协议（MVP）**
  - **效果**：更换数据提供方，不必修改客户端的倒计时和提醒逻辑。
  - **实现**：第一版用**一个完整快照 `events.json`**，包含频道与版本、生成时间、可选来源健康、事件列表。每个事件保留稳定 ID、修订、类型、适用范围、明确时间或窗口、证据时间和原始链接。
  - **语义**：区分“统一重置预告”“已完成声明”“赠送可自行使用的重置机会”“规则变更”“倍率活动”；一条公告可有多个效果。
  - **异常**：时间/范围未知 → 展示待确认，不创建确定时刻的自动通知；事件改期/撤回 → 必须通知客户端取消旧计划。完整快照移除旧事件时应有明确的撤回语义，不能让离线设备继续执行。
  - **验收**：版本递增、旧版本拒绝、空列表、未知字段、改期、撤回和多效果事件均可复现。

### B. 时间与提醒

- **F04｜当前时间（MVP）**
  - **效果**：默认显示系统本地日期与时间，支持 12/24 小时制，秒显示可选。
  - **实现**：Go 时间服务驱动；按内容变化重绘，不使用持续 60 FPS 绘制。
  - **异常**：时区改变、夏令时切换、系统休眠唤醒后重新计算。
  - **验收**：与系统时间一致；后台运行与恢复后无累积漂移。

- **F05｜时差与公告时间（MVP）**
  - **效果**：看到公告原时间、本地时间、跨日日期和倒计时。
  - **实现**：存 UTC 绝对时刻；使用 IANA 时区名称与 Go `time` / `time/tzdata`；相对时间以来源发布时间为基准。
  - **异常**：夏令时导致不存在或重复的当地时间时明确处理；“今晚 / 稍后 / EOD”与未知时区保留模糊状态，**不猜某个午夜**。
  - **验收**：跨日、夏令时重复/缺失、夏令时调整、时区切换均有固定用例。

- **F06｜提醒引擎（MVP）**
  - **效果**：只对**适用用户且时间明确、证据未失效**的公告在设定时刻提醒；用户还可创建手动提醒。
  - **实现**：提醒由事件 ID + 类型 + 生效时刻 + 提前量标识，持久保存已发状态；本地时间重算，不做“每秒减一”的持久累计。
  - **异常**：改期取消旧任务；休眠后只补仍有意义的一条；来源失效、已撤回或未知范围时停用新的自动公告通知；通知 API 请求成功不等于用户一定看到。
  - **验收**：重复更新不二次弹窗、撤回不响、唤醒后不连发、免打扰与通知权限拒绝有清楚状态。

### C. 状态与缓存

- **F07｜“上次检查时间”与新鲜度（MVP）**
  - **效果**：用户能判断应用是不是正常更新，知道多久未检查，而不会误把“几天没新帖”当成故障。
  - **实现**：分别记录：
    - `last_attempt_at`：最近一次客户端发起请求。
    - `last_http_success_at`：最近一次成功收到 HTTP 响应。
    - `last_valid_feed_at`：最近一次确认当前 feed/缓存有效。
    - `last_source_checked_at`：**上游提供方明确声明**最近检查目标来源的时间。
    - `last_event_changed_at`：公告内容最后变化时间。
    - `last_failure_at` / `next_retry_at`：最近故障、下一次检查。
  - **异常**：仅有客户端 200/304 不能更新 `last_source_checked_at`；上游没有心跳字段则显示“上游状态未知”；事件未变化却上游检查正常时显示“已检查，无新公告”。
  - **验收**：304、空列表、长时间无公告、上游停止更新分别产生正确状态。

- **F08｜异常提示（MVP）**
  - **效果**：桌面显示简短状态，详情页能查看故障原因和时间。
  - **实现**：在上游约定 5 分钟刷新时，建议超过约 15 分钟提醒更新延迟、30 分钟标记来源可能过期并暂停过期事件的新自动提醒、60 分钟提示严重异常。**阈值随提供方 SLA 调整，当前不是固定产品承诺**。
  - **异常**：没有上游核查心跳，不假称“正常实时”；401/403 可立即显示权限故障；诊断通知只在状态切换时触发，避免反复弹出。
  - **验收**：测试正常/延迟/过期/未知/权限拒绝及恢复，日志不包含 Cookie、Token 或个人账户内容。

- **F09｜最小本地缓存（MVP）**
  - **效果**：离线时仍显示最后已验证的公告、对应时间和缓存年龄。
  - **实现**：将配置、最后有效 feed、URL/身份对应的 ETag、去重标识和最近健康状态写入用户配置目录；原子更新，只有变化时落盘。
  - **异常**：缓存损坏或来源身份变化不得误用于 304；旧数据必须标注时间，证据过期后不继续发送新自动公告提醒。
  - **验收**：断网、重启、损坏缓存和变更数据源均能恢复或清楚降级；MVP **不需要 SQLite**。

### D. 桌面与设置

- **F10｜桌面背景卡片（MVP）**
  - **效果**：桌面可见，普通应用窗口可遮挡；卡片不抢键盘焦点，锁定状态不妨碍桌面图标点击。
  - **实现**：Go 核心 + macOS 原生 AppKit / Windows 原生窗口适配；透明时钟卡片优先原生绘制，不每秒修改系统壁纸。
  - **异常**：Explorer 重启、Spaces、虚拟桌面、多显示器断开和 DPI 缩放需要实测；不能用置顶浮窗替代真实桌面行为。设置窗口如使用 Wails，原生 UI 生命周期必须统一管理。
  - **验收**：macOS 与 Windows 分别在真机验证焦点、图标点击、多屏、显示桌面、位置恢复及 24 小时资源消耗。

- **F11｜托盘和设置（MVP）**
  - **效果**：快速查看下一次有证据的公告、最近请求时间，完成刷新、隐藏、编辑位置、免打扰、退出操作。
  - **实现**：界面分成三个简短区域：“公告与提醒”“桌面显示”“来源状态”；未来上线收费时再加入“授权与关于”。
  - **异常**：退出应用后不承诺继续即时提醒；关闭设置窗口不等于退出；点击刷新合并请求并受来源频率限制。
  - **验收**：所有入口真的能操作，UI 不展示重复技术字段，禁用状态说明清楚。

### E. 可选或商用阶段

- **F12｜外部格式转换器（可选）**
  - **触发**：合法的数据提供方只有 RSS / 其他 JSON，不能直接给出 F03 事件协议。
  - **方案**：在外部数据生产侧用现有工具转换成静态 `events.json`；不在本桌面项目新建爬虫和常驻后台。
  - **退出条件**：能够按 F03 规则输出有效、可更正的事件后结束，不继续扩展提取管线。

- **F13｜个人 Codex 额度（可选）**
  - **触发**：用户确实需要**个人账户**额度窗口，而不是仅看公开公告。
  - **方案**：单独使用本地官方 Codex App Server 支持的额度读取方法；不向本产品服务器上传 OpenAI 凭据。
  - **边界**：个人窗口不能与公共事件时间混写；不硬编码五小时等周期；无可用官方返回就显示未知。

- **F14｜试用与收费（商用阶段）**
  - **触发**：经过真实数据、双平台和成本 Beta 后，确认持续付费价值。
  - **方案**：30 天首次完整免费、无需绑卡；价格目标 0.99/月，但**币种尚未确认**。如采用美元，优先比较一次性 US$11.88/年与实际 US$0.99/月，明确展示实际扣款金额和周期；先复用现成托管支付/权益能力。
  - **边界**：前期不默认建立授权服务器；正式付费时需完成恢复、退款、两设备、离线与数据访问权限的端到端测试。
  - **验收**：收费、授权有效期和页面说明一致；不可把本产品收费描述为包含 Codex 额度。

### F. 工程和发行

- **F15｜自动化测试与质量证据（每阶段）**
  - **实现**：用固定 JSON fixture、模拟 HTTP 状态及可控 Go 时钟测试；真源 HTTP、真实 UI 与支付分别留证据，不相互替代。
  - **验收**：覆盖 F01–F11 所属的成功、失败和恢复路径；每个结论标记 VERIFIED / NOT_TESTED / BLOCKED。
- **F16｜安装与更新（发行阶段）**
  - **实现**：macOS 签名、公证和可下载安装包；Windows 相应签名包及安装、更新、卸载流程。对具体 GUI 框架的依赖、签名和架构先验证再定。
  - **验收**：从下载的实际安装包检查首次运行、自动启动、退出、升级和卸载；不能用 Go 跨编译替代真机验收。

## 4. 最小数据格式和用户看到的状态

### 4.1 事件 JSON（设计示例，不是真实公告）

```json
{
  "schema_version": 1,
  "channel_id": "codex-public-announcements",
  "feed_version": 3,
  "generated_at": "2026-10-11T09:00:00Z",
  "source_health": {
    "status": "ok",
    "last_checked_at": "2026-10-11T08:59:00Z"
  },
  "events": [
    {
      "id": "demo-event-001",
      "revision": 1,
      "type": "reset_announcement",
      "state": "active",
      "audience": "known-eligible-plan",
      "effective_at": "2026-10-12T08:00:00Z",
      "verified_at": "2026-10-11T08:58:00Z",
      "source_url": "https://example.org/announcement"
    }
  ]
}
```

- **协议定义**
  - `schema_version`：客户端可理解的协议版本；不支持的版本拒绝。
  - `feed_version`：同一频道单调递增；不允许旧版本覆盖新数据。
  - `generated_at`：外部提供方生成 feed 的时间，不等于目标网站最后检查时间。
  - `source_health.last_checked_at`：外部提供者**确实有能力证明**的检查时间；没有时使用 `null` / 未知。
  - `events[].id` + `revision`：用于相同公告的修订关联和旧通知取消。
  - `type`：预告 / 完成声明 / 赠送机会 / 规则变更 / 倍率等实际类别。
  - `audience`、`effective_at`：适用范围或时间未知时，保持 `unknown` / `null`，不自动生成精确提醒。
  - `state`：有效、替换、撤回；支持需要长期保留的撤回标记或全快照对账。
- **安全边界**
  - 只有来源可信、事件范围确定且核查时间符合约定，才允许自动公告提醒。
  - 首次安装不回放全部旧公告；上游更正、撤回须更新本地计划。
  - 可选：若供方已有可信心跳，后续拆成小型 `status.json` 与只在版本变化时下载的 `events.json`；**第一版无需拆分**。

### 4.2 UI 文字示意（虚构状态）

- **正常**
  - 当前时间：19:52
  - 公告：暂无确定的下一次重置
  - 上次请求：19:50（2 分钟前）
  - 上游检查：19:49（3 分钟前）
  - 上次公告变化：10 月 7 日
  - 提示：已检查，无新公告。
- **上游没有健康字段**
  - 本机读取成功：19:50
  - 上游最近检查：未知
  - 提示：数据可读取，但无法判断提供方是否持续监控。
- **上游长时间未更新**
  - 上次有效检查：18:40
  - 最近请求：19:50，HTTP 200
  - 提示：来源更新延迟；显示的是旧公告，不会根据过期公告创建新提醒。

## 5. 商业模式与成本

- **价格属于假设，不是已批准商品**
  - “0.99”币种待用户确认；如为人民币，不能沿用下面的美元算例。
  - 第一次免费建议：首个可用数据源接通后，用户主动开启 30 天完整试用，免绑卡，不自动扣费。
  - 美元方案 A：一次支付 US$11.88，享有一年服务权益，月均 US$0.99；**不能只展示 0.99/月而隐藏实际年付**。
  - 美元方案 B：实际每月 US$0.99；支付固定手续费通常占比更高。
- **新的成本归属**
  - 外部数据方：授权、接口费、人工审核或格式转换（由实际来源决定）。
  - 桌面服务：HTTP / CDN 请求、软件签名、更新、故障和客服。
  - 收款：支付手续费、退款与试用支持。
  - **不再默认计入**本项目自建 X 采集服务器、数据库、模型流水线和审核后台的成本。
- **简单敏感性算例（仅假设 USD）**
  - 按一次年付 US$11.88、示例支付费 2.9% + US$0.30/笔、每位付费用户每月 US$0.15 变动储备，月均贡献约 **US$0.786**。
  - 月固定成本若约为 US$40 / 130 / 370，对应年付运行保本人数约 **51 / 166 / 471**。
  - 这些只是无利润余量的运行成本示例，未含首发研发、获客、税，也不代表数据提供方真实报价。
- **什么时候决定正式价格**
  - 获得真实数据合同或数据源许可。
  - 两平台可用并完成至少 30 天运营、费用和用户价值观察。
  - 确认用户愿意为“桌面显示 + 可靠公告提醒”持续付费，而不是仅因有免费功能而安装。

### 13.2 版本兼容与证据协议

- 主 Feed `schema_version: 1` **保持不变**；可选加入 `history_url`（与 Feed 同 origin 的 HTTPS 绝对地址）和正整数 `history_version`，两者必须同时存在；`news` 为最多 64 个结构化资讯项。
- 客户端最多读取 12 页归档，每页最多 200 条，最大 2 MiB/响应；从 `history_url` GET，首批参数为空，后续 `?cursor=<next_cursor>`。各页保持相同 `channel_id`、`archive_version`、`coverage_start`、`coverage_end`、`complete`，最后一页 `next_cursor` 为空；拒绝跨 origin 跳转、重复游标、重复 `id+revision`、版本回退或与主 Feed 版本不一致。
- 归档：`{"schema_version":1,"channel_id":"demo-synthetic-announcements","archive_version":1,"coverage_start":"2026-08-08T09:00:00Z","coverage_end":"2026-10-12T11:00:00Z","complete":true,"records":[],"next_cursor":""}`；这只是 **合成示例**。
- 历史单条可包含 `kind`（`reset_announcement` / `reset_completed` / `extra_opportunity` / `observed_reset`）、`source_type`（`official` / `user_observation`）、`source_published_at`、`source_updated_at`、`effective_at`、`confirmed_at`、`observed_at`、`verified_at`、`state`、`source_url`（HTTPS）、`revision`、`audience`。
- 资讯单条包含 `id`、`revision`、`title`、`summary`、`published_at`、`updated_at`、`source_url`、`category`、`source_type`（`official` / `third_party` / `editorial`）、`state`（`active` / `withdrawn` / `source_unavailable`）、`verified_at`。
- 时间口径：重置“预告”按原始**发布时刻**、官方“已完成”按独立**官方确认时刻**、赠送按发布时刻、用户观察按**观察时刻**计数。预计生效时刻仅用于倒计时，不可替代“已经完成”。
- 仅显示 Demo 虚构 `example.org` 证据链接；来源可用性由上游提供方维护，HTTP 成功不证明来源没有失效或冒充。
