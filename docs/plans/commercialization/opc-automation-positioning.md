# OPC 自动化定位

更新时间：2026-09-16

> Plan / Positioning。这里的 OPC 指 One Person Company / 一人公司。本文定义中文市场的短名称、受众和获客表达，不表示 OpenDesk 已经取得任何市场第一。

## 1. 为什么需要把名字收短

过去内部使用的名称，例如：

`Agent-authored Local Automation Delivery Runtime for independent developers / automation consultants`

适合界定竞争边界，但不适合中文官网、视频标题和搜索传播。

以后采用两层命名：

| 用途 | 短名称 | 精确定义 |
| --- | --- | --- |
| 主赛道 | **Agent RPA** | Agent-driven RPA |
| 第一优先小山头 | **OPC 自动化交付** | 一人公司 / 自动化顾问把 Agent 做出的自动化交付给客户 |
| 第二小山头 | **双入口 RPA** | Recorder + Coding Agent → 同一种 Workflow |
| 品牌主山头 | **可复用 Agent RPA** | AI 做一次 → verified reusable automation |
| 长期扩张 | **多端 Agent RPA** | Desktop + Browser + Mobile → 同一种 Workflow |

长名称只保留在 Research / Benchmark 中。

## 2. 第一优先：OPC 自动化交付

核心用户：

- OPC / 一人公司；
- AI 自动化顾问；
- 独立自动化开发者；
- 小型自动化实施团队。

核心问题：

> 我已经能用 AI 做出自动化，怎样把它可靠地交付给客户，并重复卖第二次？

OpenDesk 要证明的链路：

```text
Agent / Human 做出自动化
→ Workflow
→ 参数化
→ 验证
→ 打包 / 授权
→ 客户机器运行
→ Evidence
→ 诊断 / 维修
→ 第二客户复用
```

中文营销候选：

> **一个人做自动化，也能像公司一样交付。**

## 3. 为什么 OPC 值得做中文流量入口

2026 年中文网络已经出现较明确的 `OPC = One Person Company / 一人公司` 内容生态，并且常与 AI、Agent、自动化、个人技术基础设施、产品化服务和可复用交付一起出现。

因此它和 OpenDesk 的目标用户存在天然重叠：

```text
一个人经营
+ AI 提升产能
+ 自动化降低重复劳动
+ 可复用资产提高交付规模
```

但目前没有可靠搜索量、CPC 或转化率数据证明 `OPC` 一定比“独立开发者”流量更高，所以它应先作为 P0 中文关键词测试，而不是把热度当成既成事实。

## 4. OPC 只作为中文优先标签

`OPC` 在全球英文语境有多种含义，例如 Open Platform Communications。

因此：

```text
中文内容
→ OPC / 一人公司 / AI 一人公司 / OPC 自动化

英文内容
→ one-person company
→ solo automation business
→ automation consultant
→ solo automation builder
```

英文 SEO 不单独依赖 `OPC` 缩写。

## 5. 为什么它比“多平台第一”更应该先做

OpenDesk 长期可以覆盖：

```text
macOS
Windows
Browser
Mobile
API
```

但 Appium、UiPath 等已经证明“覆盖平台多”本身不是稀缺优势。

当前更接近现有 OpenDesk 能力的，是：

```text
Workflow
+ Execution
+ Evidence
+ protected package
+ License
+ client delivery
+ maintenance
```

因此先证明 OPC 自动化交付，比马上补齐全部 Browser / Mobile 更接近可验证的 Top 1 小山头。

## 6. 推进顺序

```text
P0  OPC 自动化交付
P1  双入口 RPA
P2  Browser Adapter
P3  Mobile Adapter / Appium integration
P4  多端 Agent RPA
```

一句话：

> **先争 OPC 自动化交付，再扩多端 Agent RPA。**
