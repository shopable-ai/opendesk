# Desktop Measurement Oracle → Production Gap Matrix

> Baseline: `apps/opendesk/prototypes/desktop-measurement/ORACLE.md` is the stable product contract; executable HTML/CSS/JS remains final authority.
>
> This matrix records the **pre-fix static audit** used to drive Production alignment. Status vocabulary is intentionally limited to `MATCH`, `PARTIAL`, `MISSING`, `WRONG`, `NOT_APPLICABLE`. Native visual rows remain `PARTIAL` until real OS evidence exists; automated tests do not substitute for native qualification.

## Summary before Production fixes

The current implementation already has the correct single-service/single-session foundation, frozen capture model, snapshot tokens, Update/Adjust lifecycle, geometry/evidence model, keyboard bridge and much of Candidate plumbing. The main Oracle-visible drift is concentrated in:

- initial tool is `point` instead of the Oracle's initial `region`;
- Production exposes post-result Region edit handles/body move/nudge that the Oracle does not define;
- manual Region accepts any positive size rather than the Oracle's minimum 5×5 logical px;
- Candidate Stack ordering and reset semantics do not exactly match small/specific → larger ancestor behavior;
- Alt suspension and Magnet OFF do not fully clear/invalidate candidate state/preview as the Oracle requires;
- Adjust hides the surface correctly but Production has no Oracle-equivalent minimal visible Continue affordance;
- Qualification still treats old Region resize/nudge behavior as product acceptance;
- native visual parity cannot be promoted to PASS without real macOS/Windows evidence.
