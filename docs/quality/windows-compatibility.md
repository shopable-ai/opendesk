# Windows Compatibility Ledger

This ledger is the long-lived source of truth for Windows support. It separates implementation from verification and records the evidence required before a capability may be described as verified on Windows.

## Status model

- `implemented-unverified`: a Windows implementation exists, but no qualifying live Windows evidence has been recorded for the current contract.
- `verified`: the current contract has passed qualifying evidence on a real Windows runner or an explicitly controlled interactive Windows desktop.
- `partial`: only part of the public capability is implemented or verified; the missing portion is named explicitly.
- `unsupported-by-design`: the capability is intentionally unavailable on Windows and must not be advertised as supported.
- `broken`: a reproducible Windows failure exists for the current contract.

Cross-compilation is compilation evidence only. `GOOS=windows` is never Windows runtime evidence. GitHub `windows-latest` is valid for deterministic/runtime checks that do not require a real interactive user desktop. Visual, global-input, multi-monitor/DPI, and destructive/session-changing checks require the evidence tier named in `Required verification`.

Runtime artifacts, screenshots, logs, and temporary fixtures belong under `.runtime/tests/windows-compat/` and must not be committed. This file records durable conclusions and links/identifiers for evidence only.

## Evidence classes

1. **Hosted deterministic** — real GitHub `windows-latest`; build, parser/path tests, protocol tests, safe Win32/COM fixture tests, Runtime JS contract tests.
2. **Interactive desktop** — explicit Windows user session; visual acceptance, global input callbacks, multi-monitor and mixed-DPI behavior.
3. **Destructive/manual** — explicit opt-in only; session-changing or user-affecting operations. Never run in the ordinary hosted gate.

A row moves to `verified` only when its required evidence class has passed for the current observable contract. Partial capability families remain `partial` until every advertised sub-capability is either verified or explicitly marked unsupported.
