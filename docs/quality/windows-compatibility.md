# Windows Compatibility Ledger

This ledger is the long-lived source of truth for Windows support. It separates implementation from verification and records the evidence required before a capability may be described as verified on Windows.

## Status model

- `implemented-unverified`: a Windows implementation or compatibility fix exists, but no qualifying live Windows evidence has been recorded for the current contract.
- `verified`: the current contract has passed qualifying evidence on a real Windows runner or an explicitly controlled interactive Windows desktop.
- `partial`: only part of the public capability is implemented or verified; the missing portion is named explicitly.
- `unsupported-by-design`: the capability is intentionally unavailable on Windows and must not be advertised as supported.
- `broken`: a reproducible Windows failure exists for the current contract and no current fix has landed.

Cross-compilation is compilation evidence only. `GOOS=windows` is never Windows runtime evidence. GitHub `windows-latest` is valid for deterministic/runtime checks that do not require a real interactive user desktop. Visual, global-input, multi-monitor/DPI, and destructive/session-changing checks require the evidence tier named in `Required verification`.

Runtime artifacts, screenshots, logs, and temporary fixtures belong under `.runtime/tests/windows-compat/` and must not be committed. This file records durable conclusions and links/identifiers for evidence only.

## Hosted Windows P0 closure

Hosted Windows P0 is closed at source `7501f19cbc0064bb095dff2b85ac9da6522a313d` by [Windows Core run 34596333500](https://github.com/shopable-ai/opendesk/actions/runs/34596333500), job `103252886435`, on GitHub-hosted `windows-latest`. Maintained Go compilation, Custom UI seams, Window Manager seams, the canonical portable build, public Runtime Window contract, hosted Win32 fixture, Native UI Host protocol, relocated portable distribution contract, test-architecture audit, and evidence upload all passed.

The Runtime asset ownership decision used by the distribution is:

- **A. Compile-time embedded:** Go Runtime/native bindings and constants/defaults already compiled into binaries, plus resources embedded by the Native UI Host build.
- **B. Executable-relative Runtime assets:** every top-level `polyfills/*.js` and `jslibs/*.js` file (19 + 5 at the recorded source), `resources/opendesk-notification.png`, four predefined files under `sounds/public/`, and the complete `ui-host/` publish closure. These are the only source-owned files added to the portable distribution closure.
- **C. Application/user assets:** user scripts and configuration, project Custom UI/App Mode files and icons, explicit audio inputs, and user-provided Native Extensions. These remain inputs and are not copied into the Runtime distribution.
- **D. Development-only assets:** examples, tests and fixtures, schemas used only for development/validation, documentation, source maps not required at runtime, and `.runtime/` evidence/logs. These are not shipped.

The P0 support statement is intentionally limited to the canonical `win-x64` portable target and Hosted deterministic evidence. `win-arm64` remains unsupported/unverified as a complete OpenDesk distribution. Interactive Windows 11 evidence is still required for real multi-display and mixed-DPI behavior, foreground policy, GlobalShortcut callbacks, tray/notification/dialog/toast visual behavior, real keyboard/mouse global capture, Recorder hardware/session paths, and other user-session-dependent behavior.

## Evidence classes

1. **Hosted deterministic** — real GitHub `windows-latest`; build, parser/path tests, protocol tests, safe Win32/COM fixture tests, Runtime JS contract tests.
2. **Interactive desktop** — explicit Windows user session; visual acceptance, global input callbacks, multi-monitor and mixed-DPI behavior.
3. **Destructive/manual** — explicit opt-in only; session-changing or user-affecting operations. Never run in the ordinary hosted gate.

A row moves to `verified` only when its required evidence class has passed for the current observable contract. Partial capability families remain `partial` until every advertised sub-capability is either verified or explicitly marked unsupported.
