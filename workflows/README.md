# OpenDesk 工作流

状态：流程作业文档；不是已安装的调度器，也不是业务或整链测试通过报告。

## 目标与本阶段优先级

OpenDesk 面向工作和生活中的重复操作、多步骤任务与跨应用协作。已经明确且能够验证的步骤沉淀为普通 OpenDesk JavaScript；必要的理解、动态判断与例外处理保留 Agent 参与。后续可以接外部编排，但普通脚本不依赖 LangGraph、Recorder、Compiler 或独立 Workflow Runtime。

当前商业推进以现金流为先：宣传具体可交付的结果，接小范围付费项目，完成交付、验收与收款，再从真实项目中提炼复用资产。允许早期人工参与，不以“先建成平台”作为接单前提；低价应对应小范围，不对应无限维护。

## 三个入口，不混成一条技术流水线

| 当前要做什么 | 入口 | 本次交出什么 |
| --- | --- | --- |
| 获客、评估、报价、交付、收款与复购 | [客户交付流程](client-delivery/WORKFLOW.md) | 有范围的付费项目、验收记录、实际回款及复盘 |
| 从任务或已有脚本得到可复用自动化 | [Agent-to-Recipe](agent-to-recipe/WORKFLOW.md) | 经过明确范围验证的普通 JS，必要时含 Agent／人工环节 |
| 使用已经交付的自动化完成一次业务 | [业务执行流程](business-execution/WORKFLOW.md) | 本次业务结果、证据或明确的停止／待确认状态 |

客户交付流程按需调用 Agent-to-Recipe；得到候选并验收后，业务执行流程负责每一次真实运行。每次运行不重新做完整十二阶段，每次接单也不要求从零生成代码。计算器是技术验证目标，不是获客方案，也不建立一套应用专属开发 WORKFLOW。

## 目录职责

`docs/frameworks/` 维护方法、分层与公共合同；`prompts/automation/agent-to-recipe/` 维护六个专业 Skill、提示词及已有任务包模板；`workflows/` 维护路由、先后关系、交接、完成门槛与失败去向。不复制六套 Skill 正文，不将提示词挪回本目录。本目录也不同于 `.github/workflows/` 的 CI 配置。

现有普通 JS 保留其已经核对的源码位置。新候选先按共享合同放在当前 attempt；正式成品进入获准维护的项目或既有示例目录。客户私有脚本和数据不默认进入公共仓库。是否拆文件由实际复用与当前 Runtime 加载能力决定，不为每个点击新建目录。

运行日志、截图和临时任务进度按根 [AGENTS.md](../AGENTS.md)存入 `.runtime/`。它是可清理目录，不是长期资产库；有效证据需要获准保留、脱敏归档和可核对引用。

## Workflow 作者约定

先写清“结果是什么、谁或什么是目标、怎样证明完成”，再写动作。每个可独立交接的业务步骤沿用[任务求解方法](../docs/frameworks/automation-problem-solving-framework.md)的步骤说明：输入与来源、前置与授权、输出与验证、有效条件、失败与重入。不另建第二份强制 schema。

工作流需给出入口与范围、责任人／Agent、依赖、产物位置、完成条件、预算、停止方式、失败归属和可复用资产。Agent-to-Recipe 的 request、handoff、progress 与公共字段只在[共享合同](../docs/frameworks/agent-to-recipe-skill-contract.md)维护。文件本身不提供执行、权限隔离或暂停恢复能力。

普通 JS 是业务执行源码；合同定义正确性，Evidence 证明实际发生的事实。语义步骤与工作流说明不是第二份可执行 IR。只使用当次 API 文档支持的能力，不凭空增加 Node runner、`opendesk skill run`、模块加载、`Execution.resume` 或新全局对象。

每个候选必须记录实际工作目录、一行正常命令、输入方式、依赖和适用范围；实际运行才可产生通过证据。只要求写文档不授权桌面操作、发消息、广告投放、安装、发布或付费。

## 资产化与平台的先后顺序

先形成可交付项目，再沉淀可复用的应用操作和业务能力。准备共享的资产至少能说明版本、用途、入口、输入输出、应用／系统范围、依赖与权限、验证范围、维护者、来源与复用许可、升级／回退方式和成本。缺少当前证据时如实标注，不继承旧版本的通过结论。

账户、联系人、聊天记录、客户材料、密钥和本机坐标不是通用资产。复用之前确认客户约定和资料权限；来源不清先保持私有。等相似项目反复复用且维护成本可接受，再考虑目录检索、版本分发、权限、计费和市场，不先实现平台。
