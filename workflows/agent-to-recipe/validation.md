# 验收边界与下一步推进

本文件定义怎样验收，不是执行报告。沿用[共享合同](../../docs/frameworks/agent-to-recipe-skill-contract.md)和现有质量体系，不预填分数，不新增平行 Gate 编号。

## 1. 分别报告四件事

| 范围 | 可证明的内容 | 不可替代 |
| --- | --- | --- |
| 文档／静态检查 | 文件、链接、阶段映射、输入输出与责任是否一致 | 不能证明工具和桌面操作可用 |
| 独立交接检查 | 只凭指定输入能继续或准确指出缺口 | 同一 Agent 的旧记忆不能冒充隔离测试 |
| 候选 Fresh Run | 本次候选、环境、输入和业务结果符合合同 | 不能用旧参考脚本替代新候选 |
| 混合业务端到端 | 真实 JS、Agent／人工边界及最终结果均有证据 | mock 判断或单片段通过不够 |

每一阶段按阶段卡单独记录输入核对、输出、criterion、证据、gate.scope、失败与责任归属。不把 S3 的节点成功写成 S6 示范通过，也不把 S8 草案写成 S9 完整过程通过。

## 2. 优先验收场景

复用当前测试规程及合同中已有场景。新任务至少覆盖与目标相符的正常输入、合法变参、错误拒绝、本次真实数据流、环境／对象变化、关键证据缺失和受控接续；具体范围在 S1 冻结，不执行未授权扰动。

S8／S9 重点检查：业务步骤独立可读；示范值不成为运行常量；JSON／可读视图版本与 hash 不一致会阻塞；代码推断不会被当作新示范。

混合消息示例重点检查：同名对象、上下文新增消息、过期批准、无 Agent、非法输出、发送后回执缺失和恢复重入。先用脱敏样本和不发送模式验证结构，再在明确授权范围内验证真实动作；文档示例不是发送授权。

外部副作用测试先选只读、草稿或受控目标，不对真实客户付款、发货、删除或重复发送做破坏性注入。记录 not-run／blocked 原因，不用改小 requested 取得 pass。

## 3. 计算器是目标样本，不是另一条开发流程

可参考[现有计算器验证规程](../../docs/quality/agent-to-recipe/calculator-validation.md)，但运行前必须核对其中引用的源码和命令。

本次初始远端核查基线为 `8fba1d2271da7f1039f075eca62efd82a9d06910`；该提交说明为 `chore(workflows): remove invalid workflows`，核查时远端没有 `workflows/`。因此旧规程引用的 `workflows/macos/calculator/calculate-and-reuse-result.js` 不能被当成当前现成入口。随后远端 `a79ded518dd14df6c37144dc302be9519169ad45` 已补入通用流程、业务执行和客户交付入口；本轮在其基础上增量完善，不覆盖这些并行成果，不恢复已删除的应用脚本，也无法证明本机未提交脚本的状态。

后续执行先核查本地工作树，保留已有修改和真实脚本；确有可用资产则走接续范围，只补必要证据与过程。不自行重建旧路径骗过 gate，不用 JS 算术代替 UI 计算，也不把历史的 1000／287 当本次结果。尚无可用脚本或环境则记录阻塞，再按授权决定创建候选。

## 4. 收敛的推进顺序

先完成一个低风险目标的开发交接与候选 Fresh Run，证明 S8／S9 到 S11／S12 的数据来源没有断链。接着验证“读取内容 → Agent 判断 → JS 输出草稿”的混合闭环，最后才在明确授权下增加发送核验。

在真实复用需求出现后提取组合 helper 并验证其输入输出；再做第二使用者的资产交付。外部编排和平台以这些已有产物为基础，不倒过来要求先建设平台才跑通任务。

后续报告必须列出实际候选／hash、命令、工作目录、构建来源、环境、各场景结果、证据和未测项。只写入本目录时，业务执行和整链验收状态仍为未执行。
