# recipe-build：输入输出适用规格

本页拥有 S11 对正式合同的消费方法，不另建 schema。字段、版本、CandidateManifest 与交接规则唯一依据：[共享合同](../../../../../docs/frameworks/agent-to-recipe-skill-contract.md)；评分统一见 [validation-plan](../../../design/validation-plan.md)。固定 SKILL.md、本规格和实际读取的必要方法／契约版本；业务输入另有固定引用。

## 必需与条件输入

首次生成必须实际取得 request、TaskContract、已确认 SemanticProcedure、当前需要的 AppProfile／操作规则、实际 helper 与 canonical／公共约束、正常 Runtime 入口、输入合同、依赖和修改范围。不能仅看到路径或声称“已选型”就假定其正文可读。检查引用的根目录、实际字节、hash、schema、任务与范围。

修复还需原候选、原失败、允许修改的对象与重验要求；旧资格是条件输入，不是首次生成的前置。已有资产接续按原 continuation 规则处理，不伪造历史；无关截图、完整 Dossier、远期规则和未发生的 Qualification 可省略。

## 下游判断与获准来源

| S11／S12 必须判断或产出 | 需要的内容及正常来源 | 应交付与证明边界 |
| --- | --- | --- |
| 每个业务要求怎样由代码实现 | 合同要求＋Procedure 的步骤、输入、前后置和停止 | JS 与 sourceMapping；映射存在不证明分支真的可达 |
| 运行时值是否真实传递 | Procedure 的生产／消费／绑定／类型／政策，必要定向证据 | 实际返回值流向及必要变换；历史 observedValue 不是默认答案 |
| 调用者怎样改变业务输入 | Procedure 参数语义、输入政策及当前入口／结构化输入契约 | 按[下文实现消费](#可变业务输入的实现消费)交付 inputContract 与真实入口绑定；只有 helper 参数不算完成 |
| 操作怎样安全实现 | Profile／同版 handoff 的目标、定位、读取、等待、动作、运行门禁、恢复及未知 | 实际 API／helper、即时检查与范围；局部认识不等于实测操作 |
| 方法能否在 Runtime 调用 | 已选择 canonical、共享约束、当前平台／入口与构建信息 | Candidate.apiRefs、dependencies、entryCommand、workingDirectory；文档不能证明运行通过 |
| 候选是否同一版本 | 实际脚本与依赖字节、固定上游引用 | scriptRef／scriptHash 及清单；hash 只证明字节一致 |
| 如何验收及修复 | 预定标准、实际检查、支持范围、限制和变化影响 | 交 S12 的冻结候选与重验范围，不预填资格结论 |

## 可变业务输入的实现消费


本节说明 S11 怎样消费既有 SemanticProcedure.parameters、Business Step.inputSources 与 CandidateManifest.inputContract；字段仍由共享合同维护，不增加公共字段、schema 或运行引擎。仅在声明业务参数化时适用；固定任务仍可作固定范围交付，不能据此宣称任意变参。

| 责任 | 必须交清／落实什么 | 不能替代为 |
| --- | --- | --- |
| S1／S8—S9 | 哪些业务输入可由调用者改变，其含义、类型、必要格式／长度／值域、缺省政策与支持边界；每项连接实际 Business Step 输入及允许变换 | 只有一个 parameters 名称表，或从一次示范自动推断全部组合都获支持 |
| S11 | 使用当前已发布的输入入口，将调用者输入校验后传入实际业务函数；入口方式、inputContract、源码区域、所选 API／入口契约互相对应 | 只有内部 helper 有参数；主入口仍写死；修改源码／常量后把另一候选称作同一候选的变参 |
| S12 | 使用同一冻结 Candidate 与入口实现，只更换其允许的业务输入；场景与独立 Oracle 在运行前确定，记录每次实际输入及其来源 | 改测试桩读值、把 expected 交给生产脚本、重写候选或只改变资格声明 |

调用前可判定的业务输入错误应在首次业务副作用（含清除／状态准备）前拒绝。类型、格式或超范围输入不得被静默转型、截断、钳制或回退为示范值；未知字段按已声明政策拒绝或明确忽略，但绝不能覆盖 runtime value／Expected。依赖实际读取才能判定的条件，在该读取后、依赖它的下一次副作用前检查，不要求 S1 猜未来结果。

运行时值仍由本次实际生产者产生，不成为可覆盖的调用参数；默认值也不得含示范读数或 Oracle。纯格式验证和获准字符展开可以由 JS 完成，不得借参数处理在 JS 中重新计算本应由 UI 取得的业务结果。改变参数不自动改变应用身份、布局、权限或定位策略。

需要结构化输入时，从当前 API 短入口取得 [Execution.input](../../../../../docs/api/execution.md#executioninput) 与实际启动入口的完整契约；这是已有能力，不表示任意 `-script` 命令都接受 `--input`。本节不重定义 CLI flags、序列化或 Runtime 行为。扩展旧候选输入范围时先修订相应合同／过程，再形成新 Candidate；旧候选、旧 spec 和资格保持原证据绑定，不手改旧 hash 让其“兼容”。

## 不变量、检查与缺口

业务含义、Expected、实际事实和 Unknown 分开。业务运行只消费已解决的生产数据；保持前导零和必要单位精度，不能把运行时值复制进 parameters／config／Secret 的默认答案。每个必要输出有消费者或终点去向；没有输出的合法步骤可用空消费者，不能机械禁止全部空数组。

sourceMapping 关联已确认 Business Step 和能力决定，不倒推选型历史、不重新做 actionDecisions。运行时门禁与资格 Gate 分离：去掉历史证据不等于去掉高风险动作即时检查。依赖外部 OCR／Vision／模型须明示，依赖 Agent 实时规划的程序不能称为离线确定性 Recipe。

先按需求与数据流审阅，再执行适用静态／合同检查；有 Runtime 条件与授权才实跑正常入口。首次候选检查不要求先有 Qualification。当前分段检查不证明任意 JS 的可达性、别名、变量遮蔽或通用等价性；超范围保留覆盖缺口，不改业务迎合检查器。

缺资料包先找协调者；业务语义回 S8—S9，原动作取舍回 S7，操作规则回应用工程，Agent 原事实回 S3—S6，Human 来源回原 Human 责任。部分代码只能按真实部分完成交接，关键未决不能伪装为可用候选。副作用未知先核对，不重放；修复后新候选固定新字节、保留旧失败和有效上游，只重验受影响范围及必要回归。

## 正常、拒绝、修复／复用样例

以下是可审阅的方法练习，非模型或桌面执行证据；实际调用需固定输入。Expected 不进入 Producer 的事实输入包。

| 类别 | 明确输入 | 输出／判断 | 原因及接续 |
| --- | --- | --- | --- |
| 正常首次生成 | Procedure 要求读取 ticketCode，再按 identity 查询，最后读取状态并打印；Profile 与实际 API 契约齐全，无 Candidate | 普通 JS 的查询输入绑定读取返回值；状态读取连接终点打印；生成首份 CandidateManifest | 不要求未来候选或资格；真实示例字符串 `00128` 不写死 |
| 拒绝语义缺失 | 过程只说“处理编号”，未说明保留前导零或可采用变换 | 返回 S8—S9，指明缺少哪条政策／输入关系；不自行转成 Number | 代码可编译不代表业务语义正确 |
| 拒绝虚构规则 | 只有目标截图和不存在的 helper 名称，被称为“已验证操作” | 返回应用工程，区分可用认识与缺失操作规则／实测 | 文件路径和声明不能替代实际源码或规则 |
| 定向修复 | 原 JS 已读 ticketCode，却把固定 `128` 传给查询；过程和应用规则正确 | 只修实际数据绑定，形成新脚本 hash／Candidate，保留旧失败并交 S12 重验数据链 | 不重新示范，不把旧资格复制给新字节 |
| 原样复用 | 精确原候选未变，输入／规则仍适用，无改进目标或实现缺陷 | 引用原字节及适用核对，不生成假改动；待验范围仍交 S12 | 静态保留结论不授予当前环境资格 |
