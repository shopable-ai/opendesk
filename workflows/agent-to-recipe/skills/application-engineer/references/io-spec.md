# application-engineer：三模式输入输出适用规格

本页说明 discover、harden、repair 怎样分别消费正式合同；三模式不是必须依次运行的流水线。AppProfile、引用、版本、交接和失效唯一依据：[共享合同](../../../../../docs/frameworks/agent-to-recipe-skill-contract.md)的应用工程增量与发布条款；Human 来源同时遵守 [Human 作业树](../../../../human-to-recipe/design/task-decomposition.md)。评分仅用 [validation-plan](../../../design/validation-plan.md)。本页不创建第二套 Profile、状态或 schema。

## 共用进入核对

读取本次 request、模式及范围、必要输入实际正文，固定方法／本规格和实际采用专项正文的版本；核对根目录、hash、schema、任务／来源身份、支持范围及本次权限／预算。路径可读、来源内容可信、现场仍适用是三件事。只有“已授权”“已验证”文字不够；观察、桌面输入、上传图像及外部动作分别受原授权限制。

允许按当前问题读取专项材料。discover 不需要完整 Procedure；harden 不强制重跑 discover；repair 不重新盘点整个应用。非必需图像、全部原生树、远期布局和无关规则可以省略；省略不得掩盖必要目标、父区、进入路径、结果区或重名对象。已有有效资料先复核复用。

## discover：近期目标 → 最小应用认识

必需：固定合同、近期目标／必要操作、实际观察或获准采集条件、已提供的相关旧资料；没有旧 Profile 可以开始。输入无现场或采集授权时只在实际材料可支持的范围认识，不宣称现场可操作。

| 下游必须判断／产出 | 正常信息来源 | 本次产物及边界 |
| --- | --- | --- |
| 示范能否找到正确应用／对象 | 合同对象、实际应用身份／页面观察 | AppProfile 的必要身份、状态、目标、进入条件及未知；不是全部应用模型 |
| 目标与结果区是什么关系 | 固定观察／关系证据、已有可核对资料 | 有来源的 targets／relations／claimSources；外观解释不冒充原生事实 |
| 当前认识是否足够推进 | 同版证据、当前范围、规则适用限制 | scoped 审阅与缺口；认识通过不自动使定位、操作、业务通过 |

作业：先对照目标复核旧资料 → 确定缺口与最小观察范围 → 区分可见事实／解释／Unknown → 整理必要目标、关系和状态 → 检查引用／几何／可辨识性 → 生成适用同版审阅材料 → 发布最小 Profile 或明确缺口。没有屏幕映射的截图可以支持界面认识，不能据此点击。

## harden：已确认过程＋工程缺口 → 可消费操作规则

必需：已确认 Procedure 或 Human 的已确认过程、当前需要的 Profile／规则、明确待补操作及限制、相关 API 契约与获准验证条件。不要求先有候选代码或最终 Qualification。

| 下游必须判断／产出 | 正常信息来源 | 本次产物及边界 |
| --- | --- | --- |
| 代码怎样定位和确认目标 | 已确认步骤／目标＋有来源 Profile | 目标身份、locator、geometry、唯一性与失效条件；一次矩形不是永久身份 |
| 怎样读取、等待与动作 | 当前操作要求、真实 canonical／共享约束、已有规则 | 读取类型、等待条件和预算、actionStrategy、runtimeGuards、stop/recovery；不猜不存在的 helper |
| 规则验证到什么层级 | 实际观察、局部实测、声明环境与变化场景 | 局部验证记录及 not-run／blocked；规则设计不等于业务资格 |
| 哪些可以复用，哪些需补强 | 精确旧版、当前依赖及本次缺口 | 有效规则保留，定向增量及引用；不强制重复建模或验证无关项 |

作业：逐个待补操作对照既有规则 → 核对目标与当前 API → 补必要定位、读取、等待、动作、停止和恢复约定 → 区分运行门禁／资格断言／Evidence → 按获准层级验证正常与必要变化、失败停止 → 发布规则及剩余 Runtime／环境缺口。S9 的工程 not-run 可由本模式处理，不反向编造已发生的选型或验证。

## repair：具体失败＋旧规则 → 局部修订和重验要求

必需：固定失败、旧 Profile／规则、受影响对象／操作、当前已知状态和允许修复范围；需要新观察时另取授权。不要求先跑 discover 或重写全部过程。

| 下游必须判断／产出 | 正常信息来源 | 本次产物及边界 |
| --- | --- | --- |
| 失败归因是否真在应用规则 | 原始失败／回执、旧规则、实际环境／目标 | 归因及证据；事实／语义／实现问题按来源返回，不统称定位失败 |
| 修改什么、保留什么 | 具体差异、依赖关系与支持范围 | 新版本 changeLog、修订规则、有效旧资产引用与影响分析 |
| 能否安全继续及重验哪里 | 实际副作用状态、预算、受影响消费者 | 定向重验与恢复请求；未知效果先核对，不重放前缀 |

作业：固定失败与旧版 → 核对实际效果及责任 → 只补缺证或修改失效规则 → 列出影响对象、过程、候选与验证 → 先冻结新 Profile／helper 再生成审阅记录，避免 hash 环 → 重验受影响项及必要回归 → 发布可消费新引用。旧证据、失败和资格不覆盖；规则变更影响候选时生成新候选并交 S12。

## 来源路由与 S9 消费边界

| 缺口 | Agent 来源 | Human 来源 |
| --- | --- | --- |
| 原历史动作、实际读值／回执缺失或冲突 | S3—S6／task-demonstrate 定向补证；不能事后重造旧事实 | H2 事实采集；按 H4 审阅／补观察确认；不改标为 Agent 示范 |
| 原动作整理、归组或取舍错误 | S7／trace-distill | H3 整理、H4 审阅；H5 的增强取舍按其已确认输入修订 |
| 业务含义、参数、数据关系错误 | S8—S9／procedure-synthesize；源政策缺失回 S1 | H4 意图／需求补充与 H5 过程提炼，按具体缺口返回 |
| 应用关系、定位、读取、等待或操作规则错误 | application-engineer 当前适用模式 | H5 应用工程，复用本 Skill，但保持 Human 来源 |
| 目标、授权或成功标准变化 | S1，停止依赖动作 | H1／需求确认，不由增强模式自行授权 |
| 代码或验收设置错误 | S11 或 S12，按缺陷归属 | H6 代码或 H7 验收，保留原标准 |

已有获准资料只是没交付时，先找协调者补交；原资料本身缺失／矛盾才回源责任。不能把所有失败统一退 H4/H5，也不能统一退 Agent 示范。

Dossier 是 Agent 历史事实来源。S9 的正常输入是固定 DistilledSteps，加本次明确交付且可读取的必要应用资料、政策、选择记录和定向证据；历史 lineage 不授权静默重读完整 Dossier／Raw Trace。应用工程不重新拥有 S7 的原动作取舍；Human action disposition 仍由 Human plan 维护。generic CollectionItem 的业务字段映射由过程／业务代码负责，不塞入 Profile。

## 三模式的正常、拒绝、修复／复用样例

下表是方法练习，不是实际模型、宿主或桌面证据。版本固定和实际来源必须由真实请求提供；模型置信度不代替授权或验证。

| 模式／类别 | 提供的内容 | 应交付／拒绝及理由 |
| --- | --- | --- |
| discover 正常 | 合同需读取工单标签，提供当前局部截图及来源，无完整 Procedure | 最小 Profile：标签、所属区域、结果关联、可见状态与未知；不要求未来过程 |
| discover 拒绝 | 只有无屏幕映射截图，却要求据此立即点击 | 可继续只读认识；拒绝点击并具体请求映射／身份／授权，不把图像像素当屏幕坐标 |
| discover 复用 | 同版有效 Profile 覆盖当前目标，身份与可变前提核对无变化 | 记录本次适用核对并引用原版，不重新全屏建模 |
| harden 正常 | 已确认查询步骤，只缺结果读取与有限等待规则；已提供对应契约和观察 | 定向读取／等待／停止规则，局部验证层级明确；不重做整个过程 |
| harden 拒绝 | 操作只有未实现方法名或“已验证”声明，无源码／契约或实测来源 | 不交可执行操作；记录具体 Runtime／证据缺口，不伪造 helper |
| harden 复用 | 当前全部所需规则已有效且支持范围相同 | 引用原规则与验证边界；没有新工程缺口则不改版、不强制运行 |
| repair 正常 | 固定失败显示重名目标歧义，旧规则只按文字匹配，父区证据可用 | 仅增加有来源父区约束，发布新规则、影响和重验；不改业务标准 |
| repair 拒绝 | 提交超时、效果未知，请求直接再点一次 | 保存失败与 unknown，先核对实际效果，拒绝盲重放或切换后端重复提交 |
| repair 修复／复用 | 失败来自下游错误参数，原定位规则及现场证据仍有效 | 原规则保持不变，定向交 S9／Human 对应语义责任，补正新版本后重消费 |
