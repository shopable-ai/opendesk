# application-engineer｜独立审阅基线

审阅对象仅为本 Skill 的方法与交付能力，不把其他 Skill 或整链表现平均进来。本页不是新的 Gate/Workflow，不更改 S1—S12。审阅输入限本 Skill 四层材料、正式合同及指定任务材料；不能依赖完整聊天、标准下游答案或最终 JS 补缺口。

## 七个维度逐项判定

| 维度 | 本 Skill 必须独立回答 | 不合格表现 |
| --- | --- | --- |
| 方法正确性 | 需求如何转成认识问题，再以观察形成主张；harden/repair 如何只补局部 | 从代码倒推历史；重复建模；把回执当后置 |
| 输入输出完整性 | 每模式进入条件、Profile/规则/审阅内容、范围与未决如何表达 | 只有文件路径；缺读取/等待/停止合同 |
| 责任边界 | S2/S10 与 S1、S3—S6、S7、S8—S9、S11/S12 谁拥有何种判断 | 代做业务参数化、原动作取舍或资格放行 |
| 失败处理 | 缺证、歧义、unknown 副作用、超时、版本变化如何返回/接续 | 盲重放；降低标准；覆盖旧失败/资格 |
| 案例解释 | Calculator 能否从输入走到逐项输出，并解释错误链 | 把案例观测/尺寸当通用规则或历史实测 |
| 下游消费 | 每消费者实际取得哪些固定正文、能做什么、不得做什么 | 让下游从 lineage 偷读全历史或猜规则 |
| 跨应用复制 | 替换对象/关系/环境后，模板与方法是否仍成立 | 依赖数字按钮、固定窗口尺寸或特定 helper |

## 独立审阅练习

提供未知应用任务及无坐标映射截图，要求给出最小认识和不能点击的理由；去掉 Procedure，答案仍应可成立。提供已确认查询过程、只缺等待/读取，答案应定向补强；提供完全有效规则，答案应复用。提供重名目标失败，答案应局部加有据范围；提供提交效果未知，答案应先停止/核对。把读取目标改成工单状态区，方法不应要求 Calculator 元素。

每次记录实际输入/方法/规格版本、执行方式、输出、逐项错误及扣分依据。文档 walkthrough、自我审阅、确定性检查、未参与上游的执行者测试、真实桌面验证分别报告，不互相冒充。没有独立宿主/现场能力时明确 not-run。

分数可用于本 Skill 的七维文档审阅，但不能据此发布官方 Gate、模型 Producer 能力分或 QualificationRecord。不可用文件数、模板数、测试数或整链旧 PASS 证明达到 95。方法/来源/安全停止的关键错误必须修正，不能被其他高分抵消。
