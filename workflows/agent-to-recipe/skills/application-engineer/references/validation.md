# application-engineer｜正确性检查

本页检查方法和交付，沿用现有 [验证计划](../../../design/validation-plan.md) 的适用 G0—G7/F0—F10；不新增 Gate。文件存在、schema 合法、脚本测试通过都不单独证明本 Skill 正确。

## 检查顺序

| 检查 | 具体做法 | 发现错误的反证 |
| --- | --- | --- |
| 输入就绪 | 逐项核对模式、必需输入、真实字节/版本、权限/预算和现场适用性 | discover 被要求先提供最终 JS；repair 无旧规则或失败材料 |
| 需求覆盖 | 每个必需认识问题都有主张或明确阻塞，保留父区/锚点/结果/重名对象 | 只标按钮、不标结果；难目标被降为次要 |
| 证据可信 | 把身份、状态、关系和坐标主张逐项追到原图/属性/实际观察 | 只有代码、Expected、模型置信度或“已验证”文字 |
| 结构/几何 | 检查 ID 唯一、引用存在、父关系无环、图像范围、坐标空间/变换和安全区域 | image 像素直接当 screen 坐标；textBounds 当点击区 |
| 语义 | 对照原图与同版叠加/关系/属性视图审阅必要对象和关系 | 标框正确但指向错误业务对象；未读状态被写 false |
| 操作 | 审核输入输出、定位唯一性、读值来源、等待上限、门禁、后置和停止规则 | 仅有 click 坐标；无限等待；回执成功就宣称业务成功 |
| 修订影响 | 对照旧/新版及 dependsOn 查受影响规则、过程、Candidate/验证 | 修过规则仍沿用旧 qualification；覆盖失败证据 |
| 消费交接 | 让审阅者只用本 Skill、合同和固定输入解释下一安全动作 | 必须借助聊天、最终代码或未交付的全量 Dossier 才能继续 |

## 三模式必须通过的反例审阅

**discover：** 只有 `calculator-current.js` 时，不得据窗口尺寸或 helper 宣布首次认识完成；应列出当前需观察的问题。截图没有屏幕映射时可以交付限定认识，必须拒绝依赖坐标的点击。没有 Procedure 不是 S2 失败理由。

**harden：** 已确认过程只缺读取/等待时，不重新设计步骤或变量；若规则全覆盖且当前条件有效，输出有效复用。未实现 API、未实际存在 helper 或没有语义确认的操作，不得列成可执行交付。

**repair：** 提交超时且效果 unknown 时必须停输入、先核对效果；重复点击不是维修。两处同名控件可用有来源父区约束局部修复，不能改成功标准。输入参数错误则保留有效定位规则并返回 S8—S9/S11 对应责任。

## 工具能证明什么

保留现有 `scripts/review.py` 的 ingest-extraction、validate、render、revise 工作路径。先从仓库根目录查该脚本帮助并使用其实际参数；不发明子命令或声称它会调用模型。ingest-extraction 只接收已保存的实际提取记录，核对 actualImageConsumed、原图 ref/hash/尺寸、observation 与基线；空返回、截断、拒绝、冲突不能修饰为成功。

真实认识闭环为：原图及采集元数据 → 宿主实际看图/获准 provider 实际接收字节 → 原始模型输出 → 显式字段适配 → validate → render → 对照原图审阅 → 必要 revise → 再验证/渲染。只有 Agent 看图不能声称 provider 调用；脚本接收本地路径不能证明模型看过图。没有对应能力时保留 not-run，不能用 OCR 或模型自评替代。

结构校验器不认证业务关系或真人审阅。确定性静态检查可继续，但不能补足未发生的多模态提取、真实操作或独立上下文交接。缺检查器实现时明确采用人工/逐项核对及其限制，不自报程序 PASS。

## 操作验证与支持范围

对声明可执行的规则，分别验证重新定位、正确目标唯一性、读取与目标绑定、有限等待、失败停止、动作回执与真实后置。选取未参与建模的画面和所声明支持变化；未测试布局、语言、主题、平台或 provider 不进入支持声明。没有桌面/授权则写 not-run，不因离线通过提升成熟度。

Collection 场景按适用 SC-A—SC-P 分开验证 visible collection、traversal 和业务 parser；Runtime gap 不靠填造方法通过。取消、超时、重复副作用、过期坐标/原生 ref、歧义目标和证据冲突必须可安全停止。

## 放行判据

每一项正向结论都有范围和证据；每个关键未知有禁止消费范围与返回责任；下游无需猜测。任何必要授权/人工审阅缺失、关键来源冲突或未知副作用，都不得发布依赖工作的正常 pass。文档独立审阅分数不代替能力评测、Gates 或 QualificationRecord。
