# task-demonstrate：输入输出适用规格

本页只拥有 S3—S6 对现有合同的使用方法。字段、引用、状态与发布语义唯一依据：[共享合同](../../../../../docs/frameworks/agent-to-recipe-skill-contract.md)第 5—7 节，尤其 DemonstrationDossier 与 S7 → S9 输入充分性增量；评审规则见 [validation-plan](../../../design/validation-plan.md)。方法及本规格固定实际内容版本，不能把业务 inputRefs 的 hash 当作方法版本。

## 必需与条件输入

必需：本次 request；固定 TaskContract、实际生效 WorkPlan、推进当前步骤所需 AppProfile／规则；实际业务输入、当前环境／构建与入口；获准对象、工具、文件根、动作及预算。开始动作前实际读取正文并核对 hash、schema、任务、计划与目标身份。没有完整未来 Procedure、DistilledSteps、Candidate 或 Qualification 不构成缺输入。

条件输入：定向补采请求及原失败／已有证据；已有资产接续的明确来源和用途；只在业务确实需要时取得截图、OCR、AX/UIA 或其他证据。不要求所有场景开启 Recorder、截图全桌面或使用同一种感知方式。现有 Recorder／Replay 能力存在，但录制资产不自动变成本次 Agent 示范。

字段存在、路径可解析或检查器能读资料，不等于 Producer 已消费内容；“已验证”“已授权”的自述必须追到实际来源。旧 AppProfile 可复用，但当前账号、窗口、焦点和执行状态仍按必要范围重核。

## 从下游需要反推同步采集

| 下游判断／产出 | 需要的信息 | 本次实际来源与交付 | 能证明与不能证明 |
| --- | --- | --- | --- |
| S7 判每个动作保留／合并／排除 | 原动作、顺序、目标、输入、计划关联、实际观察与验证 | 真实执行日志／动作记录及固定 actionsRef、executionRefs；Dossier 索引必要证据 | 证明发生了什么，不直接证明动作在所有环境都必要 |
| S7 保留运行时值生产者 | 原始读值、类型、读取动作、应用／目标身份 | 实际 observation；Dossier.runtimeValues.origin、observedValue、evidenceRefs | 证明本次读值；历史样例不是未来默认输入 |
| S7／S9 保留实际消费者 | 每个原消费者、实际传入值、实际采用的变换、应用与目标 | 实际动作与值的消费记录；对照实际输入，不仅写“使用了变量” | 允许变换政策不证明本次真的采用了哪种变换 |
| S9 判断值的复用含义 | 业务含义、类型、必要单位精度、允许变换、有效期、重读规则 | 固定合同／明确政策；若后来确认，保存新政策来源版本 | 不能仅由一次观察推导通用政策；缺政策回 S1 |
| S9 明确应用关系与能力选择 | 目标关联、选型理由、候选处置、canonical／约束、实际验证状态 | 固定 Profile／关系证据及原工作包的 capability-selection 记录 | API 文档证明契约，不证明实际选型或运行；not-run 不补造证据 |
| S6／后续核对业务终点 | 最终实际读值、最终输出去向、逐项标准与真实结果 | 实际 UI／业务观察、输出日志、criterion 对应 evidence | 动作返回成功不等于业务成功；没有后续动作的终点仍须保留 final output |
| 失败后安全接续 | 原失败、最后确定状态、未知副作用、消耗预算及可保留成果 | 原始失败和动作回执；Dossier.sideEffects／unresolved／handoff | 缺回执不能推断未执行；新观察不能补写成旧事实 |

Dossier 保留历史完整来源；给 S9 的必要证据由明确的定向材料交付。不能因为 Dossier 里有内容，就省略 S7 的必要投影或让 S9 静默读整份历史。

## 产物及不变量

输出 DemonstrationDossier＋固定 Raw Trace／Evidence 引用、planned／actual 对照与必要偏差记录。共享合同已定义 Dossier 最小字段，本页不复制 schema。同步留存脱敏动作参数、实际观察、真实业务值、消费者、验证及副作用；不保存私有思维过程。

事实、解释、Expected、Unknown 分开。动作、observation、runtimeValues 的值、应用和目标身份一致；消费者集合完整，每个实际变换有来源；无输出动作的空消费者可以合法，终点读值却不能丢 final output。合法重复输入保留，不能把看似重复的点击预先去噪成缺事实。

实际读值保留原类型、前导零、必要单位精度；预期答案只供比较，不能进入后续业务输入。记录候选失败必须确有失败，未尝试记录 not-run；不为选型表完整重跑已经有效的调用。

## 检查、拒绝与恢复

动作前检查目标唯一性、身份、状态、权限和必要预算；动作后检查回执、实际观察及后置。按既定标准逐项核验，不因为最终数字正确就忽略错误数据来源。完成部分工作不能冒充完整任务成功。

事实／读值缺失由本职责定向补采；输入包漏交已有资料先找协调者；业务含义／权限缺口回 S1；应用定位／读取规则失效回 application-engineer。原取舍属于 S7、业务解释属于 S8—S9，不在示范中替下游裁定。

unknown／partial 副作用保留并停止依赖动作，先核对实际效果，不能自动换后端、重放前缀或重复提交。原失败、原证据和已确认成果不覆盖。补采是新执行、新证据、新引用，注明支持范围；旧现场无法补证则保持未知。修复规则／政策后固定新输入，重核必要现场，仅继续获准且受影响的工作；已有有效示范不为了生成方法重新执行。

发布 handoff 时区分本次作业结束与 gate 通过，绑定方法、request、实际输入与全部实际产物；只有完整且可消费的成功范围进入 S7 正常路径。失败包可供诊断，不能转作成功示范。

## 三类方法样例

这些是方法练习，不是实际模型调用或真实桌面证据；真实调用必须提供上述固定材料，Expected 不给生产者补事实。

| 类别 | 输入／现场 | 应交付或拒绝 | 原因与接续 |
| --- | --- | --- | --- |
| 正常 | 获准合成教学场景：读取工单号字符串 `00128`，实际用 identity 输入查询框，读取状态并打印；输入／读值／目标记录齐全 | Dossier 保存 `00128` 原字符串、读源、实际查询消费者、实际变换与状态终点输出；记录真正使用的规则与选型状态 | 保留前导零；打印是终点消费者；这张教学表不证明真实执行 |
| 拒绝 | 只给“查询成功”截图及预期工单号，没有原始读值或实际消费者输入 | 不补造完整成功 Dossier；指出缺哪次读取、消费或来源，返回定向补采 | 最后结果相同不能证明中间输入真实；历史不可恢复部分保持 unknown |
| 拒绝未知副作用 | 查询之外的提交动作超时，无证据确认是否生效 | 保留原失败与 unknown，停止重复提交并请求获准状态核对 | 超时不等于未执行；切换后端不消除重复副作用风险 |
| 修复／复用 | 有效前段事实已冻结；只缺终点状态证据，且获准重新读取、确认无新业务副作用 | 保留原前段及失败，执行本次定向读取，保存新 evidence／attempt，限定其证明范围后重新交接 | 新读值不是过去时点的读值；不为补终点证据重跑整个任务 |
