# trace-distill：输入输出适用规格

S7 的正式字段与 S7 → S9 增量唯一依据：[共享合同](../../../../../docs/frameworks/agent-to-recipe-skill-contract.md)。本页定义怎样使用，不复制 schema 或新的状态。方法、规格、合同与实际输入分别绑定精确版本。评分及检查覆盖只引用 [validation-plan](../../../design/validation-plan.md)。

## 必需与条件输入

实际读取本次 request、TaskContract／生效计划、固定 Dossier／Raw Trace、关键读值与实际消费者证据、必要 AppProfile／业务政策。核对获准根、实际字节、hash、schema、任务、计划、应用与目标身份。旧事实可复用，但不能把别的任务结果冒充本次来源。

恢复取舍需要原失败与恢复相关事实；不要求 S9、Candidate 或 S12 成果。应用术语可辅助解释，不代替真实动作。非必需诊断材料可以省略；原始事实有关键缺口则定向补证，而不是读 Expected、完整聊天或最终代码填空。

## 从 S9 的需要反推 S7 必须交付

| S9 必须判断／产出 | 需要的信息 | 获准来源与 S7 交付 | 证据界限 |
| --- | --- | --- | --- |
| 必要步骤及顺序 | 实际动作目的、输入输出、前提、后置、验证、取舍理由 | Dossier／Trace＋合同 → steps 与 actionDecisions | 计划外必要动作不能自动 omit；未执行计划不能 retain |
| 值是什么 | 业务含义、类型、必要单位精度 | 固定合同政策／有来源说明 → runtimeValues 必要投影 | 一次观察不能推导通用业务政策 |
| 值从哪里实际取得 | 读动作、应用、目标、真实值与证据 | 原动作＋observation＋Dossier.origin 交叉核对 | 仅字符串相同不能证明读源相同 |
| 谁实际使用、怎样使用 | 完整原消费者、实际输入、实际变换 | 原消费动作 → consumerBindings，映射 producerStep／consumerSteps | allowedTransforms 不等于 actual transform；每个原消费者逐项保留 |
| 以后何时重读 | 有效期、失效与重新获取规则 | 固定政策及必要现场依据 → validity／reacquireOnFreshRun | 不能把历史值作为未来默认答案 |
| 目标之间什么关系 | 应用身份、读目标与消费目标关联 | 固定 Profile／关系证据，明确供下游读取 | ID 存在不证明关系成立 |
| 选型依据是什么 | 上游实际选择记录、契约、验证状态 | 原工作包定向记录由协调者明确交付 S9 | API 文档不证明实际选型；不从未来代码倒造 |
| 终点怎样交付 | 最终实际读取和去向 | 原事实＋合同 → 保留 terminal read／final output | 没有下一动作不能删除终点读取 |

资料可以由请求、主产物和明确补充共同提供，不强制把全部应用资料塞进 DistilledSteps。S7 的 dossierRef／sourceActionRefs 是历史 lineage；S9 不能沿其静默读取全历史。检查器可读全源只为比对，不能代替对 Producer 的必要材料交付。

## 作业、不变量与检查

先核对动作、observation 与 Dossier 的值和应用／目标身份一致，再核对完整生产／消费集合；矛盾回事实责任，不能选相信最方便的一份。每个受处理动作有且仅有明确取舍；保留所有必要读值、消费者、状态准备与有依据等待，禁止机械删除重复动作。合并不丢原动作、不偷换因果和数据顺序；异常恢复与成功路径分开。

事实、解释、Expected、Unknown 分开；runtimeValues 不变成输入参数默认值。保留字符串前导零。多个原消费者合并到同一步时，consumerBindings 仍保留每个 action 的实际输入与各自变换；无输出动作允许空消费者，终点值仍有 final output。

当前顺序检查仅覆盖 text／digit-string、identity／characters、明确原生产者和前向跨步数据关系。金额、分支、循环或同一步内部读后用等合法业务超出覆盖时记录 CHECKER_COVERAGE／专业审阅，不把业务改成单一历史答案。结构与引用通过不证明因果必要性或真实现场。

## 缺口与失败接续

包中漏交已有获准材料先交协调者；原事实／读值冲突回 S3—S6；政策缺失回 S1／原政策责任；关系或规则缺失回应用工程；S7 错投影或错取舍由 S7 修。Human 资料保持 Human 原来源，按原合同交对应采集／审阅／增强责任，不追认为 Agent。

partial／unknown 副作用不能进入正常成功路径，先核对实际效果。保留原失败与 Dossier，修订只生成新 DistilledSteps；下游 Procedure／Candidate／Qualification 按影响重验。只补交 S9 材料且 S7 输入／方法／合同不变时，复核并复用 S7 字节，不再次生产；输入或方法改变则不得复用旧结果。每次新尝试新目录、预算累计、不重放业务。

## 正常、拒绝与修复／复用样例

以下是方法练习；实际确定性调用见所属测试域与质量记录，不是模型或桌面证据。

| 类别 | 已提供内容／变更 | 应交付／拒绝及理由 |
| --- | --- | --- |
| 正常 | 合成 `0040` 原读取＋两个实际消费者，一个 characters，一个 identity；两消费者合法相邻合并；终点状态读取 | 保留 `0040`、两项 consumerBindings 和各自实际输入；合并步骤不丢两个原动作；状态保留 final output |
| 正常合法省略 | 上例没有非必需诊断说明；查询动作没有业务输出 | 仍可交付必要步骤；无输出步骤空消费者合法，不按空数组一律拒绝 |
| 拒绝 | 读值相同但原 action 的应用／目标与 observation.origin 不同，或 Dossier 漏一个原消费者 | 拒绝投影，回 S3—S6 核对实际来源，不能只比较字符串或照抄漏项集合 |
| 修复 | S7 错把一次必要消费 omit，原事实完整 | 原 Dossier 不变；S7 修取舍与映射、发布新版本，再让 S9 重消费，不改历史 |
| 复用 | S7 已通过，只缺 S9 的实际选型记录；方法／规格／源输入未变 | 补交固定选择记录，重新检查原 S7 并保留相同字节，只继续 S9；保留第一次失败与累计预算 |
