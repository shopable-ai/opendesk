# trace-distill｜失败处理与接续

## 先保全事实

停止依赖缺项的正常交接，保存原输入/方法版本、失败、最后可信状态、已知副作用及真实派生草稿。S7 默认只读；动作可能已经发生而效果未知时，不自己重放、不重建历史、不以重试获取熟悉答案。

区分 fail（已有反证）、blocked（必要条件不足）、not-run（相应检查/执行未发生）；unknown/partial 如实保留，不改名成功。失败可以附局部成果，但不能把原请求缩小后称整体 pass。

## 精确返回原责任

| 问题 | 返回责任 | 必须指出的缺项/修复内容 |
| --- | --- | --- |
| 已有获准材料未交付、不可读、ref/hash/根不符 | 协调者 | 哪个固定材料、实际缺字节/权限/版本、影响哪个消费 |
| 历史动作、读值、目标身份或消费者事实缺失/冲突 | S3—S6 task-demonstrate | 精确 action/value/observation、矛盾字段和所需证据；新采集不得回填旧历史 |
| 目标/成功标准/授权或值政策缺失 | S1/原政策说明者 | 原要求、含义/类型/单位/变换/有效期中缺哪项 |
| 应用关系、目标映射或状态/操作规则缺失 | application-engineer 的适用 S2/S10 模式 | 相关目标、读取/消费关系、已知观察和工程缺口 |
| 必要动作被删、取舍/来源映射/值投影有误 | S7 trace-distill | 保持原事实，修改哪些 actionDecisions/steps/runtimeValues 及原因 |
| 正确 DistilledSteps 被下游错误解释/参数化 | S8—S9 procedure-synthesize | 正确来源、错误 Business Step/数据映射；不新建第二份原动作取舍 |
| JS 未实现已确认过程、顺序/错误停止有误 | S11 recipe-build | 已确认步骤/规则与对应代码缺陷；不改历史使之适配代码 |
| 验收范围或 Oracle 错误、检查器覆盖不足 | S12/相应验证责任 | 哪个声明超范围、缺什么判据/证据/检查覆盖；不修改事实迎合工具 |

效果 unknown/partial 的原动作先交事实/现场责任确认副作用；恢复候选无法证明触发/安全性时留未决，不提升为可执行分支。Human 材料保留 Human 来源，定向交其原采集/审阅/增强责任，不追认为 Agent 示范。

## 失败返回最小内容

在既有 handoff/nextRequest 中给出：原 task/plan/scope；实际方法/规格/合同和输入版本；状态、失败动作/值及 evidence；已完成的真实草稿；受阻的步骤/消费者；已知副作用；返回责任；缺哪项事实/政策/关系/映射；下一安全动作；剩余预算和重验范围。不新建失败状态机，也不只写“需要更多上下文”。

例如：原读动作与 observation 的 applicationId 不同，字符串却相同。应返回 S3—S6 核对这两项原始来源，停止该值及后续消费者的正常交接；不能自行选一项、将值常量化或换成 Expected。

## 修订、复用与停止条件

S7 自己漏投影而事实完整：只生成新 DistilledSteps，保留 Dossier/Trace 字节与原失败；按依赖让 S9 重消费，必要时传播至 S10/S11/S12。修取舍不等于获得桌面执行许可。

只有 S9 缺少已存在的选择记录，而 S7 输入/方法/规格/合同完全未变：先补交固定材料，重检并复用原 S7 字节，只继续受影响的 S9。任一影响性输入或方法变化、旧文件被改或语义不同，都不能沿用旧通过标签。

每次新尝试新目录，累计时间/重试预算，保存原失败和旧资格。没有新证据的同类失败、预算不足、必要授权缺失或无法确认副作用时停止；不无限循环。新试执行形成新的 execution/Dossier，不能用其成功覆盖历史缺口。
