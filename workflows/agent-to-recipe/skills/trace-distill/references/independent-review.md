# trace-distill｜独立审阅基线

只审阅本 Skill，不用整体 Workflow 评分代替。检查七项：方法正确性、输入输出完整性、责任边界、失败处理、案例解释、下游消费、迁移复用；各 0—100，等权均分仅是本 Skill 的文档/方法审阅结果，不是运行通过率或模型成功概率。

## 必答问题

| 维度 | 独立审阅者必须能回答 | 不能接受的替代 |
| --- | --- | --- |
| 方法 | 每个动作凭什么 retain/merge/omit/recovery；状态和数据怎样无损 | 动作减少了、最后答案对了 |
| 输入输出 | 哪些真实材料才足够进入，完整 DistilledSteps 应交付什么 | 只列文件名，或要求未来 Procedure |
| 边界 | S7 的历史取舍与 S8—S9 的业务解释有什么不同 | 由最终 JS 倒推，或在 S9 另维护 disposition |
| 失败 | 缺事实、政策、关系和自身投影各回哪里，如何安全接续 | 统一要求重做业务，未知副作用直接重放 |
| 案例 | 能否逐项解释首读、第二次清空、重复数字以及终点读取 | 只列六个步骤，不展示原动作与理由 |
| 下游 | S9 是否已实际取得值含义、读源、全部消费者及实际变换 | 凭 lineage 猜测或静默回读全历史 |
| 迁移 | 文本/前导零/多消费者/等待/恢复怎样沿用，覆盖之外怎么办 | 只支持 A/B 标识和 Calculator 常量 |

缺必要来源、允许 Expected 替代实际值、动作/消费者被静默丢弃、恢复假冒正常路径、未知副作用可放行，任一成立就不能评为达到 95；先修具体方法缺陷。文件齐全和测试通过不是补分理由。

评分记录须给逐维依据和扣分项，并区分“已做内容审阅”“实际模型独立使用”“无历史上下文交接”“真实应用执行”。后三者未做即 not-run，不能用此处文档分数填充正式验证计划或 QualificationRecord。
