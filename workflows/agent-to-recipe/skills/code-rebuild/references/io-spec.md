# code-rebuild：输入输出适用规格

本页是 S11 可选代码评审与改进的消费规格。字段、版本与候选失效唯一依据：[共享合同](../../../../../docs/frameworks/agent-to-recipe-skill-contract.md)；方法设计和评审只采用 [validation-plan](../../../design/validation-plan.md)同一规则，不另建状态或评分 schema。

## 必需与条件输入

实际取得本次评审目标／允许变更范围、精确代码及 helper 字节、入口／工作目录／依赖、相应 CandidateManifest、固定合同与过程、适用 Profile／操作规则和当前 API 契约。逐项打开正文，核对获准根、版本、hash、来源与范围；“与上次相同”或文件名不能代替字节绑定。

已有资产缺完整历史时按原 continuation 限定范围审阅，不补造示范。旧资格为条件证据，仅支持其固定候选与环境；不要求先有最终资格结论才能做候选静态检查。无关历史、整份 Raw Trace、全部 API 和未使用依赖可省略。

## 反向消费对应

| 本阶段与下游必须判断 | 信息来源 | 必须交付／限制 |
| --- | --- | --- |
| 原代码做了什么、是否符合业务 | 精确源码＋合同＋Procedure | Business Step 到函数／代码区域映射；函数名或正则命中不证明可达性 |
| 中间值是否真的被使用 | 返回值、赋值、分支和真实输入来源；必要实际测试 | 数据流发现与证据；读过 firstResult 却输入固定数仍属关键失败 |
| 能否安全用当前 API | 固定 canonical／约束、Profile 与平台范围 | API／异步／错误处理／停止与副作用判断，不发明能力 |
| 修改收益与成本 | 明确改进目标、原缺陷与风险、依赖影响 | 每项改动的位置、理由、收益、代价；无收益则保留 |
| 新候选需验什么 | 实际字节差异、受影响要求与依赖、旧资格范围 | 新 Candidate 与重验要求，或固定 baseline-retained 结论 |

## 不变量、检查和接续

事实、解释、Expected、Unknown 分开。保留业务行为、运行时值生产／消费、类型／单位精度、前导零、停止与权限边界。不要为“可读性”删除必要状态准备或结果读取；代码变少必须说明原逻辑保留、移动或删除的去向。不得从代码反向发明过去选型、执行或资格。

静态审阅按业务／数据正确性、安全副作用、API、异步顺序、有界失败和可维护性依次进行；适用时调用 `--through candidate`。检查器只支持限定源码形状，不证明任意 JS 等价性；实际测试、静态推断、旧资格分别记录。输出 baseline-retained 或 candidate-revised 是评审处置，不是新 handoff 状态。

缺包先找协调者；关键业务含义回 S8—S9，动作取舍回 S7，应用规则回应用工程，实现问题由本职责／recipe-build 修；Agent／Human 历史事实按原来源返回。部分检查保留缺口，不以总分掩盖关键错误。副作用未知先核对，不从优化直接进入重放。

保留原候选与失败，修改字节或关键依赖后固定新 Candidate，列重验范围交 S12；未变化只记录保留理由与当前适用边界，不制造新候选或新运行资格。评分绑定实际方法、本规格、候选、范围和同一真实评审者，未运行不填运行分数。

## 正常、拒绝与修复／复用样例

以下为方法练习，不是独立模型／真实桌面结论。

| 类别 | 实际应提供的材料 | 应输出／拒绝及原因 |
| --- | --- | --- |
| 正常评审 | 固定候选、Procedure 和 API 已交；请求查重复逻辑和错误处理 | 给逐位置发现、数据流与改动收益；仅有依据处修改，发布新候选和重验范围 |
| 拒绝越界 | 请求把旧定位逻辑换成未记录的新 fallback，并同时放宽失败标准 | 拒绝越界变更；规则回应用工程、标准回需求责任，不以优化授权扩大业务 |
| 拒绝假数据依赖 | 源码读取 firstResult，但下一步输入固定 `110`，旧测试最终得到 `660` | 判关键数据关系失败；最终数字正确不能抵消；修正实际变量绑定后重验 |
| 修复 | 过程正确，源码漏 await 导致后续提前读取 | 定向修异步顺序；保留原失败，冻结新候选并重验相关步骤及必要回归 |
| 保留复用 | 原候选符合本次目标，没有证据表明重构有收益 | baseline-retained，固定原 hash 与保留依据；旧资格仅按原范围引用，不宣称新 live |
