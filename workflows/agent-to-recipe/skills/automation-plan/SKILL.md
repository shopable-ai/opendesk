# automation-plan｜明确任务与制定计划

## 适用任务与边界

本方法负责 S1：用户原始要求 → TaskContract＋WorkPlan。适用于首次规划、执行中的有来源修订，以及已有普通 JS／成果的限定范围接续。不执行真实示范，不替应用工程确认现场可行性，不生成未来读值或资格结论。保留 S1—S12、G0—G7 和普通 OpenDesk JavaScript；现有 Recorder／Replay 可以提供明确来源的资产，但不因此成为本次 Agent 示范。

每次作业先读取本方法及 [输入输出适用规格](references/io-spec.md)，再按本次范围读取 [共享合同](../../../../docs/frameworks/agent-to-recipe-skill-contract.md)的调用、主产物和接续条款。业务任务拆解需要进一步方法时，按需读 [任务求解方法](../../../../docs/frameworks/automation-problem-solving-framework.md)与 [任务分解设计](../../design/task-decomposition.md)，不要求通读全部工作流。

## 进入条件与必要输入

必须有本次请求、实际可读的原始用户任务与授权来源，以及范围、工具、文件根目录和预算。首次 `plan/create` 不要求先有 TaskContract；共享合同允许其 contractRef／planRevision 暂空，但原始来源不可空。`plan/revise` 另需旧合同／计划、明确变更来源、当前进度与受影响成果；已有资产接续再提供资产来源和允许处置范围。

按 request 的固定引用打开必要资料，核对实际内容、hash、schemaVersion、任务身份和权限。完整聊天、模糊路径、“已授权”字样、Expected 或将来的 Procedure／Candidate 都不能填补缺输入。模式名称沿用现有合同；方法文件不表示宿主已经自动加载或接受新模式。

## 具体作业方法

1. **恢复来源与当前范围。** 分开原始要求、用户已确认决定、Agent 解释、候选方案和未知。接续任务先核对有效旧产物；不重写原始要求、不追认旧运行是新示范。把这次要求转成一句可观察的业务目标，明确对象、起点、终点和不做的事。
2. **定义正确性与安全边界。** 为每项成功条件建立稳定 criterionId、预期、证据来源及所需证明强度；同时定义失败、停止和支持范围。明确允许读取、写入、桌面输入、上传或其他副作用的对象与范围。没有授权的动作不进入可执行计划。
3. **分类业务信息。** 区分用户输入、配置、Secret 引用、运行时派生值、Expected 和 Unknown。值的业务含义、必要类型／单位／精度、允许变换及最终交付去向应有来源；实际读值与实际消费者留给执行阶段记录。不能用历史样例或预期代替未来读取。
4. **分解为业务工作包。** 按可解释、可验收、可接续的业务子目标建立任务树和依赖，而不是把 Skill 名称列表当作业务计划。每个近期工作包有输入、前提、输出、成功标准、停止边界与预算；远期不确定项保留 Unknown，按需渐进细化。优先检查会推翻后续路线的高影响未知。
5. **形成操作计划与检查点。** 将近期业务目标落实为“准备怎样做、需要什么、预期看到什么、怎样判断、失败怎样停止”；不编造全部点击或未经观察的窗口身份。发现关键可行性缺口交 application-engineer／discover；规划许可不自动升级为真实操作许可。
6. **做反向覆盖检查。** 从 S2、示范、S9、生成和资格的必要判断反查来源：每个要求有工作包和验收去向；每个计划动作有目标及权限；每个必要数据决定有政策或明确缺口。确认没有循环依赖、无法观察的成功标准、无界重试或把关键含义留给下游猜。
7. **保存并交接。** 写出 TaskContract 与 WorkPlan，遵守共享合同的最小内容。需要可读视图时只引用同版主产物。固定实际字节及 hash 后发布 handoff，注明实际消费的输入、方法版本、门禁范围、未决项、预算和副作用状态。正常消费者使用本次已发布的固定版本，而不是盲读 latest。

## 修订与有效成果复用

只在有真实目标变化或缺口时修订。核对变更来源与权限，保留旧合同、计划、已发生事实和原失败；用新 revision、changeLog／planDelta 记录理由与影响。由依赖关系确定哪些成果需要重验，未受影响且仍有效的应用资料、示范和代码不为凑成果重做。

请求漏交已有获准材料时，先向协调者补交；业务决定或授权缺失时返回用户／S1 的明确责任。补交或修订后固定新输入，重新执行相关检查，再继续受影响环节。已发生或状态未知的副作用先核对，不把计划改版当作重放许可。

## 输出、检查与完成含义

输出 TaskContract＋WorkPlan，可附同版任务摘要／操作计划视图；完整字段、引用和状态仍由共享合同唯一维护。检查要求覆盖、业务含义、授权、验收可观察性、依赖、预算及下游可读性。正常、拒绝、定向修订和不改版复用的例子见 io-spec。

只有本次规划范围的检查通过，才发布相应 gate.pass；这不表示应用认识、示范、代码、宿主或业务资格通过。部分完成保留明确缺口与有效成果，不缩小原请求来伪装全部完成。失败分类沿用 F0—F10，nextRequest 指明需要补什么、由谁补和从哪里恢复；不增加平行状态体系。
