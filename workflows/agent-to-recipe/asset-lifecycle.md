# 从候选到可复用资产

先沉淀能被别人理解、配置、验证和安全使用的程序，不先建设商城、Registry 或新包管理器。本文是 S12 之后的交付与维护约定，不新增开发阶段或 Runtime 状态。

## 1. 哪些内容可以成为资产

普通 JS Recipe、经过独立验证的组合能力、应用 helper、脱敏的 AppProfile、必要配置说明和验证样本都可能复用。Agent 方法 Skill 与业务资产分开维护；未经审查的运行记忆不回写共享 Skill。

活跃任务和真实运行资料留在 `.runtime/`。需要长期保留时，经授权选取可维护源码、说明、脱敏样本及必要资格摘要，进入项目认可的源码／发布位置。不能把可清理 execution 路径当永久下载地址，也不把所有截图、聊天记录和凭据一起打包。

## 2. 最小资产说明

可以先用随源码维护的 Markdown 说明，不要求新增 manifest 引擎。

| 项目 | 交付时必须清楚 |
| --- | --- |
| 身份与来源 | 名称、版本、负责人、源码／内容 hash、来源和维护方式 |
| 能解决什么 | 业务目标、输入输出、支持和不支持的场景 |
| 怎样运行 | 实际工作目录、普通入口命令、输入／配置、Secret 引用方式 |
| 依赖与兼容 | OpenDesk／应用／OS 范围、helper 版本、模型或在线服务依赖及限制 |
| 权限与风险 | 可读写对象、发送／提交等副作用、批准与停止条件 |
| 验证与证据 | 对应候选版本、实际环境、场景、qualification 范围、未测项与可用的脱敏证据 |
| 复用与维护 | 失效条件、恢复边界、升级影响、重新验证与撤下方式 |
| 分发条件 | 授权与许可证、第三方依赖要求、隐私处理、已知成本或未测成本 |

未知就写未知，不自报性能或跨平台通过。hash 只证明内容一致，不证明来源可信；取得资产不等于授权它发送、删除或读取秘密。

## 3. 晋级与复用

当前候选先通过声明范围的 S12，再审核脱敏、依赖、说明和分发许可。需要团队共享时，让另一使用者在已声明环境中从说明与参数独立运行；只复制文件而未验证不能扩大支持范围。

从单任务提炼通用 helper 需要相应复用证据；一次成功可以交付受限资产，但不能宣称适用于所有聊天软件或所有平台。所有组合依赖固定版本，依赖变更要分析受影响业务条件并重新验收。

出现应用漂移、危险失败、证据失效或版本不兼容时，暂停受影响用法，保留旧版本与限定结论，定向修复后再发布。升级不是静默改写已运行任务；未确认副作用不得通过回滚代码重复执行。

## 4. 平台后续边界

当已有多项可重复交付的资产，再建设检索、安装、版本依赖、权限展示、资格范围、撤下／升级和运营能力。平台只是资产分发与治理层，消费者仍可通过普通 JS 入口运行，不要求所有资产依赖 Agent 或某一外部编排器。

在平台出现前就把可移植源码与私有运行证据分开：发布说明应保留来源和验证范围，但公开包不携带客户数据或有效凭据。需要重验的材料由获准证据存储保留，清理后不能继续声称可审计。
