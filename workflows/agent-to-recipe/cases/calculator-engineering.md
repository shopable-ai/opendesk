## 2. 工程描述分别有什么用

| 内容 | 解决什么问题 | 不负责证明什么 |
| --- | --- | --- |
| CandidateManifest／完整 hash | 固定实际源码、入口、依赖、上游和支持范围 | 不证明业务正确或历史执行发生 |
| request／handoff | 固定这次交给谁、允许读什么、产出什么及状态 | 不自动提供桌面授权，也不替代原始事实 |
| QualificationRecord | 记录同一候选在预先确定范围的实际验收 | 不授予另一候选或未测场景资格 |
| 完整性检查器 | 检查其覆盖的文件、引用、版本和结构关系 | 退出码 0 不等于语义正确、真机成功或视觉通过 |
| 历史记录 | 保留失败、撤回结论、设计原因和修订范围 | 不能把旧“当前”当成新任务状态 |
| 截图、回执与读取 | 从不同角度支撑实际行为和结果 | 任一单项都不能独自证明完整因果链 |

这些材料需要保留，但不应挡在任务与数据流前面。正式内容 owner 仍是 Workflow、共享合同、各 Skill 和实际执行记录；案例只提供可读导航。

## 5. 保留的设计选择与适用边界

| 设计问题 | 保留的决定／理由 | 失效或补证条件 |
| --- | --- | --- |
| 是否必须有 Calculator 类 | 优先普通 JS 和已有框架 API；只有真实组合、转换或校验价值才加普通函数 | 不为提高评分强制应用对象；有复用收益再论证 adapter |
| 区域、目标与坐标 | 分开区域、组件语义身份、当前几何；相同数字可能出现在结果、历史或按钮 | 身份／布局漂移需重新核对；不沿用历史坐标 |
| 按钮矩阵 | 保留为候选，不能默认 3×4 或均分整个窗口 | 需证实行列、间距、留白、跨列键、当前范围和失配行为 |
| 文字／结构／图像定位 | 根据当前权限、契约、现场证据和代价选择，不预设全局最优顺序 | 历史某次失败不等于另一候选本次已失败；无实测不声称更快 |
| 单按钮、序列、表达式、一次计算 | 分别是动作、顺序、字符转换、准备＋求值＋等待＋读取 | 不强制四层函数；等号只能由明确的一层负责，不能重复追加 |
| 清空、读取与等待 | C／AC 和清除全部运算并非同义；回执、显示 0、可继续状态分别核对 | 不能把错误文字、空白或不支持格式转为默认数字；固定等待不证明 ready |
| 运算符与格式 | 当前固定输入用 `×`，不把 `*／x` 静默当作同一控件；保留原始字符串 | 有来源的局部 OCR 别名是另一种定位规则，不授权全局字符替换；新范围另验 |
| 普通 JS 与代码改进 | 生成者必须自检；独立 code-rebuild 是 S11 内的可选职责 | 修改候选要重新核对资格；不新建 Compiler／Runtime／可执行 IR 掩盖缺口 |
| 复用与恢复 | 新生成、已有脚本改进、合格脚本不改、定位局部修复分别选择真实入口 | 不把局部补证说成完整新示范；效果 unknown 时不盲重试 |

固定案例不能证明任意混合运算的优先级、负数／小数／指数、任意输入长度、所有按钮组合、窗口移动／重排、其他平台或恢复策略都受支持。合法变参、旧状态污染、歧义／遮挡／缺目标、空读／错读、错误 Expected、顺序中断及同版重复运行，均按 requested scope 单独安排并记录，不用“接口接受参数”代替参数化资格。

能力发现沿 [Agent API 入口](../../../docs/api/agent/README.md)到选中方法的 canonical 契约；S8—S9 收敛能力决定，S11 绑定，S12 验收。历史 r003 的 API 取舍和 r009 的实现可供带来源复用，但不是新 Agent 的预制发现答案。
