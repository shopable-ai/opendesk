# S7：完整复盘与必要路径提炼

责任 Skill：[procedure-synthesize](../../../prompts/automation/agent-to-recipe/procedure-synthesize/SKILL.md)。本阶段默认不操作桌面、不修改代码和原始证据。共同规则：[阶段约定](README.md)。

## 输入与进入条件

新生成链读取 S6 已通过完整示范门禁的 dossier、冻结合同、相关 AppProfile 和精确证据引用。接续链可以改为读取与合同匹配且已固定路径／hash 的既有代码、范围明确的事实 dossier 及适用证据；它不因此取得完整示范身份。其他失败资料只可用于明确授权的诊断。

## 本阶段要做的事

先核验来源，再重建任务叙事：实际目标、必要前置、动作效果、业务数据及其消费者。把观察事实、Agent 解释和待验证假设分开；只给可审查的理由摘要，不要求私有思维记录。

接续链先建立代码到业务的逐项映射：代码位置／调用、拟对应的业务目的、前后状态、数据生产者／消费者，以及支持或反驳它的 dossier／执行证据。每项用文字给出证据等级和理由，至少区分本次实测（注明参考执行或新示范）、历史支持、仅由代码推断／尚未验证；这是分析强度，不是新增 Gate 或状态值，公共交接仍遵守共享合同。

复核 S5 初步分类，判断每个动作为何保留、排除或移入异常经验。不能简单删除所有失败动作，也不能把所有成功调用都保留。必要的状态准备、取数和验证属于因果路径。

单次示范无法证明的恢复、循环与替代路径列为未知。缺必要信息则提出指定节点的补采请求，不自行调用桌面重做整件事，也不补出看似合理的事实。

## 必须保存的输出与消费者

保存 `analysis.json` 或等价可引用分析：任务叙事、causalSuccessPath、动作保留／排除理由、代码到业务映射及逐项证据等级、recoveryCandidates、openQuestions 和 revision。

每条关键判断回指动作／证据；原 dossier 不修改。消费者 [S8](08-decompose-business-steps.md) 用必要路径确定业务步骤边界，不需要读全部历史聊天。

## 通过、阻塞与回退

路径可解释，必要依赖没有被删，且每项结论不超过其证据等级、未决问题不影响声明范围内的后续分段时通过。代码与 dossier 无法匹配时不能反向提炼；影响业务理解的缺口返回 S6／定向补采，合同与事实矛盾返回 S1，经协调者处理。

## 下一阶段与最小验收

进入 S8。检查：包含探索／失败／恢复的示范能被提炼成清楚必要路径，并保留排除理由；未知事实不会因模型自信而被升级为已确认。
