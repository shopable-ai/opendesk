# S12：独立 Fresh Run、修复路由与交付

责任 Skill：[recipe-qualify](../../../prompts/automation/agent-to-recipe/recipe-qualify/SKILL.md)。质量规则：[G0—G7](../../../docs/quality/gates-and-evidence.md)、[F0—F10](../../../docs/quality/failure-taxonomy.md)。共同规则：[阶段约定](README.md)。

## 输入与进入条件

读取冻结合同或获准测试目标、确定候选、测试场景、允许起点和相关环境／授权，并按共享合同填写 `qualificationScope`；lineage 取值及语义只以共享合同为准，不在本卡重复定义。`requested / exercised / qualified / excluded` 必须是实际业务主张、场景和边界，不能只写 lineage 标签。

只验固定参考脚本时可直接进入本阶段，不伪造 S1—S11。接续最小修复读取其 S1、相关 S7—S11 有界交接；共享合同允许的严格未改复用可以没有 S7—S9 过程，但必须有 S1 收养、固定候选、适用证据、无需反向提炼理由和 S11 清单。完整新生成仍须具备 S1—S11 的有效交接以及 S3—S6 当前新 Agent 示范的完整 pass，任何接续证据都不能代替。

## 本阶段要做的事

先核对真实 binary、候选路径／hash、公开命令和工作目录、能力、权限、预算与停止方式。使用正常 OpenDesk 入口，新 execution 不依赖示范残留现场／变量／答案。Fresh Run 指新的 execution 与重新核对的动态现场，不要求删除已封存知识、AppProfile、过程、代码或证据；这些资料可以指导验收，但不得向运行注入示范业务值或旧答案。

按照预先确定的结果条件检查本次真实业务对象、输入、观察值、数据消费与最终结果。不能只读 passed=true 或退出码。单独记录执行结果和负向测试判定，正确拒绝可以是测试 pass，但该业务 execution 仍然 fail。

运行授权范围内的 Fresh Run、不同输入、旧状态污染和必要反例。无前序聊天交接是独立测试项目；不能用同一 Agent 的记忆冒充。对新候选必须验证新候选本身，既有 gate 的参考路径成功不能替它背书。

发现问题只提出证据化修复请求，由责任 Skill 发布新版本，再重验受影响场景。验收者不在原尝试中静默改候选或成功标准。预算耗尽、用户停止、权限或关键结果不明时停止依赖动作。

若最小候选先在任务位置通过，应用到正式既有脚本仍需独立授权；应用后固定最终路径／hash，并至少重验受影响场景。候选通过不能替最终落盘版本背书。

## 必须保存的输出与消费者

保存 `qualification.json` 和 handoff：scope、合同／候选版本、实际命令与目录、环境范围、各场景期望／实际、executionId、证据、失败分类、修复请求、未测项与限制。

通过后协调者交付明确版本、运行方式与验证范围。源码发布另按授权执行；文件存在、静态检查、reference-only 通过、continuation-chain 通过、new-generation-chain 整链通过分别报告。

## 通过、阻塞与回退

只有本次候选和所声明范围有足够证据才能通过；较窄 scope 的 pass 不得升级为较宽链路结论。缺环境为 blocked／未测，不模拟桌面；缺证据返回 S6／生产者定向补采；业务过程错误回 S7—S9，应用问题回 S10，代码问题回 S11。

## 结束与最小验收

终止本次尝试或交付，不无限回到起点。检查：假成功、旧答案、错误对象及缺证据均被拒绝；换测试应用只改变目标资料和测试案例，不复制十二个阶段或新增应用专属 WORKFLOW。
