# S3：真实操作与关键数据即时保存

责任 Skill：[task-demonstrate](../../../prompts/automation/agent-to-recipe/task-demonstrate/SKILL.md)。范围：一次业务节点或获准的小段操作，不代表完整示范成功。共同规则：[阶段约定](README.md)。

## 输入与进入条件

读取冻结合同、当前工作包、适用 AppProfile、获准业务输入、上一节点已验证的输出及其证据。确认本次桌面操作拥有权、停止入口与剩余预算；重新观察会变化的对象、页面和焦点。进入时明确本次材料是历史资料、固定版本既有脚本的当前参考执行，还是当前合同下的新 Agent 示范，不把三者合并成一种来源。

## 本阶段要做的事

围绕当前子目标，记录简短操作目的、目标依据和预期变化，然后使用 OpenDesk 实际工具或短脚本执行。动作参数只保存必要且脱敏的部分，不记录私有思维过程。

历史资料只能作为有来源的输入；当前参考执行记录实际脚本路径／hash、场景和本次观察，但不改写成 Agent 亲自探索出的动作；只有 Agent 在本合同和授权下新执行的步骤才进入新示范链。三类材料可以相互核对，不能互相冒名。

每个重要动作记录稳定 actionId、执行关联 ID、目标／前置状态、实际工具调用、原始返回、时间关系和证据引用。调用无异常只表明执行层结果，不自动升级为业务 pass。

**读到关键业务值就立即保存**：名称、类型、实际值、来源、证据、后续消费者、有效条件，以及 Fresh Run 是否必须重取。尚未验证的值保留 pending verification 的事实说明，不能用期望值填空或交给高风险后续动作。

记录动作是否可能已经产生副作用。中断或错误也保存已有观察，不能等任务结束再凭聊天回忆重建。

## 必须保存的输出与消费者

保存动作／观察记录和 runtimeValues 草稿，可使用本次 attempt 中的 `actions.ndjson`、`runtime-values.json`，或明确引用已有 execution 日志和结果。名称是场景产物建议，不是 Runtime 自动生成承诺。每份引用同时保留上述来源角色与适用时间；具体引用和范围字段沿用共享合同。

交给 [S4](04-verify-action-results.md) 的是指定动作、原始结果、预期后置条件和证据，不是一句“已完成”。跨调用前封存所引用版本；正在追加的日志不得伪称 hash 已固定。

## 通过、阻塞与回退

本阶段只对“本次声明来源的动作事实与必要数据已保存”判定，不能发布完整示范 pass。历史资料或参考执行记录无论多完整，也不能单独标成新 Agent 示范。结果不明时先由 S4 核对，不直接重做；身份或状态失效返回 S2，授权问题返回 S1。

## 下一阶段与最小验收

每个重要节点进入 S4，而不是执行全部动作后统一补验。检查：在此刻中断，另一执行者能判断执行了什么、观察了什么、哪项仍未知，且不会因缺成功记录盲目重做副作用。
