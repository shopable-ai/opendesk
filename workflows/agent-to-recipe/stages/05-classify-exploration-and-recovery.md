# S5：探索、错误与恢复的初步分类

责任 Skill：[task-demonstrate](../../../prompts/automation/agent-to-recipe/task-demonstrate/SKILL.md)。共同规则：[阶段约定](README.md)。本阶段是执行期间的标注与控制，S7 才做完整因果复盘。

## 输入与进入条件

读取当前子目标、S3 动作事实、S4 验证结果、此前尝试关联、剩余预算及授权，并保留历史资料／当前参考执行／新 Agent 示范的来源区分。不能只看工具是否报错来分类。

## 本阶段要做的事

把节点初步标记为 business、setup、state-preparation、verification、exploration、off-task、error、retry 或 recovery，并写明简短依据及原动作引用。

保留建立起点、提供业务数据和验证结果的动作；它们不一定直接改变最终业务对象，但可能是必要依赖。标记 retryOf／recoveryFor 等关系，不把重复尝试推断为未来必然循环。

对历史资料只能分类其记载内容，对参考执行只能分类可观察到的脚本行为；不得仅凭既有代码中的分支反推出 Agent 实际探索、误点或恢复。新示范的探索／恢复关系仍须由本次动作和证据支持。

依据实际效果、动作风险和预算决定：继续下一业务节点、等待并回 S4、定向观察回 S2、允许的有界重试回 S3，或停止。无新证据的相同失败、预算耗尽、用户取消或结果不明的高风险副作用必须停止依赖动作。

## 必须保存的输出与消费者

保存带来源边界的分类映射、retry／recovery 关联、未决问题和下一决策，可使用 `classification.json` 或同一已版本化资料中的明确字段。原始记录不可删除或改写；允许 S7 基于更完整证据修订分类解释，但不能升级证据来源。

新发现可能改变工作包时提出 planDelta：原因、预期新步骤、影响的依赖与权限边界。只有协调者更新全局计划；生产者不能自行改用户合同。

## 通过、阻塞与回退

需要当前节点事实及验证能够被解释，并有明确安全的下一入口。分类完成不是任务完成，也不是所有失败动作都可从正常路径删除的证明。

## 下一阶段与最小验收

尚有业务子目标时回到 [S3](03-demonstrate-actions.md)／S4／S2；目标看似完成后进入 [S6](06-close-demonstration.md)。检查：误点和重试被保留为反例，必要清理／取数／验证没有被错当噪声删去，且不存在无限回环。
