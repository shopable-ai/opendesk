# S11：直接生成普通 OpenDesk JavaScript

责任 Skill：[recipe-build](../../../prompts/automation/agent-to-recipe/recipe-build/SKILL.md)。本阶段是原 S11 在路线 A 的实现，不构造 Recorder IR，不要求 Compiler。共同规则：[阶段约定](README.md)。

## 输入与进入条件

新生成链读取冻结合同、S9 完整过程、S10 适用 AppProfile／helper、实际公开 API 与计划输出位置。接续中的最小修复读取 S9 对修复范围完成的过程，并同时读取固定路径／hash 的既有实现及代码映射。只有共享合同允许的严格 `reuse-unchanged` 例外可令 `procedureRef` 为 `null`；此时改读冻结合同、固定实现、适用证据和明确的无需反向提炼理由。所需定位或验证能力仍未知时返回对应环节，不边生成边发明 Runtime 接口。

## 本阶段要做的事

将业务步骤组织为普通 JS 函数和清楚的数据流：参数校验、应用／状态确认、真实操作、运行时读取、后续消费、业务断言、证据和失败处理。保留必要准备与验证，移除探索绕路。

核对实际方法名、参数、返回值、异步语义和入口能力。遵守当前加载限制，不假定 Node.js、import／require、Execution.resume 或专用 Recorder 入口存在。

期望值只用于断言；不使用示范答案、eval／Function 或内部算术替代任务要求的真实业务取数。失败必须与已有 Runtime 的失败语义一致，不能吞错后正常返回。

候选保存到本任务获准目录，不覆盖既有参考脚本。清楚声明在线模型／OCR 等依赖，允许输入范围、运行环境和风险边界。

接续链有两种诚实结果：若既有实现与当前过程及公开 API 一致，可不改文件，直接把该固定路径／hash 登记为待验候选；若确需修改，先固定 baseline 和理由，在获准候选位置制作最小差异，不先覆盖 baseline。候选经 S12 通过后，只有另有明确授权才应用到正式路径；应用后的实际路径／hash 必须作为新版本再次由 S12 验证。不能把“重新生成”写成未发生的工作。

## 必须保存的输出与消费者

保存普通 `.js` 和 `candidate.json`；未改登记时可直接引用既有 `.js`。记录实际脚本路径、内容 hash、工作目录、可复制的一行正常入口命令、输入／配置契约、依赖及上游版本、支持范围、是否未改登记或基于 baseline 的最小候选、未决事项。字段与版本引用沿用共享合同。

做过的静态检查如实记录；未执行桌面验收不得写已通过。最后发布候选范围 handoff，由 [S12](12-qualify-and-deliver.md) 验证相同路径和 hash。

## 通过、阻塞与回退

输入依赖完整、代码与公开 API 相符、候选和命令可定位，且其声明不超过 S9 证据范围时可交付待验候选；严格未改例外则不得超过冻结合同、适用证据和既有实现共同支持的范围。未改登记不等于已验收，最小差异也不等于可直接应用。业务理解错误回 S7—S9，操作能力错误回 S10。任何静态检查都不能替代真实运行。

## 下一阶段与最小验收

进入 S12。检查：验收者不读生成聊天也能定位并运行指定候选；候选不把测试目标名称当通用流程分支，也不依赖示范资料中的答案完成业务。
