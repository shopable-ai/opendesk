# S11：直接生成普通 OpenDesk JavaScript

责任 Skill：[recipe-build](../../../prompts/automation/agent-to-recipe/recipe-build/SKILL.md)。本阶段是原 S11 在路线 A 的实现，不构造 Recorder IR，不要求 Compiler。共同规则：[阶段约定](README.md)。

## 输入与进入条件

读取冻结合同、S9 完整过程、S10 适用 AppProfile／helper、实际公开 API 与计划输出位置。所需定位或验证能力仍未知时返回对应环节，不边生成边发明 Runtime 接口。

## 本阶段要做的事

将业务步骤组织为普通 JS 函数和清楚的数据流：参数校验、应用／状态确认、真实操作、运行时读取、后续消费、业务断言、证据和失败处理。保留必要准备与验证，移除探索绕路。

核对实际方法名、参数、返回值、异步语义和入口能力。遵守当前加载限制，不假定 Node.js、import／require、Execution.resume 或专用 Recorder 入口存在。

期望值只用于断言；不使用示范答案、eval／Function 或内部算术替代任务要求的真实业务取数。失败必须与已有 Runtime 的失败语义一致，不能吞错后正常返回。

候选保存到本任务获准目录，不覆盖既有参考脚本。清楚声明在线模型／OCR 等依赖，允许输入范围、运行环境和风险边界。

## 必须保存的输出与消费者

保存普通 `.js` 和 `candidate.json`：实际脚本路径、内容 hash、工作目录、可复制的一行正常入口命令、输入／配置契约、依赖及上游版本、支持范围、是否参考已有代码、未决事项。

做过的静态检查如实记录；未执行桌面验收不得写已通过。最后发布候选范围 handoff，由 [S12](12-qualify-and-deliver.md) 验证相同路径和 hash。

## 通过、阻塞与回退

输入依赖完整、代码与公开 API 相符、候选和命令可定位时可交付待验候选。业务理解错误回 S7—S9，操作能力错误回 S10。任何静态检查都不能替代真实运行。

## 下一阶段与最小验收

进入 S12。检查：验收者不读生成聊天也能定位并运行指定候选；候选不把测试目标名称当通用流程分支，也不依赖示范资料中的答案完成业务。
