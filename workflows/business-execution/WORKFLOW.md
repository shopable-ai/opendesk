# 业务执行：普通 JS、必要 Agent 判断与人工确认

状态：通用运行约定与消息场景设计示例；不是已实现的消息 API、调度器或运行证据。开发候选见 [Agent-to-Recipe](../agent-to-recipe/WORKFLOW.md)。

## 一次业务怎样运行

读取任务和授权，选择适用且版本已核对的候选，检查当前环境／对象／状态，再执行确定步骤。遇到内容理解或动态判断，交给有明确输入输出的 Agent；遇到超出既有授权的副作用，等待人工确认或停止。执行动作后独立核验本次业务结果，最后保存证据和必要检查点。

一项软件功能可能组合很多底层动作，也可能直接由一个可靠接口完成。封装边界取决于稳定业务语义与可验证输入输出，不取决于点击次数、JS 文件数量或是否使用大模型。

## 从基础动作到完整业务

| 层次 | 消息场景中的职责 | 放在哪里 |
| --- | --- | --- |
| 框架原语 | 当前窗口、截图、输入、文件、等待等通用机制 | OpenDesk 已有 Runtime／API |
| 应用操作 | 找到会话、读取可见历史、填入文字、提交、读取状态 | 应用专属普通 JS helper |
| 业务能力 | 确认指定对象、准备回复、发送已经批准的内容 | 有输入输出和验证的普通函数；必要时组合 Agent |
| 完整业务流程 | 为指定联系人处理本次消息，决定回复或转人工并核验结果 | 项目中的普通 JS 与明确的 Agent／人工交接 |

开发这些能力的 automation-plan、recipe-build 等专业 Skill 保留在 prompts；它们不是每次发消息都要重新运行的业务步骤。

## 消息示例：流程分解，不是公开 API 声明

下列名称只表示待实现的业务操作，不代表当前已有同名 API。此例没有指定实际联系人，不授权发送。

| 步骤 | 主要执行方 | 输出与继续条件 |
| --- | --- | --- |
| 查找并确认对象 | JS 应用操作；歧义时人工／Agent 辅助识别 | 当前账号、会话和身份依据；同名或身份不足就停止 |
| 读取所需历史 | JS 获取，必要时使用已支持感知能力 | 内容、来源、时间／版本和完整性限制；不能把可见片段称为全部历史 |
| 判断是否回复并起草 | 已验证规则，或必要的 Agent | 回复建议、依据、未决项和内容范围；允许选择不回复／转人工 |
| 审核发送资格 | 人或已经明确授权的规则 | 绑定发送账号、接收对象、具体内容与上下文版本的许可 |
| 再确认并提交 | JS | 重新核对会话、上下文变化、输入内容和权限；有变化则重新评估 |
| 核验本次结果 | JS／独立观察，必要时人工 | 发送结果及证据强度；界面出现气泡不自动证明对方已收到或已读 |

可以先交付“读取＋生成草稿＋人工发送”，再将经过验证的发送环节自动化。不同自动化程度应在服务说明、依赖、价格与验收中明确，不能用“Agent 能思考”掩盖缺失的业务规则。

## 最小混合实现，不要求新 Runtime

```text
普通 JS 读取当次数据 → 保存最小上下文
外层 Agent 消费上下文 → 保存受约束建议
人工或既定策略核对 → 明确许可或拒绝
普通 JS 重查现场、校验许可与输入 → 执行获准动作
独立回读 → 保存结果／不确定性与证据
```

最开始可由操作者分段运行；能可靠重复后再接自动编排。内部是同文件函数还是多个普通脚本，按当前 Runtime 加载与入口能力决定。上述上下文、建议、许可和回执只是项目交接数据，不新增 OpenDesk 公共类型或第二套 Agent-to-Recipe schema。

Agent 输出要做结构、类型、长度、业务约束与允许动作检查。业务内容是数据，不得扩大工具权限；不 eval 模型返回的代码，不让聊天中的指令越过原任务授权。只交给 Agent 完成判断所需的最少内容，秘密不放在共享提示词中。

授权需要有适用对象、动作、内容和有效条件；人工确认并不是每次动作的必经新增步骤，已存在明确且仍有效的授权可以沿用。账号、对象、内容、上下文版本或许可条件变化后，旧确认不得直接复用。

## 重试、恢复与不确定副作用

只读步骤通常可在预算内重新执行，仍须确认数据新鲜度。发送、提交、付款、删除不能因超时就重新执行。操作可能成功但回执缺失时，先查询实际结果；缺少足够核验能力就停在待人工确认，不宣称失败后安全重发。

项目可保存任务标识、目标、内容摘要、尝试状态和结果引用作为去重线索，但本地记录不能保证跨系统恰好一次。可靠程度取决于下游可查询的结果或真实幂等能力；UI 自动化不能凭一个本地布尔值承诺恰好一次。

检查点保存必要业务数据与证据引用，不保存永久有效的焦点、windowId 或坐标。恢复前重查身份和可变前提。停止、超时和取消以实际宿主／Runtime 能力为准；外层等待结束不等于内部动作已被中断。

## 运行质量与后续编排

确定步骤检查对象、输入、动作结果与真实取数；Agent 判断检查内容是否有依据、符合任务规则、是否遗漏／误答以及应否转人工；整体任务检查是否完成约定结果、是否发生错误副作用和是否超出成本／时间预算。各项分别记录，不以最后一个函数返回 true 代替业务验收。

先验证支持范围内的单次任务，再验证变化输入、旧状态、错误目标、缺证据、上下文在审核后变化，以及结果不明时停止。持续运行、批量和跨应用协作需要额外证明，不能从单次成功推断。

当出现实际需要的长流程状态持久化、人工等待、分支恢复或多节点调度时，可把已有 JS 和 Agent 判断接到 LangGraph 等外部工具。LangGraph 官方定位包括持久执行、人工参与以及确定步骤与模型步骤的组合；这不意味着 OpenDesk 已有对应适配，也不改变普通 JS 的独立运行要求。
