# 人工 Recorder｜完整作业任务树

**目标：从用户真实示范出发，形成有来源、可审阅、可验证并可维护的普通 OpenDesk JS；仅在确有必要时保留 Agent 判断。**

状态：H1—H8 作业树基线，2026-09-11。H2/H3 已同步 Recorder v2 的观察事实；H4/H6 现有仓库内 `human-to-recipe` 与 behavior-preserving `recorder-script-refiner` Skill、最小 `SemanticBuildPlan` schema／validator 和单行任务交接，renderer 仍未实现。H5.2 已补齐点击目标的 Native／OCR／Visual／Geometry／Context 多源证据、文字绑定、语义化与重新定位要求；AX／UIA 的原生目标采集、重新定位、操作选择与独立验收要求已整合进 H1—H8。本次仅补充 Human 来源与 Agent-to-Recipe 共享专业方法的映射：H1—H4 继续负责人工录制来源，H5 是按需组合共享 application-engineer、目标 trace-distill 与 procedure-synthesize 的阶段，不新增第二套专业实现。该映射不赋予 `trace-distill` 新 Skill、Windows Recorder 接线或端到端回放任何实现／通过资格。返回[工作流入口](../README.md)；规范性 DQ 合同见 [Recorder 工程设计](recorder-design.md)，真实完成、证据与未运行项见[实施与验收计划](implementation-plan.md)。

## 阅读方法

H 编号只用于人工录制作业，不改写 Agent-to-Recipe 的 S 编号。树回答完整需要做什么；实际执行按工作包选择必要分支。一个叶子不等于一个文件、类、Skill 或 Agent。

H2 采集事实，H3 整理事实，H5 理解与工程化；分析不阻塞采集。H4 与 H5 可循环，H7 按失败原因定向返回。简单坐标任务可跳过 H5 的深度分析；关键歧义、缺失、权限及不支持动作仍须说明和处理。缺口只阻塞依赖它的工作。

Human Recorder 与 Agent-first 是两条不同来源链：人工路线的原始事实来自用户输入事件、窗口／控件／画面及 H3/H4 审阅；Agent-first 的事实来自 Agent 本次真实执行与 Dossier。两者在事实足够可消费后可以复用相同的应用工程、必要路径提炼、过程提炼、代码构建和资格方法，但不能把人工录制追认为 Agent 示范，也不能要求 Agent 路线先产生 Human Recorder 文件。

点击目标理解不再分成“普通按钮”和“无文字图标”两套互不相干的链。只要本步骤需要语义增强，就统一检查可取得的 Native、OCR、Visual、Geometry 和 Context；有文字按钮优先利用可靠文字证据，无文字图标允许 OCR 为空并转由图形与上下文承担，不得把 OCR、AX 或模型任一单源当作天然真值。

默认增强路径是：原始事件保真 → 关联实际应用／窗口／原生控件 → 审阅并形成定位候选 → 程序验证重新定位与动作语义 → 普通 JS → 新运行中重新查找、单次执行与独立结果验证。原生证据可靠、目标唯一且动作语义适用时优先使用；原生信息不足时按需补 OCR、图像或受控坐标，同一脚本可以混用。多源检查不是强制开启全部采集，证据冲突时先解决歧义，不按来源优先级掩盖冲突。

复用 [Accessibility](../../../docs/api/accessibility.md) 与现有 Recorder／human-to-recipe 合同，不另建 Recorder 专用 UI 树、应用对象层或 Replay Runtime；不默认抓取整树、连续截图或逐次调用模型。原始操作事实、控件观察证据、可复用定位规则、操作与结果规则分别保存，不能用其中一层冒充另一层。

## H1. 明确任务、交付范围与录制条件

```text
H1. 明确任务、交付范围与录制条件
│
├─ H1.1 明确用户真正要完成的任务
│  ├─ 处理哪个应用、账号、文件或业务对象
│  ├─ 从什么状态开始，最终需要得到什么
│  └─ 哪些结果不能发生，哪些动作需要另行确认
│
├─ H1.2 选择本次交付方式
│  ├─ 受控坐标脚本：在声明的固定条件下重复
│  ├─ 增强普通 JS：重新找到正确目标再操作
│  └─ JS／Agent 混合：保留必要的理解与动态判断
│
├─ H1.3 盘点可以复用的已有成果
│  ├─ 已有录制、脚本、应用认识和目标规则
│  ├─ 已有测试结果及其适用环境
│  └─ 决定本次新录、接续、补录，还是修复已有步骤
│
├─ H1.4 选择采集内容与支持范围
│  ├─ 必要输入事件与运行环境
│  ├─ 按需采集窗口信息、截图、原生控件和状态
│  ├─ 区分能采集、能转换、能生成、已回放验证的动作
│  ├─ 分平台检查 AX／UIA 后端、宿主授权、系统权限及目标应用的实际控件暴露情况
│  ├─ 分开确认能采集控件、能重新定位、能执行原生动作与已真实回放，不以“有后端”代替闭环
│  └─ 明示当前不支持或存在限制的操作
│
└─ H1.5 确定权限、控制方式和资源限制
   ├─ 分开约定录制、本地保存、在线模型外发权限
   ├─ 确定敏感输入、控件名称等元数据、排除区域、保留期限和删除方式；截图、OCR 与模型外发分别授权
   ├─ 提供明显的暂停、停止和用户接管入口
   └─ 约定模型调用、补采、重试和存储预算
```

## H2. 记录用户操作及其必要现场

```text
H2. 记录用户操作及其必要现场
│
├─ H2.1 管理录制生命周期
│  ├─ 开始、暂停、恢复、停止、取消
│  ├─ 排除录制控制按钮和停止快捷键的业务回放
│  ├─ 处理退出、中断、存储失败与部分保存
│  └─ 区分停止采集、保存完成和分析完成
│
├─ H2.2 采集原始输入
│  ├─ 保存鼠标按下、释放、点击、滚轮及按键状态
│  ├─ 未按鼠标键的普通 hover move 只计数后过滤，不写 raw
│  ├─ mousedown 后的 motion／drag 保留为点击抖动或拖动判定证据
│  ├─ 键盘按下、释放、组合键与可取得的文本信息
│  ├─ 保存事件顺序、时间及必要的输入来源标记
│  └─ 来源无法确认时保留未知，不伪称全部来自人工
│
├─ H2.3 关联应用、窗口和坐标
│  ├─ 每个动作关联 application → window → optional element，不只保存起始窗口
│  ├─ 应用保存可执行路径／名称；PID 只作本次 provenance
│  ├─ 窗口保存 title、bounds、popup 及瞬态 ID/index/handle，区分同应用多窗口
│  ├─ 同时保存 screen fact、window offset/ratio 和 element offset/ratio
│  ├─ 保留显示缩放、裁切、观察时间和坐标转换所需信息
│  ├─ 验证实际窗口或弹层归属，不能仅凭 PID 相同确认同一个窗口
│  ├─ 核对点命中的输入坐标和控件范围的输出坐标；区分原生物理坐标、屏幕逻辑坐标与图像像素
│  └─ 记录窗口／应用切换、弹窗、遮挡、目标歧义和无法关联原因
│
├─ H2.4 按所选模式保存操作现场
│  ├─ 关联真实取得的操作前画面
│  ├─ 关联操作后及必要的中间状态
│  ├─ 按 H1 确认的可用 AX／UIA 后端，分别关联按下／释放的命中节点与操作目标
│  ├─ 命中文字／图标子节点时，有界寻找与本次动作相符的可操作祖先，不以“存在任意动作”直接批准
│  ├─ 即使命中按钮本身，也按消歧需要保存有限父容器；操作目标选择与定位上下文采集分开
│  ├─ 指针证据保存 role/name/identifier、必要状态、actions/bounds/hit/ancestors，不读取／保存 value 或安全内容
│  ├─ 记录 source event、观察开始／结束时间、观察阶段与完整性；区分操作前、操作后和无法确定
│  ├─ 点击后弹层消失、查询晚到或前台变化时保留关联缺口，不把事后命中冒充当时目标
│  ├─ 增强模式按需保存点击目标裁剪、必要上下文裁剪及 OCR 结果引用
│  ├─ OCR 结果必须保留 text、bbox、source image/hash、坐标映射、engine/version、confidence 与采集时间；不能覆盖原生文字
│  ├─ 保存图像范围、尺寸、来源和采集时间
│  └─ 连续动作缺少独立观察时，保留为片段或标记歧义
│
├─ H2.5 保证采集不被分析拖慢
│  ├─ 输入事件先记录，不等待在线模型返回
│  ├─ 证据采集与模型分析分别调度，原生查询不进入输入回调
│  ├─ 对查询深度、节点数、队列与耗时设边界；暂停、停止和取消沿既有 owner 清理
│  ├─ 原生调用不能强制中断时如实记录，不能把请求超时当作底层工作已退出
│  ├─ 对可检测的丢事件、缺帧和采集失败明确报告
│  └─ 资源不足时不能静默丢掉关键动作后仍报告完整
│
└─ H2.6 形成可消费的录制包
   ├─ 原始事件与环境记录
   ├─ 已获准保存的截图和辅助证据
   ├─ 事件、窗口、控件观察、画面之间的对应关系及各自来源／版本
   └─ 支持范围、完整性状态与已知缺口
```

基础模式可以不采集截图，但后续不能宣称完成了视觉理解。标签级 AX／UIA 语义是有时间与归属限制的控件观察，不代替原始输入事实，也不等于业务意图或已验证 locator；`verified`、`unavailable` 和 `not-requested` 必须明确区分。OCR 是派生观察，不是原始输入事实：缺少目标裁剪、原图 hash、坐标映射、引擎版本或来源时只能标缺口，不得在 AX 失败时静默写入一个无来源 OCR 字符串。监听回调后才取得的截图不保证是点击前画面，应如实保留时间差和缺失，不要求所有录制保存完整视频。原生观察也必须接受同样的时间关联检查，时间接近本身不能证明是点击前现场。坐标映射未经验证时，不把 nativeBounds 直接交给 mouse，也不猜测 DPI、原点或跨屏换算；只阻塞依赖该映射的路径，不一并否定不依赖鼠标坐标的原生动作。

## H3. 将原始事件整理为操作步骤

```text
H3. 将原始事件整理为操作步骤
│
├─ H3.1 识别基本动作
│  ├─ 将按下／释放组合为点击等动作
│  ├─ 区分单击、双击、右键和拖动
│  ├─ 只把有界按键后微动归一化为 click jitter，真实拖动保持 blocked
│  └─ 为每个动作绑定 source events、窗口上下文、目标语义状态和操作顺序
│
├─ H3.2 整理输入内容
│  ├─ 区分普通按键、快捷键与文本输入
│  ├─ 区分输入法编辑过程与最终提交文本
│  ├─ 在获准且能力可用时关联焦点控件与最终编辑结果；无法可靠关联时保留缺口
│  ├─ 区分粘贴动作与被粘贴的数据
│  └─ 无法可靠还原时保留原始动作或进入补充流程
│
├─ H3.3 关联动作现场
│  ├─ 每一步关联应用、窗口和相关观察
│  ├─ 每一步关联来源事件，不重复执行同一份输入
│  └─ 无法分离的快速连续动作先作为动作组处理
│
├─ H3.4 初步标记待解释片段
│  ├─ 可能的等待、探索、误点、重复和恢复
│  ├─ 可能依赖已有登录、文件、剪贴板等状态的步骤
│  └─ 标记只是候选，不擅自删掉可能必要的操作
│
└─ H3.5 形成可审阅的步骤清单
   ├─ 展示动作、所属应用／窗口、目标名称／角色、目标位置、已有截图和信息缺口
   ├─ 区分原始事实与整理结果
   └─ 修改整理结果时，不改写原始录制事实
```

事件被采到不意味着能可靠转换。输入法按键与最终文本不能同时生成重复执行；按键粘贴不意味着已知道粘贴内容及业务来源；停顿不能自动等同于应用加载等待。

## H4. 审阅、纠错与补充示范

```text
H4. 审阅、纠错与补充示范
│
├─ H4.1 查看本次到底录到了什么
│  ├─ 查看步骤、点击位置和已有证据，说明“操作了哪个窗口中的哪个目标”
│  ├─ 并列查看原始命中与实际操作目标，区分文字／图标子节点和父控件
│  ├─ 区分原生属性、OCR、图像候选、Agent 推断与人工修正；未知名称不猜填
│  ├─ 查看未支持动作、缺失片段和目标歧义
│  └─ 简单任务允许快速审阅，不强制逐条填写说明
│
├─ H4.2 修正操作清单
│  ├─ 删除无关操作，保留必要准备和验证
│  ├─ 修正错误合并、错误拆分和重复输入
│  └─ 区分误操作、恢复步骤与正常业务路径
│
├─ H4.3 补充无法直接观察的需求
│  ├─ 这一步为什么做，最终需要什么
│  ├─ 下次什么保持不变，什么需要变化
│  ├─ 数据来自哪里，已有同名内容时怎样处理
│  └─ 能从证据解决的问题先核实，不重复询问用户
│
├─ H4.4 定向补录或补观察
│  ├─ 明确缺哪个目标、哪个状态或哪个操作片段
│  ├─ 只补影响当前交付的部分
│  └─ 新补材料标为新证据，不冒充原录制现场
│
└─ H4.5 确认本次可继续的范围
   ├─ 保留修改前后版本、理由和来源
   ├─ 标记已确认内容与仍然未知的内容，形成 reviewed recording steps；可交 H5 做增强专业作业，或由简单受控路径直接交 H6
   └─ 未知项只阻塞依赖它的工作，不一律要求全部重录
```

区分三类缺口：用户做了但采集不完整；用户确实漏掉必要操作；任务依赖登录、已有剪贴板、文件或肉眼判断等隐含条件。分别补采、修正过程或补充约定，不让 Agent 自由补造整段成功流程。

## H5. Agent 理解、过程提炼与操作工程化

```text
H5. Agent 理解、过程提炼与操作工程化【按需增强】
│
├─ H5.1 建立本次任务所需的界面认识
│  ├─ 先核对已有认识是否仍然适用
│  ├─ 粗识别当前页面、主要区域和状态
│  ├─ 精查操作目标、父区域、锚点和结果区域
│  ├─ 识别控件类型、可观察状态和必要关系
│  ├─ 有界观察明确窗口／容器，保留截断、不可读取与未物化子树，不能把不完整树当完整空树
│  └─ 形成同版数据与审阅视图，不重新建模整个软件
│
├─ H5.2 分析一次点击目标：文字、图标及上下文统一处理
│  │
│  ├─ H5.2.1 确定分析现场
│  │  ├─ 核对点击时间、窗口和相关画面
│  │  ├─ 区分操作前、操作后和无法确定的观察
│  │  └─ 缺少可靠现场时保留限制，不事后重造
│  │
│  ├─ H5.2.2 从点击点提出目标候选
│  │  ├─ 利用可用的同期原生信息和视觉信息
│  │  ├─ 对照 H2 的 AX／UIA 原始命中、操作目标与父容器，核对窗口归属和观察阶段
│  │  ├─ 区分图标、文字、控件、容器和背景
│  │  └─ 点击点不能直接证明目标正确或操作成功
│  │
│  ├─ H5.2.3 形成可复核的多尺度证据包
│  │  ├─ 目标细节：控件／图标／文字的完整可见范围
│  │  ├─ 局部上下文：工具栏、列表行、卡片及相邻目标
│  │  ├─ 页面上下文：页面身份与整体状态
│  │  ├─ 保留裁切、缩放、原图 hash 与屏幕／窗口映射；不足时有界扩大
│  │  └─ OCR、模型或后续诊断均引用同一来源版本，不把审阅标注图当原始模板
│  │
│  ├─ H5.2.4 提取并绑定文字证据
│  │  ├─ 优先保存可用的原生 name／label／title 等非敏感文字事实
│  │  ├─ 选择 OCR 增强且已获准时，对目标控件内部执行 OCR，保存文字与 bbox
│  │  ├─ 按需 OCR 点击点附近及所属行／卡片／工具栏中的必要文字
│  │  ├─ 判断文字属于目标本身、相邻标签、父容器还是其他业务对象
│  │  ├─ Native、OCR、模型文字冲突时并列保留来源与冲突，不自动互相覆盖
│  │  └─ OCR 为空不等于目标无语义；无文字图标继续进入视觉与上下文分析
│  │
│  ├─ H5.2.5 提取非文字视觉与状态证据
│  │  ├─ 图标、形状、边缘、颜色及组合外观
│  │  ├─ selected／disabled／highlighted／expanded 等可观察状态
│  │  ├─ 文本＋图标按钮同时保留两类证据，不只取其中一种
│  │  └─ 无文字图标不得只按通用图标常识直接批准业务动作
│  │
│  ├─ H5.2.6 区分几何范围与操作范围
│  │  ├─ 文字 bbox、图标可见范围、完整控件范围分别表达
│  │  ├─ 所属区域范围、父容器及相邻锚点分别表达
│  │  ├─ 可操作区域与实际操作点单独表达
│  │  └─ 未知者不默认取识别矩形中心；分裂按钮不同位置可有不同语义
│  │
│  ├─ H5.2.7 确认目标归属并完成语义化
│  │  ├─ 确认它属于哪个应用、页面、区域或业务对象
│  │  ├─ 多个相同文字／图标时，结合所属行、标签、锚点或业务身份消歧
│  │  ├─ 基于证据解释控件类型、候选功能及本步骤作用
│  │  ├─ 区分激活窗口、选择、展开、切换、提交、探索、误点、重试和恢复
│  │  └─ 分开保存可见事实、模型解释、业务解释、人工修订和未知项
│  │
│  ├─ H5.2.8 检查实际效果
│  │  ├─ 分别记录期望变化与真实观察
│  │  ├─ 检查变化是否属于同一个业务对象
│  │  ├─ 排查其他输入、异步加载和外部变化的影响
│  │  └─ 结果记录为满足、失败、部分满足或未知
│  │
│  ├─ H5.2.9 解决关键缺口
│  │  ├─ OCR／图形不清楚：补清晰目标或局部原图，不伪造文字
│  │  ├─ 目标重复：补所属对象、区域、标签或锚点关系
│  │  ├─ 作用未知：补已有资料、说明或获准观察
│  │  └─ 仍有歧义：停止依赖操作，不靠重复猜测通过
│  │
│  └─ H5.2.10 发布点击目标认识与重新定位候选
│     ├─ 目标身份、所属关系、控件类型和候选功能
│     ├─ Native／OCR／Visual／Geometry／Context 的来源证据与冲突
│     ├─ 候选 locator portfolio：原生角色／标识／名称与容器、OCR 文字、图标、父区域＋文字、行／卡片关系、几何
│     ├─ 每种 locator 的唯一性、适用条件、失败条件和验证状态
│     └─ 未决问题只阻塞依赖它的生成或运行，不冒充已验证 locator
│
├─ H5.3 按动作类型采用专门分析
│  ├─ 文本输入：字段、输入来源、编辑过程与最终内容
│  ├─ 复制粘贴：数据生产者、消费者及有效条件
│  ├─ 拖动：起点、终点、必要路径和结果
│  ├─ 悬停：是否产生后续控件、菜单或提示
│  ├─ 滚动：所属容器、寻找目标和结束条件
│  ├─ 开关／复选框：当前状态与期望状态
│  └─ 窗口／应用切换：对象身份、焦点和数据交接
│
├─ H5.4 提炼必要路径、业务过程与数据关系
│  ├─ 对需要增强的 reviewed recording steps，先按共享 trace-distill 方法形成有来源的必要路径；不修改原始 recording/actions
│  ├─ 将必要操作组织为有目的的业务步骤；动作 retain／merge／omit／recovery 主责不在过程层维护第二套真相
│  ├─ 保留必要准备、读取、等待与验证
│  ├─ 区分常量、输入参数、运行时读值和敏感信息
│  ├─ 明确步骤之间的数据来源与消费者
│  ├─ 根据真实规则确认条件、循环和异常处理
│  └─ 不把一次示范或一次重试推导成普遍业务规则
│
├─ H5.5 将认识转为可重复定位与操作
│  ├─ 分开表达目标身份、定位规则、当前几何和操作点，不把控件观察直接升级为已验证 locator
│  ├─ 选择最小足够的原生、文字、视觉或相对定位依据
│  ├─ 原生候选限定当前应用／窗口，必要时先找父容器，再组合角色、已核实的标识和名称
│  ├─ 不默认 identifier 跨运行稳定，不把整树索引、PID、handle、RuntimeId 或 ElementRef 当长期定位规则
│  ├─ 在新观察中重新查询并验证唯一性、窗口归属和当前状态；多候选或搜索不完整时不选择第一个
│  ├─ 明确动作前提、状态等待、执行方式和动作后验证，分开选择“怎样找到”与“怎样操作”
│  ├─ 已验证等价且支持原生动作的按钮可用 invoke；需右键、拖动、悬停或按键语义时保留对应输入
│  ├─ 不把全部点击换成 invoke，也不把全部文本输入换成 setValue；未验证的动作转换不批准
│  ├─ 用新的原生观察或画面检查重新定位，不只匹配录制时的树或建模用原图
│  ├─ 原生信息不足时按需补视觉／文字／受控坐标；冲突回 H4 审阅，缺口只阻塞相关路径
│  └─ 失败时不自动放宽对象约束或降级为全局坐标
│
└─ H5.6 确认可复用范围与交付边界
   ├─ 哪些步骤可以固化为普通 JS
   ├─ 哪些判断需要 Agent，哪些需要人工授权
   ├─ 支持哪些输入、布局、主题、缩放和应用状态
   ├─ 哪些认识只是候选，哪些规则已有测试依据
   └─ 将已确认 DistilledSteps／SemanticProcedure、locator 来源／验证记录、动作策略、后置条件及未知项交给代码生成
```

### H5 的职责边界

Agent 主导陌生界面的布局、组件、语义和关系分析；程序承担有界原生查询、唯一性与状态检查、材料组织、OCR 调度与来源记录、坐标映射、结构校验、确定性视图和已验证规则执行；人工处理必要纠错与授权。不是固定先跑完传统规则，全部失败才问模型；也不是每次点击都重新调用模型。

H5 是 Human Recorder 来源工作流中的**共享专业方法组合阶段**，不是一个新的巨型 Skill，也不维护第二套平行专业正文：

- H1—H4 负责 Human 来源特有的任务范围、人工事件采集、动作正规化、reviewed recording steps 与人工／Agent 审阅；这些来源继续由 human-to-recipe 合同维护。
- 界面结构、图标归属、定位和应用操作复用 [application-engineer](../../agent-to-recipe/skills/application-engineer/SKILL.md) 及[应用操作专业正文](../../agent-to-recipe/design/application-operations.md)。
- 对需要增强的录制，原始／reviewed actions 到必要路径的 retain／merge／omit／recovery／unresolved 取舍复用目标 `trace-distill` 方法；当前它只是 Agent-to-Recipe 中已冻结的目标职责和 DistilledSteps 合同，尚无正式 SKILL.md 或宿主加载资格。
- Business Step、参数、数据流、分支／循环和复用范围复用 `procedure-synthesize` 的 S8—S9 责任；代码构建与独立验收不归 H5 应用工程，也不在本文件复制专业实现。
- 简单受控坐标路线允许从 H4 reviewed steps 直接进入 H6，不强制生成深度 DistilledSteps／SemanticProcedure；增强路径才按实际缺口消费上述共享专业方法。

一个 Agent 可以连续承担这些专业作业，不能据职责名称宣称相应 Skill 全部已实现，也不能把 Human 录制事实追认为 Agent 示范。

### 点击分析的执行约定

| 子作业 | 输入 | 处理与判定 | 输出／失败处理 |
| --- | --- | --- | --- |
| 现场关联 | 输入事件、窗口、前后观察 | 核对时间差、窗口、穿插输入；晚到的控件查询不能冒充同期事实 | 有限可信现场；不足保留缺口或动作组 |
| 目标候选 | 点击点、同期原生属性、图像 | 点击点是线索；区分命中对象、背景及仅激活窗口 | 候选控件，不直接宣称成功 |
| 多尺度证据 | 原图与候选范围 | 有控件边界则按边界裁切；只有点则先取周边再精查；程序校验范围、原图 hash 与映射 | 目标细节、必要局部／页面上下文；不是每次额外截三张全图 |
| 文字证据 | Native label/name、目标裁剪、局部上下文 | 按所选增强范围和授权 OCR 目标内部及必要上下文；保存 text+bbox+source；判定文字属于目标、标签还是父／邻对象；冲突不静默覆盖 | 可追溯文字证据及绑定关系；OCR 为空或冲突显式保留 |
| 非文字视觉 | 目标图像、图标、状态 | 提取图形和状态；无文字时结合上下文，但不用图标常识直接批准操作 | 可见视觉事实与候选解释分开 |
| 对象归属与语义 | 父区域、文字、图标、业务身份、重复目标 | 识别同一行／卡片／会话等必要关系，验证唯一性并解释候选功能 | 带对象约束的目标，不只给图片或 OCR 命名 |
| 实际效果 | 原期望、前后状态及其他输入 | 变化不自动证明因果；菜单出现不等于属于正确对象 | 满足、失败、部分满足或未知 |
| 工程化与验证 | 已确认目标、实际 API、locator portfolio | 明确前提、重新定位、有效操作点、等待和后置；在新画面和实际环境测试 | 候选规则与验证记录分开，结果不足不晋级 |

原图、审阅标注图与匹配模板分开。点击红点、编号和边框可以用于审阅，不直接污染模板。文字 bbox、图标可见范围、完整控件范围、所属区域和安全操作点分别表达；分裂按钮的不同位置可能有不同含义，不能默认点击识别矩形中心。

目标重复时扩大到必要业务上下文；文字或图形模糊时补局部原图；功能未知时查已有资料、同期原生说明或后续真实状态。主动悬停以取得 Tooltip、切换页面或补点击都属于新动作，须有授权和不干扰用户的时机；不得为识别删除按钮试删真实业务数据。补采取得新证据，不重造历史现场。

给模型的任务应明确：消费已整理的 Native／OCR／Visual／Geometry／Context 证据解释本次目标，不执行新动作；返回候选、关系、证据引用、简短依据、未知和补采需求。模型自报置信度不是校准成功概率，JSON 合法或模型再次说正确也不是独立验证。模型输出作为待校验数据，不直接执行其返回代码。

### 贯穿示意：每条订单都有相同的无文字“⋯”

以下是设计场景，不是现场测试结果。任务是查看输入订单的详情。

```text
录制事实：用户在订单列表某行右侧点击“⋯”
→ 证据：图标细节、OCR/原生取得的订单身份文字、含订单身份的行上下文、页面身份、点击后菜单
→ 目标认识：此按钮属于该订单行，不是全屏任意“⋯”
→ 过程解释：打开菜单是为查看详情，不是整个业务完成
→ 参数：输入订单编号，而不是固定行号
→ 定位：确认列表 → 找到订单文字 → 确认所属行 → 行内按钮唯一性
→ 操作：使用有依据的可操作点或获准原生动作
→ 验证：菜单／详情与目标订单关联，最终显示预期对象
→ 变化测试：列表重排仍选对对象；订单不存在时不误点
```

只保存一个图标小图无法单独证明业务归属。同样，只保存一个 OCR 字符串也无法证明该文字属于被点击控件或正确业务对象。矩阵和行列位置只能是已验证布局下的候选定位方式，不是所有应用的默认规则。文字、颜色、大小也是候选特征，不假设必有、唯一或稳定。

## H6. 生成普通 OpenDesk JavaScript

```text
H6. 生成普通 OpenDesk JavaScript
│
├─ H6.1 固定本次生成依据
│  ├─ 已整理／确认的步骤版本；增强路线引用实际 DistilledSteps／SemanticProcedure 版本，简单受控路线引用 H4 reviewed steps
│  ├─ 选定的目标规则与适用条件，分开冻结观察证据、locator、动作策略和结果规则
│  ├─ 输入、配置、数据流和成功标准
│  ├─ 每个 action 的唯一 disposition 和 source map
│  └─ 未分类、歧义和尚未具备的依赖必须阻止生产生成
│
├─ H6.2 使用实际可调用的框架能力
│  ├─ 核对当前 API、参数、返回值和运行方式，检查生成脚本的目标宿主是否允许原生能力
│  ├─ 复用现有窗口解析、Accessibility.find／read／perform／release 及 within，不增加第二套控件接口
│  ├─ 通过现有制作／生成链消费已验证 locator；basic 合同保持，原生语义路径由调用方明确选择
│  ├─ 基础动作直接形成普通脚本
│  ├─ 窗口／显示器相对点使用 Geometry，不手写 win.x + offset
│  ├─ 必要时提取语义变量和普通函数
│  └─ 不强制应用对象层、复杂中间表示或专用回放运行时
│
├─ H6.3 落实正确的执行行为
│  ├─ 获准的状态准备和对象确认
│  ├─ 正确定位、输入、等待和数据传递
│  ├─ 每次运行重新解析当前窗口并查找元素，不跨 execution 复用录制时的 ref
│  ├─ 提交前重验目标身份、状态与实际动作能力；只提交一次已批准的原生动作
│  ├─ 及时 release 当前 execution 的元素引用，沿既有生命周期处理停止与清理
│  ├─ 只读查询的有界重试与有副作用的动作重试分开，保留错误提示和可用的取消机制
│  └─ 不通过替换操作方式偷换用户要求
│
├─ H6.4 落实验证与副作用边界
│  ├─ 区分动作已发出、目标已命中和业务已完成
│  ├─ 对发送、提交等结果不明先核对实际效果
│  ├─ acknowledged 只代表原生调用获确认，not_needed 表示目标状态已满足；两者不自动证明整个业务完成
│  ├─ unknown 表示动作可能已提交，禁止自动重做或补一次坐标点击
│  ├─ 只有确认 not_started，且替代策略已验证、当前目标仍明确时，才按显式策略考虑切换
│  └─ 不因结果未知就自动重复执行不可逆操作
│
├─ H6.5 保持生成结果可维护
│  ├─ 代码中的步骤可追到来源与选定规则
│  ├─ 图片、配置与敏感信息采用明确引用
│  ├─ 重新生成时展示差异，保护已有人工修改
│  └─ 冲突需要处理，不能静默覆盖用户代码
│
└─ H6.6 交付候选程序
   ├─ 可查看、可编辑的普通 JS
   ├─ 必要资源、来源关联、正常运行方法与独立 Gate 要求
   └─ 标记为待验收，生成不自动回放，不把生成成功当成运行成功
```

### H6 的确定性输入和审阅规则

原生路径先复用 H5 验证过的 selector 与 `within`，能够先找容器再找目标时不增加复杂查询语法。新增证据或策略若超出现有 actions／plan／validator 的可表达范围，先在 Recorder 工程设计明确最小合同差异，再同步实现、schema、类型、validator 和兼容测试；不能把本任务树的要求当作当前 schema 已接受的字段。旧包缺证据时保留既有受控路径或明确阻塞语义生成，不补造字段，也不放宽 strict validation。原生动作替换须有 H5／H7 的等价性依据，不能由 behavior-preserving `recorder-script-refiner` 静默执行。

代码生成开始前冻结最小 build plan。当前机器合同是 [`semantic-build-plan.schema.json`](../skills/human-to-recipe/references/semantic-build-plan.schema.json)，并由 [`validate-semantic-build-plan.js`](../skills/human-to-recipe/scripts/validate-semantic-build-plan.js) 检查；它不是 Runtime API 或通用 Compiler。plan 必须包含 actions 实际文件／revision／hash、逐动作 `business | runtime-guard | qualification | evidence | excluded | unknown` disposition、Business Episode 名称与顺序、参数和常量分类、Target/Locator/Geometry、动作策略、运行门禁、恢复规则、qualification claims 以及 action→episode→代码位置的 source map。一个 action 只能有一个主 disposition；任何 `unknown`、遗漏、重复消费或相互冲突都使 H6 fail closed。增强路线若已发布 DistilledSteps／SemanticProcedure，应由 build plan 引用实际版本，不再从原 actions 隐式重新决定业务取舍。

simple console 的“复制 Agent 优化脚本”只把仓库相对 generated script 写成一句话，不携带 Skill 路径、机器 workdir、业务问卷、动作正文、派生元数据或流程说明。仓库 `AGENTS.md` 把这类请求路由到 `recorder-script-refiner`；按钮仅在脚本存在且没有真实重放时启用，Skill 在当前包内核对完整 lineage，默认行为保持优化且不提问。业务目标、动作取舍、参数化和结果 Oracle 仍属于独立的 `human-to-recipe` 生产化入口，不能因删掉提示词字段而猜测。

固定 plan 后，生成器或 recipe-build Agent 不再推断业务，只按同一顺序落代码：

1. 来源 lineage 和仓库根目录正常命令注释；
2. 应用身份、布局范围和其他运行常量；
3. 语义控件／操作点表，保留选择依据而不复制资格 Oracle；
4. 目标解析、当前状态重验、Geometry、动作和有限恢复 helper；
5. 以业务语言命名的 Episode 函数或清晰顶层段；
6. 只含业务顺序的顶层流程和不冒充验证的完成输出。

静态审阅逐项拒绝：plan/source hash 不匹配、action 未映射或多次映射、事件编号泄漏为业务命名、未实现 API、路线图工作名、目标歧义放宽、隐式 AX/OCR/坐标/键盘 fallback、手写坐标空间换算、无理由固定等待、把动作发送写成 `[PASS]`，以及来源 hash／逐步固定 Oracle／截图矩阵／evidence 写入混入生产 Recipe。生产文件与 qualification 文件分别检查；Gate 必须冻结并运行同一生产源码，不能维护另一份隐藏业务动作序列。

重新生成只接受同一 plan 的可审阅 diff，不覆盖已有人改；人工确实改变业务、门禁或定位时，先修订 plan、记录理由和影响，再派生新候选并重新资格。[Calculator plan](../golden-samples/calculator-115.semantic-build-plan.json) 是第一个 golden；TextEdit 是下一建议应用，但当前只用于跨应用 Geometry／window lifecycle 校准，尚无同等级 human 录制和 production/gate，不能预填其业务意图或双应用通过。

## H7. 实际运行、验收与定向维修

```text
H7. 实际运行、验收与定向维修
│
├─ H7.1 准备验收
│  ├─ 固定候选代码、规则、输入和环境
│  ├─ 明确本次支持范围与期望结果
│  └─ 准备获准起点和安全测试数据，不擅自清空用户状态
│
├─ H7.2 检查代码与依赖
│  ├─ 语法、API 调用、资源路径与参数处理
│  ├─ 可观察的错误、停止和清理行为
│  ├─ 覆盖多窗口／同名目标、错误归属、树截断、超时、失效引用、禁用控件、权限不足与不支持动作
│  ├─ 检查敏感字段不被默认采集，pause／stop／cancel／overflow 后原始事实与资源状态可核对
│  ├─ 检查 actionState=unknown 不重复提交，未验证坐标映射不进入鼠标路径
│  └─ 分开记录静态检查、模拟检查与真实运行
│
├─ H7.3 实际运行候选程序
│  ├─ 从声明的工作目录使用正常脚本入口
│  ├─ 保留关键动作、对象和结果证据
│  ├─ 原生路径先核对动作等价性，再以独立 oracle 核对实际结果，不以 API 返回成功代替
│  └─ 纯 JS 模式不得靠未声明的 Agent 补救后声称通过
│
├─ H7.4 验证支持范围内的变化
│  ├─ 有文字按钮：OCR／Native 文字可追源、归属正确并能参与候选 locator
│  ├─ 无文字图标：OCR 为空时仍可依据图形与上下文正确识别，不伪造文字
│  ├─ 文本＋图标按钮：两类证据同时存在且冲突可见
│  ├─ 重复同名／同图标目标：依赖所属行、卡片、标签或业务对象消歧
│  ├─ 周边标签目标：能区分目标自身文字与相邻 label／父区域文字
│  ├─ 窗口平移与窗口内部按钮位置／布局变化分别验证，不能用平移测试代替控件重新定位
│  ├─ 应用重开、控件重建和列表重排后重新查找，不依赖旧 PID、句柄、ref 或行号
│  ├─ 点击后弹层消失、查询晚到或前台变化时保留不确定，不能错绑后来出现的目标
│  ├─ 输入变化、加载延迟与快速连续动作
│  ├─ 声明支持的主题、缩放和平台差异
│  ├─ Windows 原生动作与 DPI／多显示器坐标转换分别验收；缺映射只阻塞依赖它的路径
│  └─ 目标缺失、遮挡、用户停止和结果不明
│
├─ H7.5 分别判断结果
│  ├─ 任务正确完成
│  ├─ 合理停止或当前不支持
│  ├─ 未取得充分结果证据
│  └─ 错误完成，尤其是错误完成却报告成功
│
├─ H7.6 按失败原因返回正确位置
│  ├─ 原始动作或现场不足 → H2 定向补采
│  ├─ 动作正规化或 reviewed steps 错误 → H3／H4 修正来源整理
│  ├─ 必要路径 retain／merge／omit／recovery 错误 → H5 中共享 trace-distill 职责修订 DistilledSteps
│  ├─ 业务语义、参数或可变规则不清 → H5 中共享 procedure-synthesize 职责修订
│  ├─ 目标、文字绑定、关系或定位错误 → H5 application-engineer 定向补强
│  ├─ 代码、调用或执行顺序错误 → H6 修复
│  └─ 授权、对象或成功标准改变 → H1 重新限定范围
│
└─ H7.7 发布本次验收结论
   ├─ 明确通过的版本、场景和限制
   ├─ 保留失败原因与受影响步骤
   ├─ macOS、Windows 分开列源码实现、有效构建、合成测试、真实采集、真实回放与独立结果验证
   ├─ 人工示范、受控输入和合成 fixture 来源分别标注；缺设备标未运行，不能以编译或替身冒充 live
   ├─ 记录候选 hash、来源版本、实际命令、定位调用次数／耗时与资源清理；没有测量不填数字
   └─ 修订后重新验证，不沿用旧版本的通过结论
```

H7 的点击目标回归场景是防遗漏门槛，不要求所有应用一次覆盖全部组合；但任何声称“点击目标语义化／OCR 增强闭环已完成”的实现，至少必须以可审计 fixture 覆盖：`text-button`、`icon-only`、`text+icon`、`duplicate-same-text-or-icon`、`surrounding-label` 五类。缺任一类只能声明部分覆盖，不能用无文字图标单例代表整个点击理解能力。

原生按钮闭环是上述增强链路的一个可独立验收子集，不取代五类点击目标的完整覆盖要求。每个声称该子集通过的平台，必须有“真实按钮操作及原生目标证据 → 经验证定位与动作策略 → 现有链路生成普通 JS → 新运行重新定位并执行一次 → 独立结果核对”的证据，并分别覆盖窗口内部目标位置变化与应用重开。未覆盖的变化或平台明确列为未验证，不宣称普遍适配。运行产物只记录在既有证据位置，实际状态回填实施与验收计划。

## 贯穿全部阶段的约束

| 要求 | 具体含义 |
| --- | --- |
| 事实与解释分开 | 原始点击、截图、Native 属性、OCR 派生观察、模型判断、人工修订、DistilledSteps、业务规则和已验证定位分开；不能把失败历史改写成成功示范 |
| 权限持续有效 | 录制、保存、外发、分析、试点击、维修和重复提交分别受授权约束；第三方界面内容不成为新指令 |
| 用户控制优先 | 分析不干扰正在发生的人工操作；取消不意味着撤销此前真实副作用 |
| 复用与预算 | 有效知识直接复用；补采、OCR 和模型分析只针对缺口；没有新证据不无限重试 |
| 影响可追踪 | reviewed steps、DistilledSteps、目标、文字绑定、规则、数据或代码变化后，明确哪些消费者和测试受影响；依赖不明时不能默认无影响 |
| 能力与资格分开 | 后端存在、Recorder 接线、生成可用、真实回放和结果通过分开；macOS／Windows 不互借资格 |
| 不确定性不扩大副作用 | 搜索不完整不证明唯一；观察晚到不证明原目标；动作可能已提交时不自动重做或回退旧坐标 |
| 采集最小化 | 不因加入原生控件而默认抓整树、value 或连续画面；已有敏感输入、脱敏、保留期限与外发授权仍有效 |

保留原始事实意味着不伪造、不覆盖历史含义，不意味着永久保留所有敏感输入。采集过滤、访问控制、保留期限及用户删除要求仍有效；证据删除或丢失后，相关历史结论应标不可复核。

## 表达与执行的对应

文档保留完整 H1—H8 以检查来源流程遗漏；实施按能独立验收的工作包切分，而不是继续把所有叶子拆成零散事项。每个工作包必须写清：问题、H 节点、实际输入、处理与分支、输出、验收、失败返回、现有能力和所需变更。

Human 来源和 Agent 来源在共享专业方法处的最低接线关系是：

```text
Human：recording/raw events → H3 normalized actions → H4 reviewed recording steps
                                                       ↓
Agent：TaskContract/WorkPlan → Dossier/Raw Trace ───────┤
                                                       ↓
                                         [trace-distill as needed]
                                                       ↓
                                             DistilledSteps
                                                       ↓
                                        procedure-synthesize
                                                       ↓
                                            SemanticProcedure
                                                       ↓
                                      application-engineer harden
                                                       ↓
                                               recipe-build
                                                       ↓
                                      [code-rebuild if needed]
                                                       ↓
                                              recipe-qualify
```

这不是要求简单 Human 坐标脚本必须完整走共享链；H4 已确认且本次只要求受控坐标复刻时仍可直接进入 H6。增强路线才要求相应共享专业成果充分。

优先完成两个闭环：基础录制到普通坐标 JS 的独立闭环，以及点击目标从可信多源证据、文字／图标／上下文语义化到新条件下回放的增强闭环。原生按钮是增强链路的首个最小实施子集：复用 AX／UIA 后端补采集接线，验证 locator 与动作，再接入现有普通 JS 生成和独立 Gate；其他动作按既有合同保留，不为该子集强建通用 renderer。无文字图标是增强闭环的重要场景，但不再代表整个点击目标理解。具体执行时序、角色交接、候选方法和 95 分设计目标的评分门槛在[实施与验收计划](implementation-plan.md)统一维护，不在此复制。
