# 人工 Recorder｜完整作业任务树

**目标：从用户真实示范出发，形成有来源、可审阅、可验证并可维护的普通 OpenDesk JS；仅在确有必要时保留 Agent 判断。**

状态：H1—H8 作业树基线，2026-09-10。H2/H3 已同步 Recorder v2 的观察事实；H4/H6 现有仓库内 human-to-recipe Skill、最小 `SemanticBuildPlan` schema／validator 和提示词交接，renderer 仍未实现。树中其他子作业不代表接口或工具已全部实现。返回[工作流入口](../README.md)；规范性 DQ 合同见 [Recorder 工程设计](recorder-design.md)，真实完成、证据与未运行项见[实施与验收计划](implementation-plan.md)。

## 阅读方法

H 编号只用于人工录制作业，不改写 Agent-to-Recipe 的 S 编号。树回答完整需要做什么；实际执行按工作包选择必要分支。一个叶子不等于一个文件、类、Skill 或 Agent。

H2 采集事实，H3 整理事实，H5 理解与工程化；分析不阻塞采集。H4 与 H5 可循环，H7 按失败原因定向返回。简单坐标任务可跳过 H5 的深度分析；关键歧义、缺失、权限及不支持动作仍须说明和处理。缺口只阻塞依赖它的工作。

## H1. 明确任务、交付范围与录制条件

```text
H1. 明确任务、交付范围与录制条件
│
├─ H1.1 明确用户真正要完成的任务
│  ├─ 处理哪个应用、账号、文件或业务对象
│  ├─ 从什么状态开始，最终需要得到什么
│  └─ 哪些结果不能发生，哪些动作需要另行确认
│
├─ H1.2 选择本次交付方式
│  ├─ 受控坐标脚本：在声明的固定条件下重复
│  ├─ 增强普通 JS：重新找到正确目标再操作
│  └─ JS／Agent 混合：保留必要的理解与动态判断
│
├─ H1.3 盘点可以复用的已有成果
│  ├─ 已有录制、脚本、应用认识和目标规则
│  ├─ 已有测试结果及其适用环境
│  └─ 决定本次新录、接续、补录，还是修复已有步骤
│
├─ H1.4 选择采集内容与支持范围
│  ├─ 必要输入事件与运行环境
│  ├─ 按需采集窗口信息、截图、原生控件和状态
│  ├─ 区分能采集、能转换、能生成、已回放验证的动作
│  └─ 明示当前不支持或存在限制的操作
│
└─ H1.5 确定权限、控制方式和资源限制
   ├─ 分开约定录制、本地保存、在线模型外发权限
   ├─ 确定敏感输入、排除区域、保留期限和删除方式
   ├─ 提供明显的暂停、停止和用户接管入口
   └─ 约定模型调用、补采、重试和存储预算
```

## H2. 记录用户操作及其必要现场

```text
H2. 记录用户操作及其必要现场
│
├─ H2.1 管理录制生命周期
│  ├─ 开始、暂停、恢复、停止、取消
│  ├─ 排除录制控制按钮和停止快捷键的业务回放
│  ├─ 处理退出、中断、存储失败与部分保存
│  └─ 区分停止采集、保存完成和分析完成
│
├─ H2.2 采集原始输入
│  ├─ 保存鼠标按下、释放、点击、滚轮及按键状态
│  ├─ 未按鼠标键的普通 hover move 只计数后过滤，不写 raw
│  ├─ mousedown 后的 motion／drag 保留为点击抖动或拖动判定证据
│  ├─ 键盘按下、释放、组合键与可取得的文本信息
│  ├─ 保存事件顺序、时间及必要的输入来源标记
│  └─ 来源无法确认时保留未知，不伪称全部来自人工
│
├─ H2.3 关联应用、窗口和坐标
│  ├─ 每个动作关联 application → window → optional element，不只保存起始窗口
│  ├─ 应用保存可执行路径／名称；PID 只作本次 provenance
│  ├─ 窗口保存 title、bounds、popup 及瞬态 ID/index/handle，区分同应用多窗口
│  ├─ 同时保存 screen fact、window offset/ratio 和 element offset/ratio
│  ├─ 保留显示缩放、裁切、观察时间和坐标转换所需信息
│  └─ 记录窗口／应用切换、弹窗、遮挡、目标歧义和无法关联原因
│
├─ H2.4 按所选模式保存操作现场
│  ├─ 关联真实取得的操作前画面
│  ├─ 关联操作后及必要的中间状态
│  ├─ 默认点击点命中标签级 AX 元素；必要时有界冒泡到最近 actionable ancestor
│  ├─ 保存 role/name/identifier/actions/bounds/hit/ancestors，不保存 AXValue 或安全内容
│  ├─ 保存图像范围、尺寸、来源和采集时间
│  └─ 连续动作缺少独立观察时，保留为片段或标记歧义
│
├─ H2.5 保证采集不被分析拖慢
│  ├─ 输入事件先记录，不等待在线模型返回
│  ├─ 证据采集与模型分析分别调度
│  ├─ 对可检测的丢事件、缺帧和采集失败明确报告
│  └─ 资源不足时不能静默丢掉关键动作后仍报告完整
│
└─ H2.6 形成可消费的录制包
   ├─ 原始事件与环境记录
   ├─ 已获准保存的截图和辅助证据
   ├─ 事件、窗口、画面之间的对应关系
   └─ 支持范围、完整性状态与已知缺口
```

基础模式可以不采集截图，但后续不能宣称完成了视觉理解。标签级 AX 语义是动作事实，不等于业务意图或已验证 locator；`verified`、`unavailable` 和 `not-requested` 必须明确区分。以后升级为 OCR 增强模式时，缺少的证据需要定向补采，并保存目标裁剪、原图 hash、坐标、引擎版本和置信度；不得在 AX 失败时静默写入一个无来源 OCR 字符串。监听回调后才取得的截图不保证是点击前画面，应如实保留时间差和缺失，不要求所有录制保存完整视频。

## H3. 将原始事件整理为操作步骤

```text
H3. 将原始事件整理为操作步骤
│
├─ H3.1 识别基本动作
│  ├─ 将按下／释放组合为点击等动作
│  ├─ 区分单击、双击、右键和拖动
│  ├─ 只把有界按键后微动归一化为 click jitter，真实拖动保持 blocked
│  └─ 为每个动作绑定 source events、窗口上下文、目标语义状态和操作顺序
│
├─ H3.2 整理输入内容
│  ├─ 区分普通按键、快捷键与文本输入
│  ├─ 区分输入法编辑过程与最终提交文本
│  ├─ 区分粘贴动作与被粘贴的数据
│  └─ 无法可靠还原时保留原始动作或进入补充流程
│
├─ H3.3 关联动作现场
│  ├─ 每一步关联应用、窗口和相关观察
│  ├─ 每一步关联来源事件，不重复执行同一份输入
│  └─ 无法分离的快速连续动作先作为动作组处理
│
├─ H3.4 初步标记待解释片段
│  ├─ 可能的等待、探索、误点、重复和恢复
│  ├─ 可能依赖已有登录、文件、剪贴板等状态的步骤
│  └─ 标记只是候选，不擅自删掉可能必要的操作
│
└─ H3.5 形成可审阅的步骤清单
   ├─ 展示动作、目标位置、相关截图和信息缺口
   ├─ 区分原始事实与整理结果
   └─ 修改整理结果时，不改写原始录制事实
```

事件被采到不意味着能可靠转换。输入法按键与最终文本不能同时生成重复执行；按键粘贴不意味着已知道粘贴内容及业务来源；停顿不能自动等同于应用加载等待。

## H4. 审阅、纠错与补充示范

```text
H4. 审阅、纠错与补充示范
│
├─ H4.1 查看本次到底录到了什么
│  ├─ 查看步骤、点击位置和已有证据
│  ├─ 查看未支持动作、缺失片段和目标歧义
│  └─ 简单任务允许快速审阅，不强制逐条填写说明
│
├─ H4.2 修正操作清单
│  ├─ 删除无关操作，保留必要准备和验证
│  ├─ 修正错误合并、错误拆分和重复输入
│  └─ 区分误操作、恢复步骤与正常业务路径
│
├─ H4.3 补充无法直接观察的需求
│  ├─ 这一步为什么做，最终需要什么
│  ├─ 下次什么保持不变，什么需要变化
│  ├─ 数据来自哪里，已有同名内容时怎样处理
│  └─ 能从证据解决的问题先核实，不重复询问用户
│
├─ H4.4 定向补录或补观察
│  ├─ 明确缺哪个目标、哪个状态或哪个操作片段
│  ├─ 只补影响当前交付的部分
│  └─ 新补材料标为新证据，不冒充原录制现场
│
└─ H4.5 确认本次可继续的范围
   ├─ 保留修改前后版本、理由和来源
   ├─ 标记已确认内容与仍然未知的内容
   └─ 未知项只阻塞依赖它的工作，不一律要求全部重录
```

区分三类缺口：用户做了但采集不完整；用户确实漏掉必要操作；任务依赖登录、已有剪贴板、文件或肉眼判断等隐含条件。分别补采、修正过程或补充约定，不让 Agent 自由补造整段成功流程。

## H5. Agent 理解、过程提炼与操作工程化

```text
H5. Agent 理解、过程提炼与操作工程化【按需增强】
│
├─ H5.1 建立本次任务所需的界面认识
│  ├─ 先核对已有认识是否仍然适用
│  ├─ 粗识别当前页面、主要区域和状态
│  ├─ 精查操作目标、父区域、锚点和结果区域
│  ├─ 识别控件类型、可观察状态和必要关系
│  └─ 形成同版数据与审阅视图，不重新建模整个软件
│
├─ H5.2 分析一次点击，包括没有文字的图标
│  │
│  ├─ H5.2.1 确定分析现场
│  │  ├─ 核对点击时间、窗口和相关画面
│  │  ├─ 区分操作前、操作后和无法确定的观察
│  │  └─ 缺少可靠现场时保留限制，不事后重造
│  │
│  ├─ H5.2.2 从点击点提出目标候选
│  │  ├─ 利用可用的同期原生信息和视觉信息
│  │  ├─ 区分图标、文字、控件、容器和背景
│  │  └─ 点击点不能直接证明目标正确或操作成功
│  │
│  ├─ H5.2.3 生成必要的多尺度裁切
│  │  ├─ 目标细节：图形、边缘和控件外观
│  │  ├─ 局部上下文：工具栏、列表行、卡片及相邻目标
│  │  ├─ 页面上下文：页面身份与整体状态
│  │  └─ 保留裁切、缩放和原图映射；不足时有界扩大
│  │
│  ├─ H5.2.4 区分不同几何范围
│  │  ├─ 图标可见范围
│  │  ├─ 控件完整范围
│  │  ├─ 所属区域范围
│  │  └─ 可操作区域与实际操作点，未知者不默认取中心
│  │
│  ├─ H5.2.5 理解外观与候选功能
│  │  ├─ 描述实际可见的文字、图形和状态
│  │  ├─ 结合上下文解释可能的控件类型与作用
│  │  └─ 分开保存可见事实、模型解释和未知项
│  │
│  ├─ H5.2.6 确认目标归属
│  │  ├─ 它属于哪个应用、页面、区域或业务对象
│  │  ├─ 多个相同图标时，结合所属行、标签或锚点消歧
│  │  └─ 不把“识别出图标”当成“找到了正确对象”
│  │
│  ├─ H5.2.7 解释这次点击的作用
│  │  ├─ 区分激活窗口、选择、展开、切换和提交
│  │  ├─ 结合用户目标与前后步骤理解必要性
│  │  └─ 区分正常操作、探索、误点、重试和恢复
│  │
│  ├─ H5.2.8 检查实际效果
│  │  ├─ 分别记录期望变化与真实观察
│  │  ├─ 检查变化是否属于同一个业务对象
│  │  ├─ 排查其他输入、异步加载和外部变化的影响
│  │  └─ 结果记录为满足、失败、部分满足或未知
│  │
│  ├─ H5.2.9 解决关键缺口
│  │  ├─ 图形不清楚：补清晰局部图
│  │  ├─ 目标重复：补所属对象与区域关系
│  │  ├─ 作用未知：补已有资料、说明或获准观察
│  │  └─ 仍有歧义：停止依赖操作，不靠重复猜测通过
│  │
│  └─ H5.2.10 发布点击目标认识
│     ├─ 目标身份、所属关系和候选功能
│     ├─ 来源证据、几何信息和实际效果
│     └─ 候选定位依据、适用条件与未决问题
│
├─ H5.3 按动作类型采用专门分析
│  ├─ 文本输入：字段、输入来源、编辑过程与最终内容
│  ├─ 复制粘贴：数据生产者、消费者及有效条件
│  ├─ 拖动：起点、终点、必要路径和结果
│  ├─ 悬停：是否产生后续控件、菜单或提示
│  ├─ 滚动：所属容器、寻找目标和结束条件
│  ├─ 开关／复选框：当前状态与期望状态
│  └─ 窗口／应用切换：对象身份、焦点和数据交接
│
├─ H5.4 提炼业务过程与数据关系
│  ├─ 将低层动作组织为有目的的业务步骤
│  ├─ 保留必要准备、读取、等待与验证
│  ├─ 区分常量、输入参数、运行时读值和敏感信息
│  ├─ 明确步骤之间的数据来源与消费者
│  ├─ 根据真实规则确认条件、循环和异常处理
│  └─ 不把一次示范或一次重试推导成普遍业务规则
│
├─ H5.5 将认识转为可重复定位与操作
│  ├─ 分开表达目标身份、定位规则、当前几何和操作点
│  ├─ 选择最小足够的原生、文字、视觉或相对定位依据
│  ├─ 明确目标唯一性、适用状态和失效条件
│  ├─ 明确动作前提、状态等待、执行方式和动作后验证
│  ├─ 用新画面检查重新定位，不只匹配建模用原图
│  └─ 失败时不自动放宽对象约束或降级为全局坐标
│
└─ H5.6 确认可复用范围与交付边界
   ├─ 哪些步骤可以固化为普通 JS
   ├─ 哪些判断需要 Agent，哪些需要人工授权
   ├─ 支持哪些输入、布局、主题、缩放和应用状态
   ├─ 哪些认识只是候选，哪些规则已有测试依据
   └─ 将已确认过程与应用规则交给代码生成
```

### H5 的职责边界

Agent 主导陌生界面的布局、组件、语义和关系分析；程序承担材料组织、坐标映射、结构校验、确定性视图和已验证规则执行；人工处理必要纠错与授权。不是固定先跑完传统规则，全部失败才问模型；也不是每次点击都重新调用模型。

界面结构、图标归属、定位和应用操作复用 [application-engineer](../../agent-to-recipe/skills/application-engineer/SKILL.md) 及[应用操作专业正文](../../agent-to-recipe/design/application-operations.md)。业务步骤、参数、循环和数据流属于过程提炼；代码构建与独立验收不归应用工程。一个 Agent 可以连续承担这些专业作业，不能据职责名称宣称相应 Skill 全部已实现。

### 点击分析的执行约定

| 子作业 | 输入 | 处理与判定 | 输出／失败处理 |
| --- | --- | --- | --- |
| 现场关联 | 输入事件、窗口、前后观察 | 核对时间差、窗口、穿插输入；晚到的控件查询不能冒充同期事实 | 有限可信现场；不足保留缺口或动作组 |
| 目标候选 | 点击点、同期原生属性、图像 | 点击点是线索；区分命中对象、背景及仅激活窗口 | 候选控件，不直接宣称成功 |
| 多尺度证据 | 原图与候选范围 | 有控件边界则按边界裁切；只有点则先取周边再精查；程序校验范围与映射 | 目标细节、必要局部／页面上下文；不是每次额外截三张全图 |
| 外观和功能 | 候选图像、关系、实际可用说明 | 先描述可见事实，再解释功能，不用图标常识直接批准操作 | 观察、解释、假设及未知分开 |
| 对象归属 | 父区域、标签、业务身份、重复目标 | 识别同一行／卡片／会话等必要关系，验证唯一性 | 带对象约束的目标，不只给图片命名 |
| 实际效果 | 原期望、前后状态及其他输入 | 变化不自动证明因果；菜单出现不等于属于正确对象 | 满足、失败、部分满足或未知 |
| 工程化与验证 | 已确认目标、实际 API、候选规则 | 明确前提、重新定位、有效操作点、等待和后置；在新画面和实际环境测试 | 候选规则与验证记录分开，结果不足不晋级 |

原图、审阅标注图与匹配模板分开。点击红点、编号和边框可以用于审阅，不直接污染模板。图标可见范围、完整控件范围、所属区域和安全操作点分别表达；分裂按钮的不同位置可能有不同含义，不能默认点击识别矩形中心。

目标重复时扩大到必要业务上下文；图形模糊时补局部原图；功能未知时查已有资料、同期原生说明或后续真实状态。主动悬停以取得 Tooltip、切换页面或补点击都属于新动作，须有授权和不干扰用户的时机；不得为识别删除按钮试删真实业务数据。补采取得新证据，不重造历史现场。

给模型的任务应明确：解释本次目标，不执行新动作；返回候选、关系、证据引用、简短依据、未知和补采需求。模型自报置信度不是校准成功概率，JSON 合法或模型再次说正确也不是独立验证。模型输出作为待校验数据，不直接执行其返回代码。

### 贯穿示意：每条订单都有相同的无文字“⋯”

以下是设计场景，不是现场测试结果。任务是查看输入订单的详情。

```text
录制事实：用户在订单列表某行右侧点击“⋯”
→ 证据：图标细节、含订单身份的行上下文、页面身份、点击后菜单
→ 目标认识：此按钮属于该订单行，不是全屏任意“⋯”
→ 过程解释：打开菜单是为查看详情，不是整个业务完成
→ 参数：输入订单编号，而不是固定行号
→ 定位：确认列表 → 找到订单 → 确认所属行 → 行内按钮唯一性
→ 操作：使用有依据的可操作点或获准原生动作
→ 验证：菜单／详情与目标订单关联，最终显示预期对象
→ 变化测试：列表重排仍选对对象；订单不存在时不误点
```

只保存一个图标小图无法单独证明业务归属。矩阵和行列位置只能是已验证布局下的候选定位方式，不是所有应用的默认规则。文字、颜色、大小也是候选特征，不假设必有、唯一或稳定。

### H6 的确定性输入和审阅规则

代码生成开始前冻结最小 build plan。当前机器合同是 [`semantic-build-plan.schema.json`](../skills/human-to-recipe/references/semantic-build-plan.schema.json)，并由 [`validate-semantic-build-plan.js`](../skills/human-to-recipe/scripts/validate-semantic-build-plan.js) 检查；它不是 Runtime API 或通用 Compiler。plan 必须包含 actions 实际文件／revision／hash、逐动作 `business | runtime-guard | qualification | evidence | excluded | unknown` disposition、Business Episode 名称与顺序、参数和常量分类、Target/Locator/Geometry、动作策略、运行门禁、恢复规则、qualification claims 以及 action→episode→代码位置的 source map。一个 action 只能有一个主 disposition；任何 `unknown`、遗漏、重复消费或相互冲突都使 H6 fail closed。

simple console 的“复制 Agent 完善提示词”只把 workdir、录制路径、revision/readiness、issue code 计数、semantic coverage、可选 candidate 路径和用户待补合同交给新对话。它不复制动作正文／AXValue／raw，不自动调用 Skill、生成 Recipe、运行 Gate 或取得资格；接收 Agent 仍须重新读取实际 actions 字节和 hash。业务目标或成功条件占位符未填写时，Agent 先询问，不能从事件序列推断。

固定 plan 后，生成器或 recipe-build Agent 不再推断业务，只按同一顺序落代码：

1. 来源 lineage 和仓库根目录正常命令注释；
2. 应用身份、布局范围和其他运行常量；
3. 语义控件／操作点表，保留选择依据而不复制资格 Oracle；
4. 目标解析、当前状态重验、Geometry、动作和有限恢复 helper；
5. 以业务语言命名的 Episode 函数或清晰顶层段；
6. 只含业务顺序的顶层流程和不冒充验证的完成输出。

静态审阅逐项拒绝：plan/source hash 不匹配、action 未映射或多次映射、事件编号泄漏为业务命名、未实现 API、路线图工作名、目标歧义放宽、隐式 AX/OCR/坐标/键盘 fallback、手写坐标空间换算、无理由固定等待、把动作发送写成 `[PASS]`，以及来源 hash／逐步固定 Oracle／截图矩阵／evidence 写入混入生产 Recipe。生产文件与 qualification 文件分别检查；Gate 必须冻结并运行同一生产源码，不能维护另一份隐藏业务动作序列。

重新生成只接受同一 plan 的可审阅 diff，不覆盖已有人改；人工确实改变业务、门禁或定位时，先修订 plan、记录理由和影响，再派生新候选并重新资格。[Calculator plan](../golden-samples/calculator-115.semantic-build-plan.json) 是第一个 golden；TextEdit 是下一建议应用，但当前只用于跨应用 Geometry／window lifecycle 校准，尚无同等级 human 录制和 production/gate，不能预填其业务意图或双应用通过。

## 贯穿全部阶段的约束

| 要求 | 具体含义 |
| --- | --- |
| 事实与解释分开 | 原始点击、截图、模型判断、人工修订、已验证规则分开；不能把失败历史改写成成功示范 |
| 权限持续有效 | 录制、保存、外发、分析、试点击、维修和重复提交分别受授权约束；第三方界面内容不成为新指令 |
| 用户控制优先 | 分析不干扰正在发生的人工操作；取消不意味着撤销此前真实副作用 |
| 复用与预算 | 有效知识直接复用；补采和模型分析只针对缺口；没有新证据不无限重试 |
| 影响可追踪 | 目标、规则、数据或代码变化后，明确哪些消费者和测试受影响；依赖不明时不能默认无影响 |

保留原始事实意味着不伪造、不覆盖历史含义，不意味着永久保留所有敏感输入。采集过滤、访问控制、保留期限及用户删除要求仍有效；证据删除或丢失后，相关历史结论应标不可复核。

## 表达与执行的对应

文档保留完整树以检查遗漏；实施按能独立验收的工作包切分，而不是继续把所有叶子拆成零散事项。每个工作包必须写清：问题、H 节点、实际输入、处理与分支、输出、验收、失败返回、现有能力和所需变更。

优先完成两个闭环：基础录制到普通坐标 JS 的独立闭环，以及无文字图标从可信证据到新条件下回放的增强闭环。具体执行时序、角色交接、候选方法和 95 分设计目标的评分门槛在[实施与验收计划](implementation-plan.md)统一维护，不在此复制。
