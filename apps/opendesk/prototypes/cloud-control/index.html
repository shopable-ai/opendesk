Browser Cloud Control R1

当前优先目标

保留“我的任务”作为普通用户入口；本原型是整体架构说明，不应被复制成独立的大型云控工作台。

  • 已有底座：Task v1 固定安装、用户授权、Authority、RunHost、Worker、ChromePage、Run/Result、IndexedDB。
  • 待接入：唯一 SW 连接 owner、WSS 通知、HTTPS claim、持久请求、准入 Run 绑定、startPermit、租约与取消栅栏。
  • 待接入：Authority 结果受限投影、服务器持久回执、断线对账、最小托管设置。
  • R1 有合法 Host、精确目标与空闲槽才执行；不得因为 SW 在线而声称支持后台无人值守。
  • 真实正向验收必须运行 sample.form-fill@1.0.0，留存真实页面效果及 runId/resultId。
当前云控能力均为待实现项目；这里不能调用真实 RunHost。

Desktop 云适配（规划）

独立阶段

Desktop 使用 OpenDesk 原 Runtime/Execution、Recipe/Flow、系统权限与原有单活调度机制。

  • 固定产物类型由 Desktop 适配选择，不能被替换为 Browser 的 opendesk.task-package.v1。
  • 云端只提供任务来源、许可、租约与回执语义；原桌面 Execution 和 Scheduler 继续决定动作归属与恢复。
  • 需要对窗口/应用可达性、UIA/AX 授权、取消和不可回滚副作用单独验收。
  • 后台持续运行必须按正式 Desktop App lifecycle 与明确用户授权设计。
不等于当前 OpenDesk Scheduler 已具备云端 claim/receipt。

Mobile 一等执行端（规划）

Android / iOS 待定义

这是跨平台架构预留，不是已存在的完整手机自动化应用或无限制后台执行能力。

  • 各平台 TaskRef、可执行动作、设备身份、系统权限、前台/后台约束必须由具体端实现。
  • 移动操作系统对后台任务、无障碍和自动操作存在差异，不能直接移植桌面守护运行逻辑。
  • 断网、App 被系统挂起、用户退出和权限被撤销必须返回明确等待/未知/取消事实。
  • 真机完成配对、原生运行结果、撤权与恢复测试前，只能标记 PLANNED。
