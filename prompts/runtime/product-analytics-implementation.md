# OpenDesk：接入 PostHog 现成统计服务，完成窗口、按钮与 Flow 运行统计

## 目标需求

让 OpenDesk 具备可实际使用的基础产品统计：产品方能在现成 PostHog 后台看到窗口打开次数、关键按钮使用次数和 Flow 运行结果；普通用户不用注册统计账号、填写 key 或操作内部目录。

最终链路必须成立：

```text
用户明确同意基础使用统计
→ 打开 Flow Runner / 点击运行、停止、上一个、下一个、列表
→ 官方产品层产生标准事件
→ 先校验同意、调用来源与字段白名单
→ 通过非阻塞统一服务和 PostHog Provider 发送
→ 云端可以查询到实际事件
→ 现成 Dashboard 的统计口径正确
```

同时必须保证：拒绝/关闭统计或网络不可用时，OpenDesk 的打开窗口、运行、停止、安装、录制和测量功能不受影响；用户业务内容不进入统计链。

本轮首先完成六个核心事件：

```text
app_started
app_session_started
screen_viewed
ui_action
flow_run_started
flow_run_finished
```

点击 Run、真正开始运行、真实终态必须分开。Stop 点击只代表请求，不得直接记为已经停止或成功。未观察到结果不能推断成功。

## 当前状态

方案合同已经保存：

`docs/architecture/product-analytics.md`

先完整阅读该合同，再核验最新源码和已有实现。文档当前是待实现设计，不是功能或云端验收已完成的证明。

选型为 **PostHog Cloud + 官方 Go SDK + OpenDesk 薄适配层**。PostHog 不是谷歌服务；本轮不实现 GA4，也不建设自己的分析服务器、数据库或 Dashboard。

本轮范围是官方 OpenDesk 产品，不能自动给所有第三方 `.js` / `.odflow` 增加遥测。现有 Runner 代码命名以最新仓库为准，不因此重新执行命名迁移。

## 本轮执行

沿当前官方 App 的真实生命周期直接实现，不另开一轮泛化架构研究。

优先复用成熟 SDK 的队列与批量发送，OpenDesk 只负责产品事件、同意与隐私校验、来源权限、身份/会话、配置和必要诊断。SDK client 由 App primary instance 统一拥有，不随窗口或 child execution 重建。JS → Go 使用现有受保护产品 bridge，需要路由时复用 App Local Services，不开第二个 Runtime 或 listener。

将窗口事件接在真实可见节点，将关键交互接在统一 action dispatch，将运行开始/终态接在可信执行 owner。不能靠 DOM 重绘、按钮文案或“HTTP 请求受理”推测业务结果。绑定随窗口关闭释放，重开不得重复计数。

隐私必须在任何队列、日志和发送之前生效。默认未同意，不缓存历史行为；只接受登记的事件、字段及允许值。本地/私有 Flow 不上传名称、路径、私有 ID 或这些内容的散列。不得采集源码、执行参数、OCR、截图、剪贴板、AI 对话、原始异常或用户输入。

实现持久同意开关、随机安装标识和前台使用会话，不能复用机器/授权设备 ID。托盘常驻和后台定时运行不能制造前台活跃；首次同意不补发此前行为。关闭时先阻止新请求和重试，再丢弃待发队列，退出不能无条件 flush。

只使用公开 project token；管理 API key 和 Google api_secret 不得进入发行包。遵守现有官方配置 source-of-truth，终端用户不配置供应商。禁用 Session Replay、全量 autocapture、自动日志/异常转发、Feature Flags 和多余人物/地理处理，并检查真实上传内容。

为内存、队列、请求、重试和退出设置明确边界。若选定官方 SDK 无法满足撤回、取消或有界队列，记录具体证据后只在同一个 PostHog Provider 内最小修复，必要时改用官方 HTTP API；不得降低合同或并行维护两套传输链。

先用本地 Debug 和受控接收端完成闭环测试，再在具备真实项目配置与授权时做云端 smoke，配置第一张 `OpenDesk Product Overview`。开发测试默认不进入生产数据；远程合成事件须明确标记测试环境。

直接交付代码、测试和必要文档。遵守当前 AGENTS 与 API 文档规则：Go 白盒测试验证内部 seam，可由 JS 观察的 Runtime 行为用真实 OpenDesk JavaScript 测试验证，不用 Node/mock 代替原生验收。公开 API 确需新增时，同步 canonical Reference、类型和测试注册，不为内部统计随意扩大公共接口。

## 完成标准

逐项报告 PASS / FAIL / NOT RUN / BLOCKED，并给出对应证据：

- 首次显示、隐藏后重开可正确统计；重复 focus/重绘、打开失败不会增加访问数。
- 受控 10 次点击产生 10 个逻辑交互事件；快捷键不重复算鼠标点击；重开窗口不叠加 listener。
- 真正开始、完成、失败、取消来自可信运行状态；启动被拒绝不记 started，未知结果不记 success。
- 未同意/拒绝时无产品行为缓存与统计网络；开启不回放历史；关闭待发和重试后不再启动统计请求，重启仍关闭。
- 禁止数据和伪装在白名单键中的自由文本均无法进入队列、Debug 或网络；第三方 Flow 不能调用官方统计或改 endpoint。
- 随机标识、前台会话和后台执行口径正确；版本、平台、环境来自可信宿主；跨日长任务保留关联。
- 断网、超时、队列满、异常响应和 Provider 错误不影响产品功能；内存和统计退出等待有界。
- 本地 Debug 能核对事件和丢弃原因；重试复用 event_id；不宣称未经验证的零丢失或端到端 exactly-once。
- 具备云端条件时，同一合成事件可在 PostHog 查询，Dashboard 的环境过滤和计数正确；HTTP 200 本身不能作为入库成功证据。
- 当前可用主机的真实 Runtime/原生窗口通过验证，其他平台按可执行程度验证并注明缺失，不把源码阅读或跨编译写成真机通过。

云端项目/token/查询权限尚未就绪时，继续完成代码、Provider 和本地测试，只把云端连接与 Dashboard 标为未完成，列出最小配置缺口。不得只交一个 NullProvider，也不得虚构云端接收结果。

最终给出：已实现能力、关键修改、测试与真实验证结果、启用/关闭/调试方式、必要产品方配置、提交与推送状态、尚未完成事项。区分“代码完成”“原生验证完成”“云端完成”，不用设计评分代替质量证据。

## 必要边界

- 保持当前 `master`；不新建分支、不 reset、不 force push，写入前核对最新目标文件并保留并行修改。
- 不自建分析平台，不把 SDK 调用散落到各页面，不为统计改造无关产品功能。
- V1 先完成六事件闭环；安装、Recorder、Measurement、Promotion 和 Marketplace 后续按同一合同扩展，不声称本轮已经全部完成。
- 产品统计不用于会员扣费、授权或广告结算；随机安装标识不等于精确真人数或完全匿名。
- 本轮的成功是可验证的真实统计链路，不是增加几个 track 调用、输出一份审计报告或把评分写到 95 分以上。
