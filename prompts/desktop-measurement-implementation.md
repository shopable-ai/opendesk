# OpenDesk：将已确认的桌面测量样机落地为真实 Measurement Session

## 目标需求

让用户通过全局快捷键、Recorder「测量」按钮或开发者「桌面测量…」菜单，进入同一个无侵入式桌面测量模式，而不是打开大型测量工具窗口。

最终用户链路必须成立：

入口触发
→ 保存进入前的真实应用、窗口和 Recorder 上下文
→ 确认并锁定真实窗口参照，冻结未被测量 UI 污染的画面
→ 通过透明标注层取点取色、框选区域、两点或两区域测距
→ 在屏幕角落查看核心中文信息，在目标附近查看必要尺寸和边距
→ 拖动、改变大小或快捷键微调
→ 复制或保存简明数值、完整中文说明、结构化数据三档之一
→ 按需查看详情
→ 退出后恢复原上下文，不残留透明窗口、输入钩子或错误录制动作。

默认界面仅保留目标与参照边框、必要距离线、角落精简信息和小工具条。详情默认关闭，鼠标附近只保留十字线、可选放大镜和短提示；PID、句柄、窗口 ID 不常驻显示。

本轮交付真实产品代码、测试和可核验的原生交互结果，不是继续制作网页演示或只输出审计报告。

## 当前状态

产品设计已经确认，唯一设计正文是 `docs/architecture/desktop-automation/desktop-measurement.md`；中文交互参照是 `tests/desktop-measurement/prototype/index.html`，配套使用说明和验证边界见该测试域 README。

HTML 是合成画面样机，不是真实桌面测量实现。其窗口、候选、显示器、颜色和部分剪切板测试数据不能成为生产事实；历史样机 PASS 也不代表当前源码或原生产品 PASS。

本地可能已有尚未同步的 Measurement 代码。以当前工作区真实实现为起点，复用已有成果，不因历史路径或远端快照未找到而从零新建第二套实现。

## 本轮执行

先用简表说明「已有可复用／本轮需补齐／证据阻塞」，给出最小修改范围，然后直接实施，不再重新讨论已经确认的产品模型。

先闭合唯一会话、真实目标上下文、快照与测量输入隔离，再把当前大测量窗口降为按需详情，接通透明标注层与角落信息。已有会话再次触发必须复用，不重新冻结、不丢结果。

复用已有 Window、Screen、Geometry、ImageColor、Global Shortcut、Custom UI/native surface 和 Recorder 能力；只有现有 surface 无法表达命中测试、焦点或截图排除时，补充必要的最小底层能力。

按照 canonical 文档完成点、区域、两点、两区域、目标相对窗口参照的几何，以及磁性候选确认／层级切换／暂停吸附／人工框选回退、调整、三档复制和保存。屏幕角落信息需避让目标，靠边、多屏和大目标时有明确的翻转、收起或受限状态。

从实际菜单、Recorder 按钮和系统快捷键进入真实产品验收。发现失败后沿失败链路定位、最小修复并重验，同时观察界面并保存关键证据。对齐当前主程序与 UI host 构建来源，避免用旧构建得出新源码已通过的结论。

最后同步 canonical 文档与质量记录，交付实际修改、真实启动／体验方式、逐项结果和未完成项。当前设备不足以验证的平台、物理多屏或权限场景标记 NOT_RUN 并说明缺口，继续完成当前环境可执行部分，不以模拟、编译或自评分替代原生证据。

## 完成标准

- 三个真实入口进入同一会话；启动中并发请求去重；重复进入保留参照、快照和结果；退出后可再次进入。
- 默认无大型普通测量窗口；标注层不新增普通标题栏、Dock／Taskbar／窗口切换项；原目标画面清楚可观察。
- 目标与参照同时明确；参照可锁定且不随鼠标漂移；整窗、内容区、自定义区域的坐标含义不混用。
- 快照不含测量 UI；原始取色、绝对／相对／百分比坐标与逐显示器 logical↔pixel 映射可独立复核；不同快照不混算。
- 点、区域、两点、两区域和目标相对参照的距离均可核验；四边距正／零／负分别表示对应边内侧余量／重合／越界。
- 候选来源与确认状态清晰；可切换候选、暂停吸附、人工框选；拖动、尺寸手柄和方向键调整正常；不静默猜错目标。
- 角落信息与标签不会遮住主要目标或操作手柄；四个屏幕边缘、较大目标、Retina／缩放、多屏和负坐标有对应结果与证据。
- 详情仅由用户主动打开；关闭详情不结束会话。三档复制／保存均保留参照、坐标空间和单位；成功与失败反馈真实；本次 PID／句柄与可重定位线索分开。
- 测量输入不触发目标软件业务操作，也不混入 Recorder；退出只恢复对应会话的合法原状态，不覆盖用户期间主动改变的状态。
- 正常退出、取消、权限失败和异常路径均清理全部测量资源；不会误注销其他功能快捷键；原窗口不存在或无法恢复时报告受限，不虚报恢复成功。
- 最终报告分别列出 PASS、FAIL、NOT_RUN；任何关键 P0 失败都不能用其他通过项或平均评分抵消。

## 必要边界

- 保持已确认的「透明标注层＋角落精简信息＋按需详情＋三档导出」模型，不回退到大窗口堆字段。
- 不新增第二个 Runtime、第二套截图／Geometry／WindowTarget／Recorder 实现，不复制样机模拟层作为生产后端。
- 不扩大为通用 locator API、UI Designer、AI Layout Inspector 或自动化制作 IDE。
- 复用并保护当前工作区已有及并行修改，仅做完成测量链路所需的改动；不以重命名或目录整理掩盖功能缺口。
- 源码和稳定测试资产进入对应职责目录，运行截图、日志与探针结果写入 `.runtime/`；测试、构建、网页样机与真实产品验收分别报告。
