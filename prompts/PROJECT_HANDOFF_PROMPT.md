# Clawdesk 项目接手提示词

你现在接手的是一个名为 Clawdesk 的桌面自动化项目。你的任务不是泛泛而谈，而是基于仓库现状，准确理解这个项目当前已经具备哪些能力、依赖哪些前提、哪些地方仍不稳定，并在此基础上继续协助实现、调用或迁移这个项目。

请严格遵守以下要求：

1. 先把项目理解为“桌面自动化运行时 + HTTP 服务 + MCP server + 视觉/OCR能力 + Agent 提示词资产”的组合系统，而不是单个脚本仓库。
2. 优先依据以下真相源读取项目，而不是凭空猜测：
   - `README.md`
   - `QUICKSTART.md`
   - `docs-user-api/index.md`
   - `docs/mcp/README.md`
   - `pkg/http/handler.go`
   - `pkg/mcpserver/server.go`
   - `pkg/mcpserver/runtime.go`
   - `automation/`
3. 在输出项目介绍、方案、使用建议或迁移方案时，必须明确区分：
   - 已有且可调用的能力
   - 依赖外部配置才能工作的能力
   - 仍在演进中、不能过度承诺的能力
4. 不要把仓库中的研究文档、草稿文档、历史目录一概视为稳定正式接口。优先以当前代码入口和当前用户文档为准。
5. 对外介绍这个项目时，必须至少覆盖以下内容：
   - 项目定位
   - 当前能力边界
   - 使用方式（CLI / HTTP / MCP）
   - 视觉与 OCR 的依赖条件
   - macOS 权限前提
   - 当前不完善之处
6. 如果你需要为其他软件、其他 AI 或另一台电脑生成接入说明，请优先描述最小可行路径，而不是上来就设计完整重构方案。
7. 如果你需要验证项目状态，请优先验证：
   - 是否能执行脚本
   - 是否能启动 HTTP 服务
   - MCP server 是否可构建
   - OCR provider 是否已配置
   - macOS 权限是否具备
8. 不要把“核心能力可用”错误表述成“整套系统完全稳定”。应保持审慎措辞。

你应当优先得出下面这个工作结论：

Clawdesk 当前已经是一个可被 AI 驱动的桌面自动化基础设施雏形，支持通过 CLI、HTTP、MCP 三种方式完成脚本执行、窗口控制、截图、OCR、目标发现和动作执行；但它仍依赖系统权限与外部 OCR 配置，且更高层的视觉恢复/验证流水线还在完善中。

如果后续任务是“介绍项目”“迁移到新对话”“给其他 AI 一份说明”“换电脑后继续使用”，请在理解完真相源后，优先输出：

1. 当前项目能做什么
2. 当前项目不能稳定保证什么
3. 最推荐的使用入口是什么
4. 换环境时先检查什么
