# 多模态自动化能力路线图（视觉 + 听觉 + 软件内容编辑）

更新时间：2026-03-02
目标：让 Agent 不只“按坐标点击”，而是具备可感知、可反馈、可长期运行的自动化能力。

---

## 1. 结论（先回答你的问题）
你提到的方向是正确的，而且在当前系统里确实还存在明显缺口：

1. 语音处理：当前仅有 `Sound.play*` 播放音频，缺 ASR（语音识别）、TTS（语音合成）、麦克风输入流。
2. 视频处理：缺视频录制、帧抽取、时间轴分析能力。
3. 视觉理解：当前主要是截图 + 像素/找色，缺 OCR、控件检测、界面语义解析。
4. 坐标映射：缺稳定的“窗口坐标 -> 设备坐标 -> DPI 缩放”统一映射层。
5. 软件内容编辑：Windows 有部分 `window.getContent`，macOS 目前只能拿标题（文本抓取能力受限）。
6. 即时反馈：缺标准实时事件流让 AI 边执行边判断下一步。

因此：
- 需要从“动作自动化”升级到“感知驱动自动化（Perception-driven Automation）”。

## 2. 当前能力盘点（基于代码现状）

### 2.1 已有能力
- 输入控制：鼠标、键盘、触摸。
- 屏幕能力：截图、像素读取、颜色块检测（`ImageColor`）。
- 窗口控制：查找/聚焦/移动/尺寸/置顶（Windows 与 macOS）。
- 文本通道：剪贴板、文件读写、部分窗口文本抓取（Windows 较强）。
- 声音输出：提示音/音频播放。

### 2.2 缺失能力
- OCR 与控件识别统一 API。
- 跨平台一致的窗口内容抽取能力。
- 语音输入（麦克风/系统音频）与识别。
- 视频输入/录制/回放分析。
- 任务运行中实时数据流（SSE/WS）标准化。

## 3. 目标架构（在现有系统上增量实现）

### 3.1 三层模型
1. 感知层（Perception）
- `Vision`: 截图 -> OCR -> 控件候选 -> 语义块。
- `Audio`: 音频流 -> VAD -> ASR 文本。
- `Video`: 帧抽取 -> 场景变化检测 -> 事件化。

2. 决策层（Reasoning）
- Agent 使用实时感知结果做步骤规划。
- 优先复用已有 Recipe，减少每轮代码生成。

3. 执行层（Action）
- 鼠标/键盘/窗口/API 调用。
- 每步动作都返回可验证结果（成功信号/失败信号）。

### 3.2 核心设计原则
- 先建立“反馈闭环”，再追求复杂模型。
- 先做可解释、可审计、可回放，再做全自动。
- 先覆盖高频业务场景（聊天自动回复），再泛化多软件。

## 4. 从简单到复杂的实施路径

### Phase 1（简单，可快速上线）
目标：聊天软件单窗口自动回复（半自动）

能力包：
1. 获取目标窗口并聚焦。
2. 截图 + OCR 抽取最近消息。
3. 识别未读状态（颜色/标记 + OCR 双通道）。
4. 模板化回复（规则 + 参数填充）。
5. AI 仅在模板无法覆盖时生成回复文本。
6. 发送前可选人工确认。

验收：
- 在单一聊天软件中可稳定完成“识别新消息 -> 回复 -> 切下一会话”。

### Phase 2（中等复杂）
目标：多会话切换 + 上下文记忆 + 长期运行

能力包：
1. 会话列表扫描与优先级排序。
2. 每个会话独立 session 状态（已读/未读/待处理）。
3. 长任务 checkpoint/resume。
4. 实时事件流驱动下一步决策。

验收：
- 连续运行 4-8 小时，能处理中断恢复与异常重试。

### Phase 3（高复杂）
目标：跨软件协同（聊天 + 文档 + 浏览器 + 文件）

能力包：
1. 跨应用任务编排（多软件切换）。
2. 语音输入与语音指令（ASR/TTS）。
3. 视频分析辅助（教程视频、录屏复盘）。
4. 策略引擎（高危动作审批/限权）。

验收：
- 多应用流程成功率达到可用阈值，且具备审计与回放。

## 5. 关键技术模块（建议新增）

### 5.1 视觉模块（优先）
新增 API：
- `POST /v1/vision/ocr`
- `POST /v1/vision/detect-ui`
- `POST /v1/vision/locate`（语义按钮定位）

输出统一结构：
- `elements[]`: `text`, `bbox`, `confidence`, `role(button/input/list)`
- `screen_meta`: 分辨率、DPI、窗口偏移

### 5.2 坐标映射模块（优先）
新增 `CoordinateMapper`：
- 统一处理：
  - 屏幕坐标
  - 窗口坐标
  - 客户区坐标
  - DPI 缩放与多显示器偏移

验收：
- “同一按钮定位点击”跨分辨率命中率显著提升。

### 5.3 语音模块（中优先）
新增 API：
- `POST /v1/audio/transcribe`（音频文件转文本）
- `WS /v1/audio/stream`（实时语音识别）
- `POST /v1/audio/speak`（TTS）

### 5.4 视频模块（后置）
新增 API：
- `POST /v1/video/record/start`
- `POST /v1/video/record/stop`
- `POST /v1/video/analyze`

## 6. 软件内容编辑能力（你特别关心）

### 6.1 现实边界
- Windows：可尝试通过窗口控件树与文本消息获取部分内容。
- macOS：通用第三方窗口文本抽取受限，需更多依赖 OCR 与 Accessibility。

### 6.2 推荐路径
1. “内容读取”优先采用 OCR + 结构化解析。
2. “内容编辑”优先采用：
   - 定位输入框
   - 粘贴/输入
   - 回读验证（再截图 OCR）
3. 对关键编辑操作做双重验证：
   - UI 状态验证
   - 内容回读验证

## 7. 聊天软件自动回复 MVP 方案（可直接落地）

### 7.1 MVP 流程
1. `window.list` 找到聊天窗口。
2. `window.focus` + `vision.ocr` 读取当前会话。
3. 识别“未读对话列表”并切换。
4. 读取最近 N 条消息（含时间戳）。
5. 通过规则模板生成回复（必要时让 AI 生成文本，不让 AI 现写控制脚本）。
6. 填充输入框，发送前校验内容。
7. 发送后记录事件与结果。

### 7.2 安全与风控
- 默认开启“敏感词/高风险动作”人工确认。
- 限制自动发送速率，防止误刷屏。
- 审计日志记录每次回复依据。

## 8. 与“经验资产库”联动（降 token 核心）
- 将聊天软件流程沉淀为 `recipe_id`（如 `chat_auto_reply_v1`）。
- Agent 运行时优先检索 recipe，而不是重新写自动化脚本。
- 每次执行结果写入 Experience Record，持续优化配方。

## 9. 量化指标（上线必须看）
1. `ui_element_locate_success_rate`（界面元素定位成功率）
2. `message_extract_accuracy`（消息读取准确率）
3. `auto_reply_first_pass_rate`（自动回复首轮成功率）
4. `token_per_task`（单任务 token 消耗）
5. `long_run_stability_hours`（长期运行稳定小时数）
6. `manual_intervention_rate`（人工接管率）

## 10. 风险与治理
- 风险：UI 变动导致定位失效。
  - 对策：多策略定位（文字+颜色+相对布局）。
- 风险：ASR/OCR 误识别导致错误回复。
  - 对策：置信度阈值 + 低置信度人工确认。
- 风险：跨软件误操作。
  - 对策：窗口指纹校验 + 高危动作二次确认。

## 11. 建议立即执行（2 周）
1. 先上视觉 MVP：`OCR + UI 定位 + 坐标映射`。
2. 打通聊天软件单场景自动回复（单软件）。
3. 接入实时事件流给 Agent 做下一步判断。
4. 把成功流程沉淀成 Recipe，减少 token 与重复生成。

---

一句话：
- 先把“看得见（视觉）+ 能反馈（事件流）+ 会复用（经验资产）”做起来，再逐步加“听得见（语音）+ 看得懂视频（视频处理）”。
