# 微信布局识别算法优化总结报告

## 执行时间
2026-03-17 15:08

## 优化目标
- 精确率 >= 90%
- 召回率 = 100%
- F1 分数 >= 95%

## 测试过程

### 1. 初始测试（复杂模拟图片）
**图片**: `mock_wechat.png` - 包含聊天项、头像、文字等细节

**结果**:
- 垂直分隔符: 检测 2/2 ✓
- 水平分隔符: 检测 5 个，其中 1 个正确，4 个误检测
- 误检测原因: 聊天项之间的颜色边界（选中状态背景色、头像边界）
- **精确率**: 42.9%
- **召回率**: 75.0%
- **F1 分数**: 54.5%

### 2. 参数优化测试
测试了 7 组不同的 `minSeparatorScore` 值（0.08 - 0.30）

**结果**: 所有配置的 F1 分数都在 25% - 54.5% 之间，无法达到目标

### 3. 后处理过滤测试
测试了 7 种后处理过滤规则（置信度过滤、Top-N 过滤等）

**最佳结果**:
- 规则: `top_confidence` (保留置信度最高的 N 个)
- **精确率**: 75.0%
- **召回率**: 75.0%
- **F1 分数**: 75.0%
- 仍未达到目标

### 4. 简化图片测试
**图片**: `simple_wechat.png` - 只包含 5 个纯色矩形区域，无任何细节

**颜色配置**:
```
侧边栏:   #2E2E2E (深灰)
聊天列表: #E0E0E0 (中灰)
聊天头部: #F5F5F5 (浅灰)
消息区域: #FFFFFF (白色)
输入区域: #F0F0F0 (浅灰)
```

**结果**:
- 垂直分隔符: 检测 2/2 ✓ (x=60, x=340)
- 水平分隔符: 检测 2 个
  - y=700 ✓ 正确
  - y=50 ✗ 误检测（期望 y=60）
  - y=60 ✗ 漏检测
- **精确率**: 75.0%
- **召回率**: 75.0%
- **F1 分数**: 75.0%

## 核心发现

### 1. 算法对颜色对比度要求很高
- 颜色差异小（如 #F5F5F5 vs #F9F9F9）无法检测到分隔符
- 需要明显的颜色对比度（如 #2E2E2E vs #F5F5F5）才能可靠检测

### 2. 内部细节会产生误检测
- 聊天项的选中状态背景色产生水平边界
- 头像、文字等元素的边界被识别为分隔符
- 即使移除显式分隔线，颜色边界仍会被检测

### 3. 参数调整效果有限
- 提高 `minSeparatorScore` 会同时降低召回率和精确率
- 算法使用动态阈值（基于统计值），固定阈值效果不佳

### 4. 检测位置存在偏移
- 期望 y=60，实际检测到 y=50
- 偏移量 10 像素，超出默认容差（5 像素）

## 根本原因分析

当前算法的核心问题：
1. **无法区分主要分隔符和次要边界**: 算法将所有颜色边界都视为潜在分隔符
2. **缺少语义理解**: 无法判断哪些边界是功能区域分隔，哪些是装饰性元素
3. **对真实应用场景不适用**: 真实应用界面包含大量内部细节，会产生大量误检测

## 建议的解决方案

### 方案 1: 增强算法（推荐）
在 Go 代码中添加后处理逻辑：

1. **跨度过滤**: 只保留跨越整个宽度/高度的分隔符
   ```go
   // 对于水平分隔符，检查是否跨越至少 80% 的宽度
   // 对于垂直分隔符，检查是否跨越至少 80% 的高度
   ```

2. **置信度排序**: 对每个方向，只保留置信度最高的 N 个分隔符
   ```go
   // 默认保留前 3-5 个最高置信度的分隔符
   ```

3. **间距过滤**: 过滤掉间距太近的分隔符
   ```go
   // 如果两个分隔符间距 < 最小区域尺寸，只保留置信度更高的
   ```

### 方案 2: 使用提示（Hints）
为已知的应用布局提供分隔符提示：

```javascript
const result = await Vision.analyzeLayout({
    imagePath: 'wechat.png',
    separatorHints: {
        vertical: [
            { label: 'sidebar', from: 0.04, to: 0.06 },      // x=60 附近
            { label: 'content', from: 0.27, to: 0.29 }       // x=340 附近
        ],
        horizontal: [
            { label: 'header', from: 0.06, to: 0.09 },       // y=60 附近
            { label: 'input', from: 0.85, to: 0.90 }         // y=700 附近
        ]
    }
});
```

### 方案 3: 简化测试场景
对于自动化测试，使用简化的模拟界面：
- 只包含主要功能区域的纯色矩形
- 确保足够的颜色对比度
- 避免内部细节产生干扰

## 当前最佳配置

对于简化场景（纯色矩形）：
```javascript
{
    cellSize: 10,
    quantize: 16,
    tolerance: 32,
    minRegionArea: 4,
    minSeparatorScore: 0.08,
    cellColorMode: 'median',
    boundarySpanWidth: 3,
}
```

**性能**: F1 = 75%（未达到 95% 目标）

## 结论

当前算法在复杂真实场景下无法达到 90% 精确率和 100% 召回率的目标。主要原因是：
1. 算法无法区分主要分隔符和次要边界
2. 真实应用界面的内部细节会产生大量误检测
3. 单纯调整参数无法解决根本问题

**建议**: 实施方案 1（增强算法）或方案 2（使用提示），在算法层面添加更智能的过滤逻辑。
