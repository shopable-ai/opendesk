# Simple recording console

From the repository root, run:

```bash
./dist/opendesk -ui -allow-recorder-capture -script examples/custom-ui/recording-console-simple.js -console-mode script -log-dir .runtime/examples/custom-ui/recording-console-simple
```

The always-on-top native `FloatingWindow` keeps one compact row of icon controls: a combined start/pause/resume button, stop, replay/test-run, “复制 Agent 完善提示词”, details, and reveal artifact in Finder. Native separators divide capture, output, and inspection actions. There is no HTML/WKWebView surface or visible status label. Hovering an icon exposes its accessible tooltip. The first button shows Play before capture, becomes `3`, `2`, `1` during target selection, changes in place to Pause while recording, and returns to Play while paused or after completion. The initial window context is read only after the countdown ends.

Stopping is the single completion action: the controller saves the immutable recording, builds its internal Actions representation, and automatically generates the JavaScript file. Actions remain available in the details dialog for diagnostics but are not a user-facing workflow step. Generation never starts replay. The replay button becomes available only after the script exists, so injecting real input always requires a separate explicit click. If automatic generation fails, the same output button changes to a generation-retry action instead of adding a permanent generation button. Finder reveals the generated script after success; before that it opens the recording directory rather than presenting `actions.json` as the primary result.

“复制 Agent 完善提示词” is disabled until an actual `actionsFile` exists, then remains available for `actions-ready`, `actions-blocked`, and `generation-error`; it does not require a generated basic script. The button reads the current actions file only to bind revision/readiness, issue-code counts, and `semanticStatus` coverage, then calls `clipboard.copy()` through an injectable `copyText` adapter. It does not launch an Agent, create a Codex thread, generate or replay code, send desktop input, or modify actions/raw/candidate. The copied handoff includes the repository-local [`human-to-recipe` Skill](../../../workflows/human-to-recipe/skills/human-to-recipe/SKILL.md) path and conspicuous business-goal/success-condition placeholders. It intentionally omits action text, keyboard content, `AXValue`, semantic reason text, screenshots, and raw contents; the receiving Agent reads the actual files inside the repository scope.

The details icon opens a native `Dialog.alert()` with the target, errors, compact saved paths, counts, and bounded previews of generated source and test-run output. Full generated source and run output remain available at the displayed artifact and log paths. Generated scripts preserve every non-pause recorded action gap at 1× speed, with a default 500ms floor and 30s ceiling; each `sleep` keeps the raw gap in an inline comment for later review or AI adjustment. Closing the dialog does not stop capture. Closing the toolbar is an explicit user stop and also cancels an in-flight generated-script run.

Pause, resume, and stop clicks are registered with `RecorderSession.excludeControlClick()` before their control action runs. The raw package keeps that explicit boundary while `buildActions()` excludes the matching native pointer envelope, so toolbar controls cannot silently become generated target clicks. Details are disabled during active capture so a modal dialog cannot interfere with the recorded desktop interaction.

The six normal controls use the built-in icon registry: the combined capture control alternates between `play.fill` and `pause.fill`, followed by `stop.fill`, `repeat`, `ai.assistant`, `info.circle`, and `folder.fill`. The replay position temporarily uses `ai.generate` while automatic generation is running or needs retry. Only the countdown uses three local template PNGs. Re-render those maintained assets on macOS with:

```bash
swift examples/custom-ui/recording-console-simple/icons/render-countdown-icons.swift examples/custom-ui/recording-console-simple/icons
```

`Recorder.start()` retains the selected PID and title as initial provenance. A second foreground read is best-effort: a startup race is reported as a warning, not a rejection. Capture is desktop-global, so changing a window title, focusing another window, or switching applications does not stop the session or filter subsequent input. Because keyboard capture follows the foreground application when explicitly enabled, keep the entire recorded desktop sequence non-sensitive and pause or stop before unrelated work.

Ordinary pointer hover is filtered instead of being written to raw. Each release resolves the current application and concrete window, stores the window-relative point, and requests label-only `target-semantics`. On macOS this records the hit Accessibility node and bubbles through at most six parents to the nearest actionable control, so a text leaf can still identify its owning button. AX values, secure text, screenshots, OCR, and full trees are not recorded; an unavailable label is represented explicitly and never fabricated.

Recorder output is observation, not a guarantee of business intent or a semantic label. `semanticStatus: "unavailable"` is a normal explicit result for WebView, Canvas, remote-desktop, permission-limited, or otherwise unqueryable surfaces. Copying the handoff prompt does not turn those gaps into inferred names and is not generation, execution, live verification, visual verification, or qualification.

Generated basic scripts enforce the recorded operating system and resolve every action against a fresh application/window candidate. Recorded PID, window ID, index, and native handle are provenance only. Exact application identity plus title distinguishes multiple windows; if the title changed, fallback is permitted only when the application has exactly one window. Clicks use fresh window bounds plus the recorded top-left offset, so moving a window is supported while ambiguous targets and resizing remain fail-closed. Pressing replay starts a three-second preparation countdown so you can restore the intended starting desktop and application state; the basic candidate does not infer that state or verify business results.
