# AI 客服助手 · Desktop · Compact Copilot（R1.3 主原型）

> **产品设计基线：** [DESIGN.md](./DESIGN.md) 集中记录客服主链路、P0/P1/P2 范围、知识/商品/SKU/链接/图片匹配、交互架构和安全准入。本 README 继续记录当前 R1.3 代码与实际验收状态。

> 2026-10-28 · `master` · **当前唯一主原型为 `preview/index.html`（Compact Copilot R1.3）。浏览器演示已做交互回归；原生 Execution、真实聊天识别、微信发送与 Mac 实窗验收仍未完成。**

## 原始目标

在 OpenDesk Desktop 主窗口、Recorder 和其他快捷栏继续运行的同时，给被用户明确授权的聊天软件窗口（优先模拟客户端，其后才是微信/企业微信）附加独立的 AI 客服面板：识别正确会话的新消息，匹配本地知识，生成推荐回复，允许编辑、一键填入草稿，由用户人工发送；后续经专项授权和回读后才考虑受控自动回复。

## 本轮唯一正式设计预览

- `preview/index.html`：离线、单文件、浏览器可执行的视觉与交互原型。
- 左侧是模拟聊天软件，右侧是模拟跟随 AI 助手；支持三会话切换、五种快捷消息场景、知识库 JSON/Markdown 导入、推荐回复编辑、填入草稿、模拟发送及内存回读、重复回复阻止、窗口拖动、缩放、最小化恢复、授权/暂停、移动视图和深浅色。
- **不连接真实微信、不调用 OpenDesk Runtime、不调用任何 LLM API、不上传知识文件、不持久保存真实消息。** 顶部并行应用状态、窗口几何、会话身份、发送回执全部是浏览器模拟值。预览里的 `<script>` 不是 Runtime 原生 Custom UI 可执行内容。

浏览器可直接打开 `preview/index.html`；不得把这份含内联脚本的文件直接交给 `ui.createWindow({content:{file:...}})`。

## R1.3 当前主预览设计（380px 优先）

- **正式主文件固定**：`examples/ai-customer-support/preview/index.html`。页面标题统一为 `OpenDesk Desktop · AI 客服助手 | Compact Copilot`，不创建同名的历史 R1.x 平行 Mock；下载单文件可命名为 `ai-customer-support-preview.html`。
- **知识库紧凑条目**：取消前置启用/停用状态图标；粗体问题与正常答案在同一段连续排列，最多显示两行，点击展开完整答案及可选来源。停用知识弱化文字，状态同时写入可访问名称和悬停提示，不依赖颜色作为唯一信息。
- **推荐回复去重**：三条建议（无知识时提供安全澄清/人工核实）直接展示正文；点击卡片只改变选用状态，不覆盖尚未发送的聊天软件草稿。底部仅显示选中类型、填入、编辑、复制操作，**不再常驻重复的回复输入框**；「编辑」只在被选中的卡片下展开输入区。
- **自动回复与人工接管**：一个自动回复开关，首次模拟授权一次确认；开启后仅对后续完整精确命中、无风险且满足权限的演示消息执行模拟发送并回读。当前会话点击「人工接管」仅暂停自动发送，**AI 仍匹配知识、展示和允许选用回复**；不补发旧消息，不在已回复消息上再次填入。
- **知识搜索、过滤和文件导入**：保留搜索 + 筛选图标 + 导入图标及状态/来源筛选；导入区按需展开，JSON/Markdown 只写入当前浏览器内存。
- **浏览器回归**：Chromium 中 45/45 项交互/安全降级断言通过；320、360、380、400、440、520px 未见横向溢出，浅/深色截图已生成。这仅是**浏览器原型验收**，真实 Mac 原生 Custom UI 与微信行为 **NOT_TESTED**。

## R1.3 紧凑助手质量补齐（2026-10-28，本轮实际核验）

**保持唯一正式原型**：继续更新 `preview/index.html`，未新增平行 Demo，继承 master 中较新的 R1.3 Compact Copilot，而不是用历史 R1.1 页面覆盖。以下均是浏览器模拟功能，不代表 OpenDesk 原生客服业务已实现。

- **推荐回复**：三条可信候选保持同时可见，正文默认两行；每条有独立展开/收起按钮，可通过键盘 Enter 连续开合且不丢焦点；点击卡片选用仍与单独编辑、填入、复制解耦；未命中时仅展示安全澄清和人工核实两个兜底，不假装第三条可信知识答复。
- **知识库**：状态、来源、适用范围可组合筛选与一键清除；默认显示前五条，可展开更多；导入文件后新知识优先可见。导入和筛选两个面板互斥，Escape 关闭并把焦点还给触发按钮；JSON、Markdown、拖放导入与异常文件处理保留。
- **托管**：模拟开启、显式同意和人工接管均限于当前会话，切换会话不会串用授权；撤销演示权限使全部模拟会话停止自动回复。未知问题停止当前会话自动发送，退出人工接管后也不悄悄恢复自动发送，仍可手动使用推荐与草稿。
- **缩放/访问性**：默认 380px，六个宽度 320/360/380/400/440/520 无水平溢出；给极窄容器提供容器查询布局，以避免 200% CSS zoom 下推荐正文和主按钮被挤成竖排。独立展开操作具备 aria-expanded、键盘与触屏入口。
- **明确未实现**：此 R1.3 单栏原型没有 R1.1 双窗口拖动/缩放/最小化/随动演示链路；“跟随聊天窗口”原本没有事件处理，已禁用并标为原生待接入，避免伪装成功。此前 R1.1 的演示历史保留在本 README，但这些能力不能据此算作 R1.3 当前原型已验收。
- **本轮证据**：使用真实 Chromium Headless，通过 Playwright `page.set_content` 加载仓库同源 HTML，独立执行 **45 PASS / 0 FAIL / 0 pageerror**：22 条推荐/知识/托管/草稿/六档浅色宽度测试 + 12 条 Markdown/拖放/键盘/去重/观察暂停/触屏/200% CSS zoom 测试 + 11 条六档深色宽度/深色 200% CSS zoom/四种窗口高度与底部操作可达性测试。截图和 JSON 报告作为当前 ChatGPT 对话附件交付。既有文档的“45/45”来自此前设计历史，本轮未复跑其原脚本；新旧两组恰好同为 45，不应视作同一套测试或累加。
- **NOT_TESTED**：macOS 原生 UI、微信/企业微信真实会话、真实窗口跟随、macOS 浏览器缩放倍率、200% 系统缩放、双显示器、Recorder 并行实机、正式知识持久化、真实外部发送回执。

**准入结论**：本轮紧凑浏览器交互可供评审；真实独立桌面 MVP 及 R1.1 已移除的双窗口模拟能力仍不满足“完整功能设计通过”门槛，必须按下一节的原生任务树继续建设并取证。

## R1.1 已完成（历史基线）的原型设计增量

- **多答案卡片**：原有准确答复、亲切沟通、人工核实三条建议同时完整可见；每条含摘要、来源可信性标识和单击选用；仍需人工审阅，可填入模拟草稿或模拟发送。
- **知识库只读浏览**：沿用原始列表，在搜索基础上增加启用/停用/限定范围、文件来源双筛选；默认五条，可展开答案或显示更多；不提供编辑、删除或写入真实知识库。
- **本地数据导入**：支持点选及拖放 JSON / Markdown；兼容 Browser 的 JSON `items`、`aliases`、`scope`、`enabled` 和旧版 `entries`；只修改浏览器页面内存，不上传、不持久保存。
- **模拟回复模式**：手动 / 半自动 / 智能托管三段切换。默认半自动；自动托管必须显式勾选模拟授权，仅在后续新消息与启用的无适用范围歧义知识完全一致时，向本页模拟聊天发送。相似/未知/受限问题进入当前会话的人工接管，不会重试或补发历史消息。
- **人工接管与演示**：推荐回复顶部常驻会话接管按钮；两段客户消息测试、演示地区昵称、精确命中「发票」场景，保留原会话绑定、模拟回执、窗口拖动和深浅色。
- **验收边界**：上述为代码静态审查后的原型行为说明，尚未获得 Mac/微信/企业微信实窗运行证据。不可将浏览器点击模拟算作真实外部发送。

## master 已有可复用能力（源码核查，不等于客服实现）

| 能力 | 当前源码/API | 使用边界 |

## 下一阶段原生 MVP 源码任务（先网页版实现，再 Codex 实机验收）

**目标：实现可在真实 Mac 上运行的“模拟聊天客户端 → 正确会话 → 本地知识匹配 → 推荐回复 → 一键填入模拟草稿”的最小闭环。不要先接微信，也不要自动发送。**

1. **审计并行入口（P0）**：先 `git status --short`、核对最新 master、AGENTS 与正式 API；检查现有主窗口/Recorder/快捷栏与 App-owned Execution 的并发约束。提交一张复用/差量表；禁止覆盖未提交修改。
2. **最小原生双窗口（P0）**：将原型视觉视为设计合同，按 `ui.createWindow()` 的受限 HTML + 独立 JS 控制器重构；实现模拟聊天窗口和 AI 面板，必须使用真实 Runtime owner，不把预览的 DOM 脚本移入原生 HTML。脚本保持可从仓库根目录执行的一行真实命令。
3. **绑定与跟随（P0）**：由 `window.get/list/current` 获取唯一目标，记录 app/pid/native handle/window id；监听现有 Events 后重新观察与定位；手动移动偏移、同执行窗口焦点例外、最小化隐藏、左/右避让、目标变化撤销。所有位置写入后核对 WindowState；不假定 `setRelativeTo` 是持续约束。
4. **知识与回复（P0）**：本地 demo JSON/Markdown 文件 + 确定性匹配与来源；未命中只推荐转人工；明确不调用云模型的基础闭环。若已配置 LLM，可作为后续独立可选增量，且不可编造配置、网络或发送成功。
5. **草稿填入（P0）**：仅针对自有模拟聊天窗口实施，填入后独立回读 text + 同一会话；切换会话时旧异步结果必须丢弃，不可写入。用户手动发送后执行独立回读，结果不明不重试。
6. **并行验收（P0）**：同一 Mac 上同时启动主窗口、Recorder、Codex 快捷栏（可用时）及 AI 客服；验证各自 UI/Execution id、正常停止/关闭、跨应用焦点、错误隔离。缺任何一项实窗证据记 `NOT_TESTED`。
7. **视觉回归（P1）**：在真实 Mac 同源原生 UI 中实测 320/360/400/440/520px、200% 缩放、深浅色、两个显示器、窗口移动/缩放/最小化恢复、拖动偏移与按钮可访问性；保存截图到 `.runtime/tests/ai-customer-support/`，不得把浏览器原型截图冒充原生截图。
8. **交付（P1）**：报告“已修改/已加载/视觉已确认/功能已验证”，列出真实命令、日志路径、证据、八项独立百分制评分及算术平均分；未验不打分。只在 master 安全提交，提供 SHA 和下一轮未完成任务。

## 安全与反方审计验收

- **会话错位**：每次填入或发送前复核 app、pid、native handle、会话 identity 和最后消息 id；任何 stale 即停止。
- **焦点争抢**：AI 自有面板临时获得焦点不应导致重绑定到其他聊天窗口；Recorder 与客服不可同时控制同一 target。
- **重复发送**：以会话与消息的关联键去重；输入可能已发生或回执未知时不可自动重试。
- **OCR 不确定**：当 AX 不充分时只能展示有标记的候选；没有证据不生成交易承诺，更不能自动发送。
- **权限/隐私**：必须由用户明确授权聊天窗口；最小化采集、脱敏日志、默认不传模型、停止/撤权后释放 listener/ref/窗口。
- **降级**：读取能力缺失时保持推荐工具/复制工具的安全降级，不伪报已读取、已填入或已发送。
