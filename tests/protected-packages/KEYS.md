# Protected Package Test Keys

This directory does **not** commit reusable private test keys.

That is intentional. The protected-package tests exercise the real key flow by creating fresh, short-lived test material for every run.

## What is generated per run

`basic-runtime-smoke.js` and the full runtime-equivalence test use separate cryptographic roles:

```text
Publisher signing key
    -> Ed25519
    -> signs .odpkg

License issuer signing key
    -> separate Ed25519 keypair
    -> signs device-bound License / entitlement material

Package content key (DEK)
    -> fresh random 256-bit key
    -> generated by package protect --key-out
    -> encrypts this package payload with AES-256-GCM

Device key
    -> generated by the production P1 device provider
    -> on macOS stored in a dedicated temporary Keychain for the test
```

The Publisher signing key and License issuer signing key are deliberately different files and different identities. A test must fail if an implementation starts treating them as one shared key domain.

## Canonical basic-smoke evidence layout

Running:

```bash
./dist/opendesk \
  -script "$PWD/tests/protected-packages/basic-runtime-smoke.js" \
  -console-mode script
```

starts the canonical runtime-equivalence test in `basic` mode and creates a unique directory similar to:

```text
.runtime/tests/protected-packages/<Execution.id>/
├── commands/
├── publisher-public.pem               # retained as safe evidence
├── license-issuer-public.pem          # retained as safe evidence
├── device-public.json                 # retained public identity
├── installed-p1/                      # temporary installed License state; removed in cleanup
├── p1-device.keychain-db              # macOS temporary Keychain; removed in cleanup
├── lanes/
│   └── basic/
│       ├── plain/
│       └── protected/
├── packages/basic/
│   ├── basic.odpkg                    # retained encrypted package
│   ├── basic.content-key              # ephemeral DEK; removed before protected execution
│   └── basic.odlicense                # raw test License; removed before protected execution
├── acceptance-ledger.json
└── runtime-equivalence-summary.json
```

Private-key, DEK and raw-License files are useful while the test is running, but they are not durable fixtures and must not be committed.

## Why there is no `test-private-key.pem` in Git

A committed private key creates several problems:

- developers start copying it into examples or production tooling;
- every clone receives the same signing identity;
- tests stop proving that key generation and key separation really work;
- leaked fixtures can later be mistaken for trusted Publisher material;
- key rotation behavior is not exercised.

Therefore the repository keeps only the **procedure** for generating test keys, never a reusable private signing key or DEK.

## Manual local key generation

If a developer wants to inspect the individual files manually, use a throwaway directory under `.runtime/`:

```bash
mkdir -p .runtime/protected-demo/keys

openssl genpkey \
  -algorithm ED25519 \
  -out .runtime/protected-demo/keys/publisher-private.pem

openssl pkey \
  -in .runtime/protected-demo/keys/publisher-private.pem \
  -pubout \
  -out .runtime/protected-demo/keys/publisher-public.pem

openssl genpkey \
  -algorithm ED25519 \
  -out .runtime/protected-demo/keys/license-issuer-private.pem

openssl pkey \
  -in .runtime/protected-demo/keys/license-issuer-private.pem \
  -pubout \
  -out .runtime/protected-demo/keys/license-issuer-public.pem
```

Then let `opendesk package protect --key-out ...` generate the per-package DEK instead of inventing a static AES key by hand.

Do not reuse these local files as production credentials.

## Required cleanup properties

A passing test proves all of the following:

- Publisher private key is removed;
- License issuer private key is removed;
- per-package DEK is removed before the protected Runtime starts;
- raw `.odlicense` is removed before the protected Runtime starts;
- protected Runtime succeeds using installed P1 state rather than Publisher-side secret files;
- temporary installed P1 state is removed after the test;
- temporary device Keychain is removed and the previous user Keychain configuration is restored;
- public keys, package digest, encrypted `.odpkg`, public device identity and safe command envelopes may remain as review evidence.

## Production boundary

Test key handling is not production key management.

Production Publisher and License/Entitlement issuer private keys should live behind an appropriate secret-management boundary such as OS secure storage, a signing service, KMS or HSM depending on deployment requirements. They must not be embedded in OpenDesk, `.odpkg`, source control, examples, logs or command output.
